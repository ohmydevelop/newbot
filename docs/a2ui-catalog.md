## 组件与协议

继续使用 [D5.1 固定的官方 React/Core 0.14.0](a2ui-foundation.md) 与 v0.9 消息。Catalog 固定标识为 `newbot:ui/v1`，协议仍是标准的 `createSurface`、`updateComponents`、`updateDataModel` 和 `deleteSurface`，不增加另一套消息语言。

| 组件         | 本轮能力                                   |
| ------------ | ------------------------------------------ |
| Text         | 纯文本、h3 标题、说明；React 转义内容      |
| Column / Row | 固定子节点列表、手机自动换行               |
| TextField    | 普通单行/多行文本、双向绑定、4096 字符上限 |
| ChoicePicker | 单选下拉、多选复选框、固定选项、双向绑定   |
| Button       | 普通/主操作/无边框样式、标准 event action  |

视图通过官方 `createComponentImplementation` 和 `A2uiSurface` 连接，DOM 控件由 React 渲染；没有使用 Basic Catalog 的 Lit 组件。Schema、状态、绑定和生命周期继续交给官方核心。当前 React 工厂不保留 API 中的父子限制字段，已在构造实现时显式保留，防止按钮内嵌输入等非法结构。

不注册任何客户端函数。不接受模型提供的 JavaScript、事件处理代码、正则、URL、HTML、iframe、样式、动态模板或新 Catalog。允许的事件名称由宿主传入，不从模型描述取得权限。TextField 不支持 `obscured` 或其他私密输入类型；固定的普通输入提示由 Host 放在模型组件树之外，并通过 `aria-describedby` 关联控件。凭证通道仍在 D6 实现。

## 先限额，再校验和执行

`shared/a2ui-policy.ts` 接收 wire JSON，先检查 UTF-8 字节，再解析并迭代检查结构；随后使用项目的 Zod 4 校验 envelope，最后才调用 Catalog/SDK 的旧版 Schema。原型键、非法 Pointer、过大索引及追加索引 `-` 被拒绝。SDK 的原生操作对象和其他版本消息不能绕过此入口。

| 限额                    | 当前值                   |
| ----------------------- | ------------------------ |
| 单批 JSON / 累计状态    | 65,536 UTF-8 字节        |
| 字符串                  | 4096 个 UTF-16 code unit |
| 单个数组 / 对象键数     | 64 / 32                  |
| 总值数 / JSON 嵌套      | 4096 / 16                |
| 单批消息                | 8                        |
| 累计组件 / 布局深度     | 64 / 12                  |
| 子节点 / 选项           | 24 / 24                  |
| Pointer 层数 / 数组索引 | 8 / 0–63                 |

布局必须是单一树：拒绝循环、孤立节点、缺失引用、重复子节点及共享子节点，避免小型 DAG 展开成过量 DOM。节点数和字节限额同时检查累计状态，不能通过多次小更新逐步绕过。

每批更新先在临时官方处理器中重放当前快照，再验证新消息、累计资源、绑定类型、有效选项和按钮文本。全部通过后才提交到原处理器。非法批次不会部分写入数据或替换当前 Surface；正常增量更新保留用户输入和焦点。临时处理器在成功或失败后均销毁。

Action 只产生传给宿主回调的结构化数据；发送前再次检查解析后的上下文大小和来源。等待操作时禁用字段与按钮，防止重复提交；失败释放等待并显示不包含原始参数的错误。关闭后拒绝迟到更新；重建示例不会把旧操作的迟到结果追加到新表单。

这些前端检查不是服务端授权。D5.3 接通真实任务前，Bridge 必须重复验证会话归属、当前表单、允许事件及其数据，不能信任浏览器自报身份或绕过 Codex 审批。

## 依赖风险的处理范围

官方 SDK 仍声明 Zod 3，新增显式开发别名 `zod3@npm:zod@3.25.76` 供 Catalog 使用匹配的类型和运行时。项目现有 Zod 4 保留原样。所有新增 SDK/别名仍是开发依赖，未被产品入口导入。

[旧版 Zod 公告](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)描述了大型非法数组产生过量校验问题的路径。本轮用独立的前置资源检查限制该输入，并验证超限数据没有进入组件 Schema；64 MiB 堆限制的子进程也能正常拒绝 65、1000 和 200000 项非法集合。此为应用入口的缓解措施，不是对依赖本身的修复，也不宣称所有上游问题都已消除。

当前生产依赖审计为 0 项，包含实验开发依赖时仍报告 4 项 high，源于旧版 Zod 及其影响的 A2UI 包。后续升级仍需重新运行契约与资源测试，不能用跨主版本强制 override 冒充兼容修复。DOMPurify 维持既有的 3.4.17 override。

## 可运行示例与验证

```bash
npm run dev:a2ui-catalog
# http://127.0.0.1:3123
npm run test:a2ui-catalog-ui
node --import tsx --test tests/a2ui-catalog.test.ts
```

示例是静态监控任务表单，创建/取消仅显示本地结果，不创建模型 Turn、真实监控任务或工具调用。所有测试钩子只在回环夹具中存在。可操作名称、服务器、指标和备注，验证更新、只读、关闭与重建。

新增 17 项自动测试，覆盖白名单、Schema、累计限额、公告中的数组路径、非法树、越界路径、空白标签、非法绑定/选项、更新原子性、Action 限制、删除及销毁。

新增 20 项 Chromium 检查，覆盖真实 React DOM、单选/多选/输入回传、数据与组件更新、焦点、普通输入提示、恶意描述/HTML/路径、等待/失败/重复提交、关闭及重建、桌面/手机与深色显示。截图检查后修正了复选框方向和桌面两列宽度，并加入几何检查。

全量 182 项自动测试、20 项新浏览器检查和 12 项原版官方样例回归通过。类型检查和构建通过。证据在 `.data/a2ui-catalog-ui/`；官方样例的原始文件及校验值保持不变。本轮只交付组件和受控入口，不把静态示例当作真实 Agent 对话验收。
