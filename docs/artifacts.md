# D1.1 产物登记与受控读取

更新日期：2026-11-08。以下为 [整体计划](roadmap.md) 的 D1.1 阶段记录，交付服务端基础能力。后续 D1.2 已接入聊天产物卡片、文件选择器和预览面板，当前结果见 [预览记录](artifact-preview.md)。统一部署与上线验收仍安排在功能开发结束后。

## 已完成

- 仅采集本实例已登记会话的实时、成功 `fileChange` 事件；记录 thread、Turn、原生 Item 和相对路径。重命名读取最终路径，删除和失败的修改不采集。
- 手动登记先验证会话归属与真实 Turn，再读取用户指定的相对路径；来源标记为 `user`，不允许前端伪造原生 Item。
- 内容存为私有 SHA-256 快照，跨会话去重；每个会话/路径递增版本号。重复的原生事件不会重新读取文件，同一 Turn 手动重复登记相同内容返回原记录。
- Turn 历史及 AG-UI 状态快照携带 `artifacts` 和 `artifactNotices`。采集不依赖浏览器连接；归档保留引用，重启后从数据库恢复。
- 采集队列与 Codex 事件消费分离；队列拥塞、读取失败和采集中进程退出具有持久化状态，不中断 Agent 任务。

快照记录的是事件之后实际读取到的稳定文件内容，不是文件系统事务或 Git 提交。读取期间发现文件变化会拒绝采集。Bridge 离线期间错过的文件事件不会在历史加载时重新采集，避免把当前文件错误标成旧版本；用户可明确登记当前文件。进程重启后，未完成采集标记为 `capture_interrupted`，不会自动重放。

## 文件边界与预算

只读取配置的工作目录。拒绝绝对路径的手动登记、`..`、隐藏路径、控制字符、符号链接、硬链接、目录及特殊设备；工作目录覆盖应用数据时排除私有存储。文件打开时使用 no-follow，并复核路径、inode、大小和修改时间；Linux 额外核验打开文件的实际路径。

支持文本/代码、Markdown、JSON/CSV、自包含 HTML、PNG/JPEG/WebP 和 PDF。扩展名由服务端匹配，图片/PDF 校验文件头，文本必须是无 NUL 的有效 UTF-8。隐藏配置、常见凭证文件名和 PEM 内容默认拒绝；这属于已知类型过滤，不能代替工作目录权限与 Codex sandbox。

- 单文件最多 8 MiB；文本最多 2 MiB。
- 上传附件与已引用的去重产物快照共用 512 MiB 配额。
- 采集队列最多 64 个任务；单个事件最多处理 32 个文件，超出项记录 `change_limit`。队列满时记录 `capture_busy`，不无限缓存。
- 目录列表每页最多 100 项，单次扫描最多 5000 项；超出时返回 `truncated`。
- 存储目录权限为 0700，快照文件为 0600。

这些读取检查约束 Web 文件接口；不声称能隔离持有相同系统用户权限的恶意进程。后续 [D1.4](artifact-lifecycle.md) 已补齐清理、物理孤儿快照回收、版本操作与容量反馈；以下仍保留 D1.1 阶段的验证记录。

## 产品接口

均复用已有登录 Session；写请求同时验证 Origin。响应元数据只包含工作目录相对路径，不返回服务器绝对存储路径。

| 接口                                     | 行为                                                                          |
| ---------------------------------------- | ----------------------------------------------------------------------------- |
| `GET /api/workspace/files?path=&offset=` | 列出允许选择的工作目录文件及目录                                              |
| `POST /api/threads/:id/artifacts`        | `{turnId,path}`，登记当前文件快照                                             |
| `GET /api/threads/:id/artifacts?turnId=` | 返回产物及未完成/失败记录                                                     |
| `GET /api/artifacts/:id`                 | 返回产物元数据                                                                |
| `GET /api/artifacts/:id/content`         | 校验 SHA-256 后读取快照；图片可显示，文本按 `text/plain` 返回，PDF 按附件返回 |
| `GET /api/artifacts/:id/download`        | 强制附件下载                                                                  |

HTML/JS 源码不在主站执行；内容端点附加 `nosniff`、限制 CSP 和禁止缓存策略。HTML 的独立 origin 隔离预览已在 [D1.3](html-preview.md) 实现；PDF Range/预览属于 D1.5。D1.1 的运行时能力报告标记 `artifacts.preview: false`；D1.2 已更新为实际支持的预览类型列表，HTML 执行在 D1.3 已按独立域名配置启用，PDF 预览仍关闭。

手动登记最多检索 20 页原生 Turn 历史；未找到时明确拒绝，不创建虚假 Turn 关联。

## 数据变化

SQLite `user_version` 从 1 升至 2，增加 `artifacts` 与 `artifact_sources` 表，保留会话、登录、运行账本和附件记录。快照保存到数据目录的 `artifacts/`。旧版程序会拒绝新版数据库；回退时需要配套的升级前数据库备份。

D1.1 当时未重启现有测试服务，也未迁移正在使用的数据库；编译产物已生成。生产部署、域名和备份演练不在本轮执行。

## 验证

`npm test`：33/33 通过，其中新增 7 项覆盖：

1. 真实 Turn 关联、伪造来源拒绝、认证/Origin 与 HTML 响应安全。
2. 越界、绝对路径、软/硬链接、隐藏凭证、无效文本、超限与不支持格式。
3. 原生事件幂等、不可变快照、多版本、采集失败及不补采旧历史。
4. 归档、重启恢复、中断采集状态和快照损坏拒绝。
5. 共享配额及跨会话去重。
6. v1 数据库升级保留旧状态，拒绝未来版本。
7. 重命名后的读取与突发采集队列/文件数量限制。

`npm run build`：通过，包含 TypeScript 检查、Web 构建和服务端打包。构建仍有既有的 Vite `.env` 提示、第三方注释和大型富文本资源分块提示。本轮测试使用临时工作区和 FakeCodex 事件；未声称完成真实模型生成文件到预览 UI 的端到端验收，该流程已在 D1.2 接入后通过真实 Codex 验证；HTML 执行预览已在 D1.3 完成真实 Codex 和浏览器验证。
