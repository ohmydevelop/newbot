# 插件配置与服务器证书

插件内的技能、连接器和钩子在 **扩展 → 插件 → 插件详情** 中管理，不拆到独立目录。用户通过表单填写设置，不需要编辑 JSON。

## 包内 MCPB 声明

插件直接携带完整 MCPB `manifest.json`，不需要宿主专有字段。单连接器可放在插件根目录；多个连接器可以分别放在各自包内子目录。宿主按 MCPB `name` 匹配原生 `mcp.json` 中的连接器 ID。重名、未知 ID、越界或缺失的入口文件会被拒绝。

```json
{
  "manifest_version": "0.3",
  "name": "example",
  "version": "1.0.0",
  "description": "Example service connector",
  "author": { "name": "Example author" },
  "server": {
    "type": "binary",
    "entry_point": "bin/example-mcp",
    "mcp_config": {
      "command": "${__dirname}/bin/example-mcp",
      "args": [],
      "env": {
        "SERVICE_URL": "${user_config.url}",
        "SERVICE_API_KEY": "${user_config.key}",
        "SERVICE_CERT_SHA256": "${user_config.certificate_sha256}"
      }
    }
  },
  "user_config": {
    "url": { "type": "string", "title": "服务地址", "required": true },
    "key": { "type": "string", "title": "API Key", "required": true, "sensitive": true },
    "certificate_sha256": {
      "type": "string", "title": "服务器证书指纹", "default": "",
      "description": "可通过获取服务器证书填写。留空使用系统证书验证。"
    }
  }
}
```

示例变量名需要由连接器自己的程序实现；宿主不会把任意指纹字段自动变成 TLS 策略。服务器程序负责校验指纹并执行连接。

当前支持 MCPB 0.3 的 node/python/binary 服务器、command/args/env/platform_overrides，以及 string/number/boolean 用户字段、标题、说明、必填、默认值、敏感属性和数字范围。`${__dirname}` 相对于该 MCPB 清单所在目录展开，entry_point 必须存在于其目录内。文件/目录字段、多行 CA、任意脚本式向导未实现，不能以空字段或默认值冒充支持。

MCPB 使用标准 server.mcp_config，其中不能添加 type、cwd、url 或 headers 等非标准启动字段。原生插件 mcp.json 保持自己的格式和启动定义，无用户配置的原生连接器不要求 MCPB。HTTP MCP 仍按原生定义/OAuth 工作，不伪装为 MCPB 本地服务器。

MCPB 格式遵循公开规范；在 Agent Plugin 内发现 MCPB 并按 name 对齐连接器，是本宿主的组合发现规则，不保证其他 Codex/ChatGPT 客户端自动采用相同发现方式。旧专有关联已经移除，旧包需更新清单后重新导入，不提供回退。

## 获取服务器证书

填写服务地址后，表单提供“获取服务器证书”。如果插件有多个地址或多个普通文本目标，用户明确选择来源和接收指纹的字段；敏感字段永远不参与选择。常见的地址、API Key、指纹三个字段无需额外选择。

1. 宿主只向该 HTTPS 地址建立 TLS 握手，读取叶证书，展示目标、有效期、系统验证状态和 SHA-256 指纹。没有 HTTP 请求，不携带 Token、Cookie 或其他服务凭证。
2. 用户核对服务器信息后点击“确认使用此证书指纹”。这一步填入草稿；点击正常的“保存”后才生效。读取证书本身不会建立信任。首次连接无法仅凭从网络读到的证书证明其身份，必要时通过管理员核对。
3. 改变地址会清除这次自动填入的旧指纹。取消或迟到响应不会覆盖新草稿，观察结果五分钟后需要重新获取。证书过期、尚未生效或用途不适用时禁止该填入操作。
4. HTTP 没有 TLS 证书，须填写服务实际的 HTTPS 地址；不会自动改协议、猜测端口或跟随重定向。

探测允许用户明确填写的私网服务，拒绝回环、链路本地、元数据和多播等禁区；DNS 解析后固定到已校验地址，限制时间、并发与返回证书大小。只读观察使用独立 socket 读取未受信任证书，完成后销毁，不能用于后续携带凭证的请求。不修改系统/其他插件的信任库，不提供全局跳过 TLS 的选项。

插件须实现收到的指纹语义。示例使用完整叶证书 DER 的 SHA-256（64 位十六进制、无冒号），只用于指定目标，保留有效期和服务器用途检查，不自动接受更换后的证书。若插件不支持证书固定，不能仅增加表单字段来声称支持。

## 保存与生效

普通设置存 SQLite，敏感值通过私密通道存入加密凭证库；不写个人 Codex 配置。保存不调用模型、不检查业务接口，从下一轮扩展快照生效。正在运行的 stdio 进程使用启动时的环境，不会被强行改写。

配置和秘密绑定插件、连接器、包摘要与接收方。更换地址、模板、包内容或信任参数后，须重新确认所需凭证；新代码不能自动领取旧授权。技能不复制到独立目录，固定 Codex 所需的运行名称与配置适配由宿主通用处理。

启用连接器时，缺少必填密钥会直接拒绝保存。修改连接参数导致已有凭证无法继续使用时，表单提示重新填写；原配置、密文和修订号保持不变。保持相同接收方的普通保存或启停可以保留已存密钥。明确点击清除可以保存为待配置状态，页面不会再显示为可用于下一轮。

发送时若明确选择插件，或专家包含该插件，宿主先检查其启用的连接器是否配置完整，再核对原生线程的实际就绪状态。失败会在模型执行前给出具体原因并保留草稿；修正后在原会话继续。未选中的待配置插件和主动停用的可选连接器不会阻止其他聊天或组件使用。历史里出现过的工具名不能作为当前可调用能力的依据。

“已保存”“MCP 已发现工具”和“业务查询成功”具有不同含义。检查连接只验证原生 MCP 初始化/目录，不保证插件业务服务的证书和 Token 有效。

## 升级

插件菜单和详情提供“升级”。导入新目录、ZIP 或公开 GitHub 来源，扫描同一插件身份、展示版本和文件差异，确认完整插件及替换后安装。身份和已有启停选择保留；新增技能默认关闭。兼容普通值保留供核对，变更包要求重新确认凭证。过期预览不能覆盖后续修改，失败回滚，重复操作不重复安装。

原生市场只有提供不同的已安装/目标版本时才开放升级；本地来源由目录管理，不冒充远程版本发现。
