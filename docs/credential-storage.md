# Provider / MCP 凭证保存与不可回读（D6.3）

日期：2026-11-09。D6.3 已接通工作台私密输入、凭证保存、原生配置引用、载入/更新/清除和重启恢复。支持自定义 Provider 的 Bearer API Key、HTTPS MCP 的 Bearer Token。账户授权、冲突的内联 Authorization、自定义认证命令、stdio 私密环境和 sudo 不在本轮开放范围。

本文记录 D6.3 的范围与当时能力。后续 D6.4 已加入可显式启用的固定 sudo 身份检查，见 [sudo 通道记录](sudo-input.md)，没有开放任意提权命令。

D6.5 已进一步收紧公开错误、工具失败和 Trace，并完成受信操作范围的隔离矩阵，见 [验证记录](credential-isolation.md)。下文保留 D6.3 当时的验证数量及能力状态。

## 使用方式

进入“设置 → 模型与 Provider”或“MCP 连接”，在可托管的连接下选择“设置/更新私密凭证”。默认选项为只保存在本次工作台运行的内存中；加密保存必须明确选择。随后通过独立可信窗口输入，点击“保存并重新连接”。

原值不回显，也没有读取原值的 Web API。更新从空输入框开始；状态只展示保存方式、是否载入、版本和更新时间。普通聊天、A2UI、MCP Elicitation 不会变成密码输入框，Agent 也没有获得请求任意私密操作的工具。

- **内存方式**：浏览器刷新、关闭或 Codex 重新连接不丢失；Web Bridge/容器重启后需重填。配置中留下的旧引用显示明确的“内存凭证已丢失”。
- **本机加密方式**：使用 AES-256-GCM 保存，Web Bridge 重启后核对配置绑定并恢复载入。原值仍不经接口返回。
- **清除**：需要界面明确确认，移除工作台管理的引用及保存值，并重新连接，撤下原生进程中的旧凭证。不会改动外部环境变量或其他认证配置，也不会吊销上游服务本身的 API Key。

任务、审批、App 调用、OAuth 或其他私密请求未完成时不能写入/清除，避免在执行中途替换认证。开始提交后先消费本次输入；进入配置写入阶段后不能撤回，关闭窗口或原生进程的计划重连不会撤销已提交的写入。等待阶段仍可取消、过期或随登出失效。

## 数据与绑定

数据库升级至 Schema v5，新增 `managed_credentials`，只保存 scope、target、随机引用/版本、绑定摘要、时间及 nonce/ciphertext/tag。内存模式不写入此表。

每条密文的附加认证数据绑定 scope、target、引用、接收方摘要及版本，不能搬到其他连接或修改元数据后复用。绑定包含接收 URL、传输/认证方式和 Header 定义；不将秘密作为可回读的“后四位”等摘要展示。

解密钥为数据目录中的 `private-credentials.key`，不在 SQLite 或 Agent 工作区中。首次创建使用独占、禁止符号链接、0600 权限及文件/目录 fsync；校验文件类型、拥有者、链接数、长度和权限。已有密文而解密钥丢失时不生成新钥覆盖，错误、替换或失权的解密钥会锁定加密读取/写入；内存方式仍可用。

默认最多保留 256 条内存/加密记录，每值最多 4096 字节，继续只支持非空可见 ASCII Bearer 凭证。正常更新清理该连接旧值；结果未确认时保留有界的暂存记录，先核对实际引用，再清理。连接存在未清理的托管值时，普通删除接口会要求先从私密入口清除。

清除是逻辑删除与运行时撤下，不承诺备份、SQLite 旧页、JS/HTTP 不可变副本的物理擦除。后台受信组件必须能够解密消费，所以“不可回读”指 Web/API 的产品边界，不是管理员无法恢复的单向散列。

## Codex 原生消费

不把凭证明文写入 `config.toml`、命令行、聊天或 JSON-RPC 参数。普通配置只写生成的专用环境引用：

| 接收方    | 原生字段                                |
| --------- | --------------------------------------- |
| Provider  | `model_providers.<id>.env_key`          |
| HTTPS MCP | `mcp_servers.<id>.bearer_token_env_var` |

这些是 [Codex 官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)列出的原生字段；行为以固定的 Codex 0.166.0 实测为准。没有引入模型网关或第二套 MCP 客户端。

存在托管记录时，在启动常驻原生进程前，先通过不含托管秘密的短时 Codex 读取实际配置，停止该进程，再为匹配的接收方载入凭证。只给配置引用一致、绑定有效且仅被其指定认证字段使用的记录提供值；引用被其他 Provider、MCP、stdio 转发或其他配置复用时不会载入。

值只进入受信 App Server 的认证环境，不修改 Web 服务的 `process.env`。Shell 保持 `shell_environment_policy.inherit="core"`，并显式启用默认秘密名排除。真实版本测试验证 App Server 命令执行和默认 stdio MCP 不继承这些专用变量；HTTP MCP 仅通过自己的原生 bearer 引用消费。

普通 Provider/MCP 保存接口不能直接写入或清除保留的托管引用，也不能绕过私密流程更换接收方。新 Turn、MCP、Apps、Provider 控制操作及设置读取前，会复核运行中已载入的绑定；发现失配后停止旧原生进程，要求核对并重新连接。外部配置修改不会被当成同意把旧钥发送给新接收方。

这是面向可信项目、可信上游的单机工作台。Provider 和持有凭证的 MCP 是受信接收方；同一宿主 UID 的恶意进程、调试器、读取进程内存或管理文件，不属于该模块的强隔离保证。正常输入/配置/推理路径已验证不带入密钥；完整错误、日志和 Trace 矩阵仍在 D6.5，不能据此宣称对任意恶意上游或不可信代码实现了秘密隔离。

## 写入与恢复

一次保存同时检查登录、输入期限、可写用户配置、配置版本、凭证版本、接收方和空闲状态。先在内存或加密表中暂存新值，再通过原生 CAS 只写引用；只有权威读回确认后才清理旧值。配置写入开始前清空输入 Buffer，避免计划重连将本次输入误取消。

- 明确未写入：删除本次暂存，保留旧配置/凭证。
- 原生回执丢失：读取实际配置；若已指向本次新引用，确认已保存但尚未应用，只重连，不重写。
- 读回仍不明确：保留暂存，提示读取实际状态，不自动重发。
- 已保存、重新连接失败：保留保存值，报告未载入，提供重连恢复。
- 解密失败/绑定失配：不载入，展示锁定或失配状态，可清除或重新输入。

私密表单继续使用独立二进制输入，字段发送后清空，浏览器不存入 React/Zustand 或 localStorage/sessionStorage。审计只记录 UUID 和状态。普通接口只返回凭证元数据。更新、清除及重连没有把秘密再次提交到聊天。

## 能力与接口

`trustedInput.persistence: true`，`storage` 分别报告 `memory`、当前 `encrypted` 可用性、`providerBearer`、`mcpHttpBearer` 和 `stdio: false`。`agentRequests`、`sudo`、A2UI 私密输入及 MCP Elicitation 敏感输入仍为 false。

新增 `credential.save` 请求沿用 `/api/credentials/requests` 和独立 `/input`；只接受 scope、targetId、两类版本及保存方式。`POST /api/credentials/clear` 清除确认后的指定目标，`POST /api/credentials/apply` 核对版本后重新连接。没有读取秘密或任意领取秘密的接口。
