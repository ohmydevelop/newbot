# 历史、草稿与操作恢复（D7.2）

日期：2026-11-09。D7.2 完成，下一批 D7.3 键盘、焦点、主题及桌面/手机适配。正式部署和统一上线验收继续留在 R1。

## 用户可见的变化

- 对话列表提供读取进度、局部失败及重试；标题搜索忽略首尾空白、大小写及兼容字符差异，明确只搜索标题。迟到的列表请求不会覆盖较新的结果。
- 加载更早消息时保留现有内容、分页游标和阅读位置；失败可重试，交叠消息去重。切换对话后旧分页响应失效；实时消息及状态快照保留当前已加载的历史前缀。
- 重命名失败保留名称草稿；归档失败保留列表行。确认后的操作刷新列表，迟到回执不会清空另一个对话的草稿。正在执行或刚开始创建任务的对话不能归档。
- 每个对话和新聊天分别保留内存中的文字、附件及技能选择。上传和发送回执关联原草稿；发送期间的新输入、新附件和其他对话不被清空。
- 批量附件逐个显示进度，部分失败保留已成功项目；取消停止剩余上传。上传期间禁止发送半完成批次，超出每条 8 个附件或每文件 8 MiB 时提供反馈。
- 发送响应丢失后保留原请求 ID，提供只读状态核对。确认已提交才清理已发送内容并解除等待，不重复创建 Turn，也不覆盖后续输入。旧请求稍后返回，不会清掉下一次发送的待确认状态。
- 停止请求显示提交中、已请求或结果未确认。读取权威状态后仍在执行时，可再次明确请求停止；不会根据 HTTP 成功直接伪造“已停止”，也不会自动重发。

## 请求未登记时的放弃

`GET /api/agent/runs/:requestId` 返回 404 只代表当前没有登记记录，不能证明迟到的请求不会到达。页面因此保留原请求 ID，并在服务端报告 `runRecovery.abandonUnseen = true` 时提供“放弃尚未登记的发送”。

新的 `POST /api/agent/runs/:requestId/abandon` 使用登录、Origin 校验、UUID 和严格空请求体。它同步写入现有 runs 表中的 abandoned 回执，使该 ID 后续的请求在创建原生线程或 Turn 之前被拒绝。即使初始发送正在等待异步校验，最终预留也会受到该记录约束。Bridge 重启后仍有效，Schema 保持 v5。

已有 reserved、dispatching、unknown、accepted 或旧版成功回执不能被该操作覆盖，返回 409 并要求核对状态；已经 rejected 或 abandoned 的请求可以确认。此入口不取消已运行的任务，原生中断仍走独立控制路径。没有自动重试发送或自动放弃。

## 保存与恢复边界

草稿只在当前页面内存中保留；刷新、退出登录或关闭页面不会持久恢复正文。浏览器现有稳定请求 ID/指纹用于防重，不保存原始提示词、附件正文或技能文件。明确重置新聊天草稿和退出登录后，旧上传/发送回执不能恢复已清空的草稿。

首次进入对话仍读取最近 30 个轮次；本次保留的是用户明确加载的较早前缀，离开后不建立完整历史副本。服务端原有最近窗口、缓存和 Codex 权威历史不变。

取消上传不能撤回已经收到的文件。未关联消息的文件继续使用既有 24 小时清理策略；成功上传但未发送的文件不会被自动提交。运行中断和归档以实际 Codex 状态为准，关闭浏览器不会终止后端任务。
