# A2UI 状态、草稿与重启恢复（D5.4）

日期：2026-11-08。本轮补齐 D5 的状态恢复、到期提示和安全降级。继续使用官方 A2UI v0.9 描述与受限 Catalog；没有增加 Agent 内核或消息协议。正式部署和上线统一验收仍留在 R1。

## 恢复行为

| 情况                                     | 恢复结果                                                     |
| ---------------------------------------- | ------------------------------------------------------------ |
| 浏览器刷新、断线，Bridge 仍运行          | 读取当前表单及已保存草稿，接回原生待处理请求；有效期不延长   |
| Bridge 或容器重启，旧请求曾等待填写      | 恢复表单和草稿为只读，提示重新生成；旧令牌与原生 RPC 不恢复  |
| 已提交或取消的表单                       | 恢复最终快照和只读状态；精确重试只返回已有回执               |
| 发送原生响应后的结果无法确认             | 保留不可重放的提交栅栏，提示检查任务状态；不再次发送原生响应 |
| 原生任务中断、请求结束、离线、超时       | 撤销旧令牌，禁用操作并说明原因；保存的普通草稿可只读查看     |
| 保存数据损坏、Catalog 不匹配、描述不完整 | 显示固定提示，不执行未知组件或脚本；仍可继续聊天及重载       |

等待时间为 10 分钟，页面显示截止时间。客户端到期先禁用，服务端在计时器和每次访问时复核，不能通过调整浏览器时钟延长权限。

首次 native Item 仍是挂载位置。SQLite 保存原生 callId 与 View 的关联；长任务的事件缓存即使裁去最初 Item，也能补回待处理表单。历史恢复只补充当前已读取 Turn 的 UI，不复制整套 Codex 对话。

## 最少持久化

数据库升级到 Schema v4，增加四张表：

- `a2ui_views`：身份、状态、版本、截止时间和已校验的标准消息快照。
- `a2ui_calls`：原生 callId 到 View 的关联，增量更新仍归并到原消息。
- `a2ui_drafts`：独立的普通字段草稿、版本和到期时间。
- `a2ui_receipts`：请求 UUID、内容指纹、接受或未知状态。

不保存活动令牌或原生 RPC 请求句柄。启动时将数据库中等待状态改为 `unavailable/runtime_restarted` 并提升 UI 版本，保留草稿供只读查看。恢复的快照再次经过资源、Schema 与组件树校验。

保持最多 32 个 SDK 实例，关闭的实例可驱逐并按需从 SQLite 恢复，活动实例不被驱逐。持久化默认上限为 512 个 View、32 MiB 快照/调用索引/草稿内容预算（并非 SQLite 文件大小），每个 View 最多 128 个调用关联，回执最多 2048 条。达到上限明确拒绝新写入，保留既有状态；存储清理界面尚未包含这些表，后续产品收尾需统一考虑，不能依赖自动删除历史腾空间。

## 草稿

字段编辑后约 450 ms 自动保存，失焦、手动“保存草稿”和 `pagehide` 也尝试保存。只有界面显示“草稿已保存”后才表示收到服务端回执；关闭页面时的 keepalive 是尽力发送，不能保证尚未确认的输入已保存。网络失败保留当前控件，提示未保存并允许重试。

保存和恢复不会因其他页面的快照更新而覆盖当前正在编辑的控件，也不移动焦点。“重载表单”会显式读取当前已保存版本。草稿采用独立的 CAS 版本，冲突页面保留本地输入并提示重载，不能静默覆盖另一页面的更新。

“清除草稿”移除服务端内容并留下递增版本的空记录，阻止迟到请求重新写回；当前输入保持不变，刷新后恢复模型原始字段。后续新编辑仍可保存新草稿。草稿有效期 24 小时，到期不可读取，并在读取、写入预算核对和启动时清理。提交开始时，把实际提交字段写入快照并清除旧草稿，避免提交结果未确认时用旧草稿覆盖最终字段。

草稿仅保存普通信息，提交前不会交回 Codex 或作为模型工具结果。浏览器不将字段值存入 localStorage/sessionStorage。表单的固定提示仍为“普通信息会随操作发送给助手，请勿填写密码或密钥”；凭证能力仍关闭，D6 单独实现。

## 接口与单次消费

沿用登录、Session Cookie、Origin 和身份/令牌检查：

- `GET /api/a2ui/:id`：当前权威状态，包含草稿版本和可用的草稿。
- `POST /api/a2ui/draft`：身份、UI 版本、令牌、`expectedVersion` 和完整可编辑字段集合。
- `DELETE /api/a2ui/draft`：相同身份约束，空 `values`，清除已保存草稿。
- `POST /api/a2ui/action`：原有操作接口，UUID 回执改为持久化。

草稿先通过独立运行时重放已验证描述并校验字段，不改变模型侧运行时、UI 版本或活动令牌。自动保存发布同一 UI 版本的 AG-UI 快照，避免重建控件造成光标跳动。提交会等待已发出的草稿保存结束，并暂停新的草稿写入。

发送原生工具响应前，先事务保存 `unavailable/submission_unconfirmed` 快照及未知回执；写入失败时不消费原生请求。管道响应成功后再保存最终状态及接受回执。若后一个写入失败，持久化栅栏仍阻止重复执行。重启后，已接受的精确重试可返回成功；未知回执只返回冲突，不猜测原任务结果。

`capabilities.a2ui.historyRestoration` 现在为 `true`，另报告服务端草稿、24 小时保留和重启只读。旧线程自动注册动态工具仍未实现，因此 `newThreadsOnly` 保持 `true`；D5.4 之前未登记的历史表单不会从任意原生参数中自行重建。
