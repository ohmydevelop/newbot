# D3.3 MCP 配置管理

日期：2026-11-08。完成 [整体计划](roadmap.md) 的 D3.3。设置页现在支持本地 stdio/HTTP MCP 的新增、编辑、删除、启停、原生重载、连接发现与安全错误反馈。Codex 仍是唯一 MCP 客户端，定义仅保存在其配置中；没有新增 MCP 客户端、配置数据库或 Agent Loop。

## 设置操作与数据边界

只有基础用户配置中明确归属、未被其他来源覆盖的定义可编辑。项目、插件、命令行或其他来源的连接只读。用户可添加自己的连接，不会覆盖现有 CLI 测试 MCP。标识采用小写字母开头的字母、数字、下划线或短横线，最多 64 字符。

| 传输  | 可编辑字段                                            |
| ----- | ----------------------------------------------------- |
| stdio | 启动命令、JSON 字符串数组参数、服务端 `env_vars` 引用 |
| HTTP  | 完整 MCP 端点 URL、服务端 Bearer 环境变量引用         |
| 共用  | enabled、启动超时 1–120 秒、工具超时 1–600 秒         |

新连接默认启动超时 10 秒、工具超时 60 秒。编辑时留空保留原命令、参数、端点和引用；参数填写 `[]` 明确清空。环境变量引用和 Bearer 引用通过单独选项移除，不清空原 `env` 值或私密请求头。现有连接不能直接转换传输类型，避免残留另一种传输的私密配置；需要时另建连接。

端点仅支持不含 userinfo、查询或片段的 HTTP/HTTPS URL；其他既有高级配置可保留，并在来源文件维护。命令、参数、环境值、完整 URL 和请求头不下发浏览器。前端只读取 origin、传输、启用状态、超时和“已有参数/环境配置”等标记。命令参数字段用于非敏感参数，不是私密凭证输入。

引用允许列表来自已有 MCP 的 `env_vars`、`env_http_headers`、`bearer_token_env_var`，以及服务端 `MCP_CREDENTIAL_ENV_ALLOWLIST`。`ADMIN_PASSWORD`、`HOME`、`CODEX_HOME`、`NODE_OPTIONS` 始终禁止引用。浏览器只能提交变量名，不能通过本接口提交 `env`、私密请求头或令牌。引用获准不代表值已设置或凭证有效。私密输入流程留到 D6。

删除需要明确确认，仅删除所属用户定义；不删历史会话或产物。删除、停用或重载后，历史 App 的后续工具交互可能失效，需要重新打开；重新打开仍会重新验证资源和工具权限。

## 原生重载与连接测试

保存、启停、删除、手动重载和测试使用相同的版本边界：不透明 revision 检查、可信用户文件定位、原生 `expectedVersion` CAS、写后读取和覆盖反馈。冲突保留草稿，用户必须明确重新读取，不自动换新版本重提。

所有修改、重载和测试要求任务、审批、App 待授权调用与 OAuth 均空闲；维护期间拒绝新任务。配置通过 `config/batchWrite` 保存，再调用原生 `config/mcpServer/reload`。正常 MCP 配置变更不重启整个 Codex。重载清理旧 App 授权记录；新目录经原生分页发现，后续打开 App 重新建立权限。

连接测试对已启用连接先提交原生重载，再通过 `mcpServerStatus/list` 的 `serverName` 读取目录；停用连接直接返回“已停用”，不启动发现。测试不创建 Agent Turn，不执行 MCP 工具，也不发起模型任务。结果区分：

- 已发现：原生目录读取成功，报告工具数量；不等于某个会话已实际使用该连接。
- 需要授权：提供现有 Codex OAuth 入口，用户明确点击安全的新窗口链接；完成授权后重载。
- 失败：命令、端点、凭证或超时导致发现失败，返回固定可恢复说明。
- 未确认：仍在启动或尚无可确认目录，提示稍后重试。

设置 API 只返回连接状态、授权类别、工具/资源数量及固定错误说明。原始 `toolsError`、工具 Schema、Server 信息、能力和 `_meta` 留在服务端，供现有 Apps Host 使用。第三方返回的原始错误不会直接成为 Web 错误或日志。

响应丢失时只检查权威配置并重载，不重复写入。无法确认配置或原生重载失败时清理旧 App 权限并进入离线状态；设置保留草稿及错误，关闭设置、检查服务端配置后，通过聊天页“重新连接”恢复。已经写入的字段不会因重载失败被静默删除。统一的跨模块恢复现已完成，支持直接在设置内重连，见 [恢复记录](configuration-recovery.md)。

新界面通过 `capabilities.mcpManagement` 启用，旧后端保留原 MCP 界面。旧客户端向新后端提交不含 revision 的重载会被拒绝，需要刷新页面，不降级为盲重载。

## 复现

```bash
npm test
npm run build
npm run test:mcp-config-ui
npm run test:mcp-config-live
```

浏览器测试需配置 `PLAYWRIGHT_MODULE` 与 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`。默认独立端口 3114，可用 `MCP_CONFIG_TEST_PORT` 改写。测试目录临时创建并清理，控制路由只在夹具注册；原生验证不会编辑共享服务的 MCP/Provider 配置。证据在 `.data/mcp-config-ui/`、`.data/mcp-config-live/result.json` 和 `.data/d3-3-*.log`。

本轮同时按用户要求更新了现有测试服务与分享入口，见 [服务更新记录](test-service-update.md)。D3.4 已完成统一恢复呈现，见 [恢复记录](configuration-recovery.md)。下一批 D4.1 MCP Apps 生命周期。
