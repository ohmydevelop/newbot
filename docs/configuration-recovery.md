# D3.4 统一配置恢复

日期：2026-11-08。完成 [整体计划](roadmap.md) 的 D3.4，D3 配置管理阶段闭环。默认模型、Provider 与 MCP 现在共用配置问题分类、恢复接口与反馈组件。

## 用户操作

保存失败、冲突或响应丢失时保留当前输入，并显示对应的恢复操作：

- **读取当前生效配置**：读取权威配置并展示当前 Provider、模型、推理强度，以及目标 Provider/MCP 的非敏感摘要。读取本身不提交草稿。
- **重新连接并读取配置**：在设置内重连 Codex 并读取当前配置，不必先关闭设置；需要修复服务端配置时会明确报告失败，不误报恢复成功。
- **采用当前配置并放弃草稿**：用户明确选择后才重置表单，按当前配置重新编辑。不会自动给旧草稿换上新 revision。

如果读取确认配置版本未变化，可以检查保留的草稿后手动重新保存；读取不会代替用户点击保存。若版本已变化，则继续禁止旧草稿保存，直到明确采用当前配置或使用既有“读取最新并放弃修改”入口。部分字段受其他来源覆盖时展示已提交状态和实际生效值，不把原用户配置的写入等同于全面生效。

表单草稿只保存在当前组件内存中，本批不新增浏览器持久化。关闭设置或刷新页面仍可能丢弃未提交输入。失败后保留输入不意味着可以在浏览器重启后恢复草稿。

错误出现时焦点移到恢复区域，读取后保留可检查的当前值；采用当前配置后焦点回到可编辑控件。手机主要操作至少 44px，长内容可换行，深色横屏可滚动访问恢复操作。配置加载过程中显示进度，避免在结果返回前误报“配置不可读”。

## 统一结果与安全边界

共享的 `ConfigurationIssue` 只包含三个枚举字段：

| 字段        | 值与含义                                                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| code        | conflict、read_only、read_failed、write_failed、write_unconfirmed、readback_failed、reload_failed、busy、overridden、switch_reverted |
| persistence | unchanged：本次未确认有配置变更；unconfirmed：结果需检查；saved：原生已确认提交                                                      |
| recovery    | read：读取当前配置；reconnect：重新连接后读取；wait：等待任务或授权结束                                                              |

服务端只序列化自身 `ConfigurationFailure` 的白名单枚举，不采纳上游错误自带的同名对象，不附加原始配置、字段值、文件位置或上游诊断。默认值编辑、Provider/MCP 写后读回及覆盖结果采用同一分类；缺少/无效 revision 的旧客户端会收到刷新与重新读取提示。

前端对传输中断或无法解析的修改响应标记为结果未确认；不能因为没有收到成功响应就判定没有写入。服务端已确认保存但随后刷新失败时仍保留“已提交”事实，后续重连失败或任务占用不会把它降为“没有保存”。普通字段校验、历史引用保护和连接诊断保留原有具体说明，不仅按 HTTP 状态码猜测错误类型。

## 恢复接口

沿用已认证、校验 Origin 的控制入口：

```json
{
  "action": "configuration/recover",
  "mode": "read"
}
```

`mode` 只接受 `read` 或 `reconnect`。请求拒绝额外 edits、文件路径、凭证、revision 或模型参数。接口读取脱敏 Settings；重连只管理唯一 Codex 子进程，不调用配置写入、模型 Turn 或 MCP 工具。

操作共用任务、审批、App 调用、OAuth、维护和并发控制。活动工作或有效授权会阻止恢复，不调用 `turn/interrupt`。进程已经离线后，原进程的 App 授权及 OAuth 等待被作废，不能用于新连接，也不会成为无效的重连阻塞。重连不会把失效授权当成允许。

原生进程可能已初始化成功，但配置仍无法读取；此时不会返回恢复成功，而是进入离线状态，阻止用未确认配置启动新任务。默认值响应丢失时尽可能重新读取权威默认值；读回失败则同样隔离后续新任务。Provider/MCP 重载后读回失败保留已提交事实并进入可重连状态。

Provider 切换失败的既有回滚继续受原生版本约束；只有原生回滚状态和有效 Provider 都已确认，才报告恢复原配置。上层覆盖或外部并发修改不会被盲目回滚覆盖。

浏览器设置请求增加独立的顺序校验：较早的读取或初始化响应不能覆盖恢复接口已经读取的较新配置。默认模型设置仍保持当前对话的选择规则，新对话使用实际默认值。
