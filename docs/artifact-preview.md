## 用户流程

原生文件修改完成后，本轮回复下方出现文件卡片，显示名称、类型、大小和版本。点击可打开预览面板，卡片和面板均可下载原始快照。最新一轮结束后，可通过“添加工作区文件”选择当前文件并关联到该轮；支持进入目录、返回上层、刷新、分页和保存反馈。

| 内容          | 当前行为                                                            |
| ------------- | ------------------------------------------------------------------- |
| 文本          | 保留空白与换行；长行换行显示                                        |
| 代码          | 复用 Shiki 高亮与复制；复制失败给出反馈                             |
| Markdown      | 预览/源码切换；保留表格、列表、公式                                 |
| JSON          | 格式化/源码切换；无效或过大时提示并显示源码                         |
| CSV           | 表格/源码切换；支持逗号、CRLF、双引号转义和多行单元格；首行用作标题 |
| PNG/JPEG/WebP | 经认证读取快照，以临时 Blob URL 显示；关闭后释放                    |
| HTML          | 仅查看高亮源码或下载；不运行脚本                                    |
| PDF           | 显示下载入口；只读预览与 Range 留到 D1.5                            |

预览面板具有加载、失败、重试、空文件和下载失败状态。Escape 可关闭，键盘焦点保留在面板内并在关闭后回到入口。小屏使用单列文件卡片和分行工具栏，长表格仅在自身区域滚动；手机横屏仍保留文件选择器的提交按钮。

文件读取失败不影响原有聊天内容。加载期间关闭会取消读取，后续打开另一文件不会显示旧响应。登录过期时回到登录界面。刷新后从会话历史恢复已登记版本，修改工作区文件不会改变旧卡片内容。

## 渲染与资源边界

- 使用已有 React/Radix、Markdown 和 Shiki 组件；预览模块按需加载，没有新增产品运行依赖。
- 主站不执行 HTML/JavaScript。产物 Markdown 中的原始 HTML 保持文本；图片引用不自动加载，Mermaid/ECharts 代码块按源码显示，避免文档自行启动额外交互或资源请求。
- 纯文本和代码最多预览 64,000 个字符；超出部分提示下载完整文件。原始下载不截断、不重新编码。
- JSON 格式化输入上限为 192,000 个字符；更大文件退回源码预览。
- CSV 最多显示 100 行数据、30 列，单元格最多 2000 字符；解析输入限定 192,000 个字符，超出时提示。
- 浏览器依据服务端能力报告显示“添加工作区文件”。旧版后端未提供登记能力时不显示该入口，避免构建更新期间出现不可用操作。

D1.2 当时未交付 HTML 隔离执行、版本管理界面或物理清理。后续结果分别见 [D1.3](html-preview.md) 和 [D1.4](artifact-lifecycle.md)；上线环境整体验收继续按 R1 执行。

## 同时修复的首次发送问题

真实 Codex 开发测试发现：登录后运行时可先于配置读取就绪，用户迅速发送时，前端可能提交空字符串 Provider，原生 App Server 随后拒绝新建会话。

现在配置读取完成前发送按钮保持禁用，客户端不提交空 Provider；服务端也将空的可选 Provider 归一为原生默认值。增加了延迟配置的浏览器检查和模拟原生空 Provider 拒绝的服务端回归，未更改 Provider 切换或执行审批策略。

- `npm test`：38/38 通过。新增 CSV/JSON/预览大小边界、文档 Markdown 安全渲染以及空 Provider 回归，共 5 项自动测试。

- 真实 Codex 0.166.0 + `gpt-6.1-sol`：由 Web 发送任务，Agent 实际创建 `browser-proof.md`，捕获原生 `fileChange` 并生成卡片；打开后显示 Markdown 标题，刷新后恢复同一快照。来源为 `fileChange`，存在原生 Item ID，文件内容与 SHA-256 均核对通过。未批准额外权限或外部工具访问。

浏览器证据在 `.data/artifact-ui/result.json`、`.data/artifact-ui/*-desktop.png`、`*-dark.png`、`*-mobile.png`；真实运行证据在 `.data/artifact-live/result.json` 和 `.data/artifact-live/real-codex-preview.png`。这些是开发验证，不代替上线前整体验收或真实手机设备测试。

## 复现

需要本机 Playwright/Chromium；未将其增加为产品运行依赖。项目外安装时通过 `PLAYWRIGHT_MODULE` 指向 Playwright 的模块入口文件，必要时通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定浏览器可执行文件。

```bash
npm run build
npm test
npm run test:artifact-ui
# 可选：会调用真实 Provider，运行一次模型任务，需要已有的 Codex 登录/配置。
npm run test:artifact-live
```

两个浏览器测试分别使用 3102/3103 本机端口、独立临时数据目录和测试密码；结束后关闭实例并清理工作区。真实测试成功后归档其测试线程。

本轮未重启原有 `newbot-test.service`，也未迁移其数据库；编译产物已就绪，界面在独立测试实例验证。正式部署、Cloudflare 配置和上线验收仍按用户要求留到开发结束后。
