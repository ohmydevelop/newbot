# 自动任务的事件触发

两种入口：外部直接发送到 Newbot，或 Newbot 通过插件连接外部服务。都进入现有任务队列、持久去重，并将连续结果写入该任务的同一会话。

## 外部直接发送

1. 在自动任务中添加“接收事件”，可填写一个事件类型；留空接收全部类型。
2. 保存任务，在概览中打开“接收配置”，复制地址与访问凭证。
3. 向该地址 POST，携带 `Authorization: Bearer <凭证>`。凭证只允许投递到这个触发器，不允许管理任务或读取会话。

请求正文使用 CloudEvents 1.0 JSON 对象。当前接收范围：`specversion`、`id`、`source`、`type`、`time`、对象形式的 `data`，可选 `subject`；`datacontenttype` 为 `application/json`。不支持二进制内容模式或批量请求。单次正文上限64KiB。

```json
{
  "specversion": "1.0",
  "id": "build-42",
  "source": "urn:my-service:builds",
  "type": "build.completed",
  "time": "2026-11-18T00:00:00Z",
  "data": { "result": "success", "build": 42 }
}
```

成功接收返回202与运行ID；重复的同一 source+id 返回200与原运行ID。相同ID内容不同返回409。返回成功表示已持久入队，不表示模型已经完成。发送方应保留稳定ID并重试暂时失败；凭证失效、类型不匹配等错误需要先修正配置。

任务编辑或暂停/恢复会改变版本，旧凭证不能投递，需重新打开接收配置。更换凭证立即失效；删除任务关闭入口。凭证加密保存，不写入任务指令或事件上下文。不要把凭证放入URL。

外部发送方必须能够访问配置中的 Newbot 地址。公网发送使用HTTPS；本地开发允许回环HTTP。无公网入口的内网机器可选择下面的出站插件方式。具体供应商原生Webhook可能使用不同格式/签名，需要独立适配；此入口不宣称直接兼容所有供应商。

## 插件连接外部服务

安装插件，在触发器中选择其来源，连接账号并填写插件声明的条件。插件可轮询或持续连接，也可协商直接回调Newbot的签名Webhook。工具插件没有声明事件接口时不会自动出现触发器。

安装格式和协议范围见 [事件桥](event-bridge.md)。只接受version 2事件声明，插件触发器必须包含providerId、connectionId、events、arguments。不保留旧业务专用格式、v1适配器或缺失字段补齐；无效旧任务及依赖记录删除，聊天正文保留。直接接收是独立的通用入口，不冒充已安装插件。
