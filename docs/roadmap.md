## 产品完成目标

用户可以通过 Web 完成聊天、选择模型和技能、管理 Provider/MCP、查看 Agent 生成的文件和页面、使用 MCP Apps/A2UI，并通过独立的可信通道完成私密授权。核心交互保持 ChatGPT 风格，桌面和手机均可用。

保留 Codex 作为唯一 Agent 内核、Fastify 作为唯一 Web 服务、React 作为唯一前端。Provider/MCP/Skills 配置以 Codex 为准。普通回答使用 Markdown，第三方 App、声明式组件和文件预览各有明确的渲染与权限边界。

## D1 文件与 HTML 产物预览

目标：让 Agent 生成的文件和页面成为可打开、可恢复的聊天产物。

- [x] D1.1 建立最小产物登记与消息关联，限定工作目录及可读取文件。实现与测试见 [产物登记记录](artifacts.md)。
- [x] D1.2 完成文本、代码、Markdown、JSON/CSV、图片的预览和下载，接入聊天卡片与工作区文件选择器。见 [预览记录](artifact-preview.md)。
- [x] D1.3 完成自包含 HTML/JavaScript 的隔离预览、打开/关闭与重新加载。见 [HTML 隔离记录](html-preview.md)。
- [x] D1.4 补齐文件版本、大小限制、清理、归档保留和断线恢复。见 [文件生命周期记录](artifact-lifecycle.md)。
- [x] D1.5 完成 PDF 只读预览及所需的 Range 读取。见 [PDF 预览记录](pdf-preview.md)。

边界和实现约束：

- 产物来源优先采用原生文件变更记录及用户明确选择的工作目录文件。模型输出任意绝对路径，不等于获得读取授权。
- 登记时验证会话归属、真实文件路径、符号链接、文件类型和大小；默认不自动登记密钥、凭证与隐藏配置文件。
- 普通消息继续使用 Markdown。文件通过受控关联显示为产物卡片，不引入自定义富文本语言。
- 活跃 HTML 在独立 origin 的 sandbox iframe 中运行，不取得聊天 DOM、Cookie、任意网络或 MCP 工具权限。
- 历史产物对应已登记的版本；后续文件变化不得悄悄替换历史内容。只保存恢复预览所需的元数据与必要快照。
- 优先复用现有文件接口、附件配额和清理机制，不创建第二套聊天存储。

本阶段支持文本、代码、Markdown、JSON/CSV、PNG/JPEG/WebP、PDF 和自包含 HTML。文件能预览不代表模型原生理解该格式；模型输入按运行时实际能力处理。音视频、Office 在线编辑留给后续明确需求。

交付验收：真实 Agent 生成 HTML 卡片后可以在聊天中打开；文本/图片可查看或下载；刷新后能恢复同一版本；越界路径与未授权工具请求被拒绝；手机无横向溢出。

D1.1 已完成服务端登记与受控读取；原生文件修改事件和手动登记均关联到会话/Turn，快照、去重、版本号和归档保留已具备基础实现。D1.4 已补齐版本交互、清理与恢复的开发验证，见本阶段记录；上线环境整体验收仍留到 R1。

D1.2 已接入聊天产物卡片、工作区文件选择器、预览面板和下载，完成小屏/深浅主题、重试、刷新恢复及真实 Codex 文件生成流程验证。

D1.3 已完成自包含 HTML/JavaScript 的独立 origin 双层预览、源码切换、关闭、重新加载、会话绑定的短时凭证和失败重试；页面不接入工具通道。原始快照与下载保持不变。

D1.4 已完成版本选择、同轮同路径卡片合并、存储用量/清理设置、未引用快照和临时附件清理、配额保留，以及归档/断线/重启恢复验证。不会自动删除历史版本来腾出配额。

## D6 私密输入与受信消费

目标：用户可以授权需要秘密的受控操作，模型只得到授权状态、受限引用或脱敏结果。

- [x] D6.1 定义可信输入请求、操作身份、有效期、取消和一次性消费。
- [x] D6.2 在 Bridge 内实现最小 Credential Broker 与受信消费组件，先打通 API Key/工具凭证实例。见 [可信私密输入记录](trusted-input.md)。
- [x] D6.3 将 Provider/MCP 设置中的私密字段接入写入后不可回读的流程；完成临时持有或明确选择的加密保存。见 [保存与恢复记录](credential-storage.md)。
- [x] D6.4 为固定 sudo 身份检查实现受控执行/私密输入通道及独立验证；不开放任意提权命令。见 [sudo 通道记录](sudo-input.md)。
- [x] D6.5 完成当前受信操作的聊天、工具失败、错误、日志、Trace 和浏览器存储隔离验证；原生循环与成功内容的信任边界见 [验证记录](credential-isolation.md)。

实现约束：

- 私密请求由可信服务端操作定义，不能由模型或第三方 iframe 任意指定接收方。
- 领取凭证必须验证工具/执行组件身份、操作范围、期限和次数，单有模型可见的引用不足以领取秘密。
- sudo 输入交给受信执行通道，不把密码注入聊天、普通工具参数或由 Codex 接管的普通 PTY。
- 只允许具备可验证消费链路的操作；无法满足隔离的能力保持关闭并修复，不用隐藏密码框冒充完成。
- 本项目面向可信项目；同一宿主用户下的 Broker 不是抵御同等权限恶意进程的强隔离边界。

交付验收：至少一个真实受信消费者成功使用凭证；模型与各输出通道均看不到明文；错误身份、重复领取、过期引用和取消操作失败。凭证与 sudo 分别报告能力状态，不共用一个已完成标记。

## 每批任务的推进方式

1. 确定本批用户操作、接口边界、数据归属和完成标准。
2. 完成最小可运行纵向流程，再补错误、取消、恢复与权限边界。
3. 运行与改动相称的类型检查、契约/安全测试和必要浏览器检查。
4. 更新本计划的勾选项、当前进度和实测记录，说明实际限制。
5. 本批闭环后进入下一批；不以静态原型、模拟按钮或未验证能力代替交付。

开发期的上述验证继续进行；最后再集中跑完整场景和目标环境验收。
