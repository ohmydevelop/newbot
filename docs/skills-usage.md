# D2.2–D2.4 技能选择、原生调用与历史引用

日期：2026-11-08。D2 Skills 使用闭环完成，沿用 [D2.1 说明查看](skills-viewer.md)、Codex 原生 Skills 和现有请求防重机制。

## 用户流程

输入框新增“技能”入口。选择器可搜索原生名称、显示名称及简介，区分来源和启用状态；支持多选，每条消息最多 8 个。选择时受控读取当前说明并记录 SHA-256，停用或无法读取的技能不能加入。选择完成后，在输入框上方显示可移除的技能项。

技能仅用于下一条发送的消息。发送成功后清空选择；验证或网络失败时保留草稿与选择。切换会话、新建会话和退出登录清空未发送选择。发送结果尚未确认时锁定技能修改，继续使用既有稳定 requestId 查询机制，不自动重复执行。

消息发送后，用户消息显示“本条消息指定的技能”。点击可查看该技能的当前说明；名称和指纹保留调用时的值。说明发生变化时明确提示“以下显示当前版本”；技能停用仍可只读查看，删除、路径失效或无法读取时保留原引用并显示可重试错误。名称变化会显示原名称。查看历史引用不重新运行技能。

不保存每份历史说明全文；历史引用记录用户指定的技能及 Bridge 在发送前校验到的内容指纹。Codex 原生输入通过路径加载技能，指纹不对运行时文件加锁；校验完成后其他宿主进程仍可能修改文件，不声称模型读取的字节被永久固定。

## 原生输入与验证

`POST /api/agent/run` 新增可选 `skills`：

```json
{
  "skills": [{ "id": "64 位技能标识", "sha256": "64 位说明内容指纹" }]
}
```

实际值必须是 64 位小写十六进制字符串。最多 8 项、禁止重复，条目不接受额外的名称或文件路径。未选择时省略或传空数组，服务端归一为空缺字段，保留旧请求的防重指纹兼容。

Bridge 在创建新提交记录前重新发现、读取并验证技能；在实际派发 Turn 前再次验证，覆盖初始化/恢复期间的变化。每次都检查 ID 是否仍在原生列表中、启用状态、受控文件读取和内容哈希。未知、停用、缺失、链接、超限或已变化的技能拒绝执行，提示用户移除或重新选择，不悄悄改用别的技能。

验证通过后，仅由服务端生成固定版本 Codex 的原生输入：

```ts
{ type: "skill", name: currentSkill.name, path: currentSkill.path }
```

它与普通 `text`、附件输入并列，不向聊天文本拼接技能正文，也不将浏览器传入的路径直接交给 Codex。原生类型来自自动生成的 `UserInput`。技能内部如何加载和执行继续由 Codex 负责，没有新 Agent Loop。

所有输入在派发标记之前准备完毕。已接受请求即使之后删除了技能，也可按原 requestId 返回原结果；改变技能选择不能复用同一请求 ID。丢失响应时依靠原生 `clientUserMessageId` 与历史确认，不重复发送。

## 历史关联与数据库

SQLite 开发 Schema 升级为 `user_version=3`，新增 `run_skills` 表，关联 `runs.request_id`，仅保存顺序、技能 ID、原生名称、显示名称、来源和 SHA-256。不保存说明正文、绝对路径或另一份完整对话。v1/v2 数据迁移保留已有会话、登录、附件和产物；较新数据库仍拒绝由旧版本打开。回滚需使用与应用匹配的数据库版本。

引用在派发前与请求绑定：明确未派发的失败会解除关联；已派发但结果未知时保留，以便后续确认。按会话归属和原生用户消息的 canonical client ID 恢复；仅在 client ID 缺失且 Turn 已确认时对该轮首个用户消息使用兼容回退。不会将引用关联到其他消息或其他会话。

原生消息到达后发布包含引用的 AG-UI 权威快照；刷新、断线重连、历史分页、Bridge 重启和归档读取均从现有请求关系恢复。附件关联与技能引用共存，不覆盖附件内容。

运行时新增 `capabilities.skillSelection = { structuredInput: true, history: true, maxPerMessage: 8 }`。旧后端隐藏选择入口并继续保留原有技能发现、启停能力。读取界面复用 D2.1 的文件与 Markdown 边界；新界面按需加载，没有新增产品依赖。

## 复现

```bash
npm run build
npm test
npm run test:skills-ui
npm run test:skills-use
# 可选：需要现有 Codex/Provider 访问，会执行一次真实模型任务。
```
