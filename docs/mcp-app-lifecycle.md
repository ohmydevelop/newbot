# MCP Apps 生命周期（D4.1）

日期：2026-11-08。基线为固定 Codex 0.166.0、生成的 App Server 类型及已安装的官方 MCP Apps SDK。本批完成加载、结果关联、关闭、过期与重新打开。后续 D4.2 Host 能力说明与 D4.3 普通 Elicitation 已完成，见 [Host 能力记录](mcp-app-host.md)及[普通输入记录](mcp-elicitation.md)；更广的官方示例矩阵继续放在 D4.4。

## 用户行为

工具成功完成后，聊天根据原生 UI 元数据或当前 MCP 工具目录显示交互应用。View 明确区分资源加载、协议初始化、已连接、失败、过期和已关闭，并显示 Server / Tool 及原始结果身份。加载和初始化分别限时 15 秒，失败后提供明确重试入口；关闭及失败后的键盘焦点回到重新打开按钮。

每次打开从 Codex 历史读取对应 thread / turn / item 的原始参数和结果，然后读取 UI 资源。重新打开创建新 View，并重放原始结果；先前在 App 内刷新的临时状态不冒充原始结果。不调用 `turn/start`，也不重跑原 MCP 工具。

关闭立即移除 iframe，并请求服务端撤销 View 和待授权请求。资源尚未返回时也可通过 requestId 取消，迟到的响应不能使已关闭页面复活。重新打开重新读取资源与权限。已经批准并提交给 Codex 的调用可能继续执行；关闭 App 不等于中断该工具。

View 到期、配置重载、Codex 重连及缓存页面恢复均提供重新打开入口。可见页面每 15 秒只读检查 View 状态，窗口重新聚焦或恢复联网时也检查；本地到期计时不依赖检查响应。页面退出发送尽力清理请求；离线或进程突然结束时不能保证清理请求到达，服务端仍通过短期有效期限制残留权限。

## 服务端与权限

- 历史描述符只保存关联元数据，不创建、延长或恢复权限。内存最多保留 256 个描述符及 32 个按线程隔离的最小工具目录。
- 每次打开产生独立随机 token，有效期 15 分钟，绑定当前 Web Session 的服务端摘要。最多同时存在 32 个 View；达到上限时要求关闭已有 View，不驱逐活跃页面。
- 最多 32 个未完成打开请求。取消记录保留 5 分钟、最多 256 个；操作还会在每次异步返回时检查取消状态。登出撤销该 Session 的 View 及未完成加载。
- 只从属于工作台的线程读取原始结果。优先带 turnId，通过原生 `thread/items/list` 分页查找，每页 100 条、最多 50 页；未找到时明确失败，不退回其他工具结果。
- 打开、申请工具授权及批准执行前重新读取对应线程的 MCP 目录。来源工具必须仍关联同一 `ui://`，允许的工具必须属于同一 Server、同一资源且具备 App visibility。来源关联变化使旧 View 失效。
- 每次 App 工具请求仍需用户单次批准。授权最多 2 分钟，且不超过 View 到期；拒绝、超时、取消、View 关闭或配置重置使未消费授权失效。批准前再次校验 Session 与最新工具权限。
- 资源必须匹配请求 URI，并为 `text/html`（允许 MIME 参数）；原始参数/结果及 HTML 分别限制 2 MiB。原始结果中的 App 私有 `_meta` 仅通过显式打开交付给 Host/View，不扩散到普通聊天 DTO。
- 独立 origin、`sandbox="allow-scripts"`、严格 CSP、禁止网络和第三方依赖的现有约束保持有效。沙箱文档同时验证 View 与所属登录仍有效；关闭、登出或到期后旧 URL 返回 404。

控制接口为 `/api/mcp-apps/open`、`close`、`status`、`call-request`、`call-approve`、`call-cancel`。均要求主站登录和合法 Origin。状态和撤销不调用 MCP，可在配置维护期间完成清理。`capabilities.mcpAppLifecycle.leases` 用于版本检测；新 Web 连接旧后端时不发送尚未实现的生命周期控制接口。

错误响应只携带白名单问题码和固定提示，不把上游诊断、工具 Schema 或敏感内容拼入用户可见错误。此批没有增加外链、网络、消息注入或任意资源读取权限。

## 开发验证

`npm test` 共 131 项通过，其中新增 16 项生命周期测试，覆盖独立租约、到期、分页历史、跨 Session 拒绝、取消迟到加载、资源校验、权限变化及授权撤销。

`npm run test:app-lifecycle-ui` 使用隔离目录及官方 SDK 的模拟 App，19 项检查覆盖两个原始结果的准确关联、无元数据回退、关闭/重开、单次批准/拒绝、授权超时、资源/初始化超时、失败重试、缓存页面恢复、运行时失效、独立浏览器 Session、手机深色布局及网络隔离。测试仅创建一次模拟 Turn，重新打开不增加模型或工具执行。证据在 `.data/app-lifecycle-ui/`。

另运行统一配置恢复、MCP 设置及原 MCP Apps SDK 交互回归；共享测试服务更新后，使用已有模拟监控工具的真实 Codex 历史验证原始结果读取、资源隔离、关闭撤销和再次打开。详细服务验证见 [测试服务更新记录](test-service-update.md)。这些是开发检查，正式环境及上线整体验收仍留到 R1。
