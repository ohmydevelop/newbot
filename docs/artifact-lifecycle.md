# D1.4 文件版本、容量、清理与恢复

日期：2026-11-08。完成 [整体计划](roadmap.md) 的 D1.4，沿用现有 SQLite v2、附件和快照目录；不增加持久化系统或数据库迁移。

## 用户可见变化

文件预览新增版本选择器。同一会话、同一路径的所有已保存版本可切换，初始仍显示打开卡片时的版本；出现新版本不会自动替换正在查看的内容。“此回复”和“最新”分别标识原卡片版本与最新已知版本，列表可刷新，超过 50 条时按版本号加载更早记录。

同一轮多次修改同一路径，回复下方合并成该轮最新版本的一张卡片，所有中间版本仍保留。不同轮的卡片保持各自关联。切换版本后，内容、版本号和下载入口同时更新；HTML 换版会撤销旧运行凭证并打开新快照，而不是在旧页面里替换脚本。

设置增加“文件存储”，展示共享配额、已保存快照、上传附件、未登记文件及历史版本数量。可刷新用量、清理过期未使用文件，读取和清理失败均有反馈。旧后端没有对应能力时不显示新增管理入口。

文本、图片和 HTML 的预览继续按 D1.2/D1.3 的权限与内容边界运行；文件版本列表按原产物所属的会话/路径查询，不接受任意服务器路径。

## 保留与清理策略

| 数据                                     | 策略                                                                       |
| ---------------------------------------- | -------------------------------------------------------------------------- |
| 已登记版本的快照                         | 保留，无论会话是否归档或浏览器是否在线                                     |
| 多条记录共享的快照                       | 按 SHA-256 去重；任何一条引用存在就保留                                    |
| 未被引用的 SHA-256 快照                  | 最后修改时间超过 24 小时可清理，删除前再次检查数据库引用                   |
| 新上传但未绑定运行的附件                 | 沿用现有 24 小时过期策略                                                   |
| 已绑定运行的附件                         | 保留，包括归档会话与结果未知的运行                                         |
| 旧版 legacy 附件及无法确认来源的附件文件 | 保留并计入配额，不凭文件名猜测删除                                         |
| 目录、符号链接、未知文件名与不安全链接   | 不遍历、不自动删除；正常文件按保守方式统计                                 |
| 部分写入留下的未引用损坏快照             | 下一次明确读取同内容文件时，可重新创建；已被历史引用的快照不会被该路径覆盖 |

启动时完成扫描和到期清理，正常运行时按小时维护，也可从设置手动清理。GET 用量接口只扫描和更新内存统计；删除仅发生在维护或明确的清理操作中。工作区不属于清理范围。私有快照和附件目录本身也必须是真实目录，拒绝跟随链接目录执行读写或清理。

采集与快照维护共用串行队列，避免文件刚写完、尚未登记时被当作孤儿删除。模型事件仍持续消费，不因文件清理而停止 Agent。此协调范围是同一个 Bridge 进程；按产品既定单实例方案运行，不支持多个 Bridge 同时共享写入同一个数据目录。

## 配额与异常

附件和去重快照共用 512 MiB。已登记内容的预算按元数据保留，扫描到的未登记正常文件也占用预算；因此重启后留下的未引用文件不能绕过配额。重新引用已存在的有效快照时，将未登记占用转成已登记占用，不重复收费。

配额是应用文件预算，不是文件系统分区的硬限额。缺失快照仍保留原预算与记录；数据库、目录元数据及其他进程的磁盘使用不包含在该配额中。上传与采集都在写入登记前检查预算，采集提交前再次检查，以处理上传在异步写入期间消耗配额的情况。

文件大小继续限制为单份产物 8 MiB、文本 2 MiB；上传文本仍遵守原有更小的附件限制。满额时拒绝新的内容写入，给出明确反馈。清理不会自动删除引用中的历史版本，也不保证腾出已有版本占用的空间；本轮不增加历史版本删除界面。

快照读取仍验证大小、路径、链接和 SHA-256。缺失或损坏返回 HTTP 410，说明历史记录保留并提示从备份恢复；不读取当前工作区来冒充旧内容。恢复原始快照后，同一产物 ID 可重新读取。损坏的已引用快照不会自动覆盖。

## 恢复行为

- 浏览器关闭后，后端继续执行与采集；重新进入时通过权威线程状态恢复产物。
- 断线重连返回包含版本引用的 AG-UI 状态快照，不要求重放所有文件事件。
- Bridge 重启后从 SQLite 和快照文件恢复同一产物 ID、版本与哈希；旧 HTML 运行凭证失效，重新打开时再授权。
- 归档保留产物与绑定附件引用，维护不会因侧栏中不可见而删除它们。
- 进程中断时未完成的采集仍标记失败，不会自动补采当前工作区内容并伪装为过去版本。

归档浏览/取消归档界面不在本批新增范围。这里验证的是数据保留和受控读取恢复，也不声称容器崩溃后原模型任务会继续运行。

## 产品接口

均复用已有 Session 与写请求 Origin 校验；独立应用域仍不能访问 API。

| 接口                                      | 作用                                                           |
| ----------------------------------------- | -------------------------------------------------------------- |
| `GET /api/artifacts/:id/versions?before=` | 当前产物的同会话/同路径版本，按版本号倒序，每页最多 50 条      |
| `GET /api/storage`                        | 扫描并返回应用配额、分类用量、可回收预算和文件大小限制         |
| `POST /api/storage/cleanup`               | 清理到期未引用内容，返回清理数量、释放配额、失败数量及最新用量 |

读取版本元数据不会更改原来的消息关联。存储统计不返回私有绝对路径、凭证或文件内容。

`npm run test:artifact-lifecycle`：11 项浏览器检查通过，包含关闭页面后完成采集、运行中新版本不替换当前预览、选择版本与下载一致、刷新保留、列表失败重试、HTML 版本运行撤销、清理结果与保留文件、缺失快照恢复、用量错误恢复、深色和 375px 布局。图片证据经实际打开检查，手机版本行与预览操作分开排列。

原有 `npm run test:artifact-ui` 的 19 项和 `npm run test:html-preview` 的 14 项回归通过。`npm run build` 通过，包括 TypeScript、静态压缩/上一代资源保留及服务端打包，没有新增产品运行依赖。

这些恢复测试使用独立目录和 FakeCodex；本轮未重新调用真实 Provider。真实 Codex 的文件/HTML 生成流程验证沿用 D1.2/D1.3，不将模拟事件称为真实模型验收。备份介质恢复、正式容器、目标浏览器与长时间运行仍按用户安排留到 R1。

复现浏览器检查需本机 Playwright/Chromium；项目外安装时设置 `PLAYWRIGHT_MODULE`，必要时设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`。证据在 `.data/artifact-lifecycle/result.json`、`versions-*.png`、`storage-*.png`；原有回归证据沿用 `.data/artifact-ui/` 和 `.data/html-preview/`。
