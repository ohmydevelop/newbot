## 用户操作

新增 Provider 填写标识、显示名称、API 基础 URL，以及可选的服务端凭证环境变量名。标识采用小写字母开头的字母、数字、下划线或短横线，最多 64 字符。新定义固定采用 `wire_api = "responses"`，不使用 Codex 账户授权。只有基础用户配置中可明确定位、未被其他来源覆盖的自定义定义可编辑；内置和其他来源的定义保留只读。

编辑时端点和凭证引用留空表示保留。浏览器只获得端点 origin，不获得完整路径、查询或凭证。服务端按叶子字段修改 `name`、`base_url`、`env_key`，保留既有私密请求头、令牌及高级选项。勾选“移除现有 env_key 引用”只移除此引用，不清空其他认证字段。URL 仅允许 HTTP/HTTPS，拒绝 userinfo、查询和片段。不能通过接口提交原始密钥、任意配置字段或原生 edits。

凭证值仍在服务端配置。允许引用 `OPENAI_API_KEY`、已有 Provider 的环境变量引用，以及服务端 `PROVIDER_CREDENTIAL_ENV_ALLOWLIST` 指定的变量名。`ADMIN_PASSWORD`、`HOME`、`CODEX_HOME`、`NODE_OPTIONS` 不可引用。允许引用不代表变量已经设置或凭证有效；诊断会检查变量是否可用。私密凭证录入仍属于 D6。

删除需要界面内明确确认，并检查当前 Provider、全部 Web 历史（含归档）、有效配置及配置层中的引用，以及 Codex 原生未归档/归档历史。任一引用存在或历史核对失败均拒绝删除。删除仅移除该用户定义，不删除会话及其他配置。

## 模型目录与连接诊断

这两项操作分别报告结果，不产生“完整 Agent 兼容”的标记：

| 操作                             | 来源与边界                                                                                                           |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 当前 Provider 的发现模型         | Codex `model/list`，支持分页；模型目录不是连接成功证据                                                               |
| 非当前自定义 Provider 的发现模型 | 服务端固定请求其 `/models`；结果仅用于诊断，不直接进入聊天模型选择器                                                 |
| 基础 Responses 测试              | 服务端固定向 `/responses` 发送 `Reply OK.`，不开流、不存储、无工具、最多 64 输出 Token；校验响应外形，不返回模型内容 |
| Codex 账户授权 Provider          | 不读取或转发账户令牌；提示切换后查询原生目录，并通过真实对话验证                                                     |

基础测试可能产生少量模型费用，界面在操作前说明。诊断有 15 秒超时、256 KiB 响应上限，禁止重定向，不转发上游原始错误或模型输出。模型 ID 限制长度与字符，并过滤含已解析凭证的结果。HTTP 服务端是诊断的执行方，浏览器不会直接请求 Provider。

流式事件、推理参数、工具循环、上下文恢复与真实双 Provider 的完整兼容矩阵留到 R1。没有在本批调用外部模型来代替该验收。

## 保存、切换与失败处理

所有新编辑/删除及 Web 切换携带 D3.1 的不透明 revision。服务端重新读取后核对，并将可信用户文件和原生 `expectedVersion` 交给 `config/batchWrite`。冲突不会自动换版本重提；草稿保留，用户明确重新读取并确认修改。底层配置适配器已抽取通用变更入口，HTTP 返回值仍只含脱敏配置。

操作要求任务、审批、待授权 App 调用与 OAuth 全部空闲。配置维护期间拒绝新任务；保存后重启唯一 Codex 子进程，清理旧 App 运行记录并重新读取配置。已有 App 视图可能需要重新打开会话。即使部分字段被上层配置覆盖，也重新加载后显示真实生效值。

保存响应丢失时不重复写入。若读回表明配置确已变化，会从权威配置重新加载进程，HTTP 仍报告结果需确认，界面要求重新读取。无法确认配置或重启失败时进入离线状态；修复服务端配置后，关闭设置，通过聊天页“重新连接”恢复。不会在配置与进程状态不明时继续声称保存成功。跨 Provider/MCP 的统一恢复现已完成，见 [恢复记录](configuration-recovery.md)。

切换后重新发现模型，为已明确配置但在新目录中不可用的默认模型/推理强度选择有效值。新对话使用新配置；历史会话继续依照保存的 Provider 恢复。切换失败时只对本次已确认的版本尝试恢复原用户层字段；后来发生的修改不会被回滚覆盖，进程改从当前配置重新加载。旧的无版本内部夹具/兼容切换路径保留，新 Provider CRUD 不会降级盲写。

通过 `capabilities.providerManagement` 启用新界面。连接现有旧后端时继续显示原 Provider 列表，不显示不可调用的管理入口。

- 相关回归：默认配置 11 项、Skills 调用 11 项浏览器检查，以及 MCP Apps SDK 初始化、结果和经审批的反向工具调用通过。构建与 TypeScript 检查通过。
