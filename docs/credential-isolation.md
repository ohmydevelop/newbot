# 私密消费的输出、错误、日志与 Trace 验证（D6.5）

日期：2026-11-09。已完成当前受信操作范围的隔离矩阵，并修复 HTTP 错误、流式工具失败和 Trace 元数据中的遗漏。D6 阶段闭环，下一阶段 D7 产品体验收尾；正式部署与上线统一验收继续留在 R1。

## 本轮修复

1. **HTTP 错误来源。** 原先只根据中文开头和长度判断可公开错误，无法区分产品提示与上游反射。现在只有产品明确构造的 `PublicError` 及受控子类可提供提示；普通异常、解析错误、原始诊断均使用固定说明。异常携带的状态码还须是合法的 400–599 整数，不会进入 Fastify 的二次错误正文。既有文件、技能、配置和表单的固定恢复说明保留。
2. **原生运行时错误。** Codex 版本探测、进程启动、初始化失败均返回固定诊断，不转发 `execFile`、stderr 或原始异常正文。
3. **工具失败。** MCP 历史视图原本已隐藏原始 `error.message`，但 AG-UI `TOOL_CALL_RESULT` 曾直接使用原始错误。现在流式事件、快照与历史统一隐藏失败诊断和失败结果；MCP Apps 的 `isError: true` 结果也只提供固定说明。成功的结构化数据及 App 专用显示元数据继续按原有协议传递。
4. **Broker 输出。** 消费者结果严格限制为固定状态、原因枚举和布尔标志。即使后续消费者错误地把上游正文作为 `reason` 返回，也不会进入票据或审计。
5. **Trace 元数据。** 不再读取异常自定义 `name`；错误类型使用固定分类，操作名和 Turn 状态采用白名单。对话/运行标识以带 `sha256:` 前缀的摘要记录，相同标识可关联，原文不导出。私密消费有独立的显式 Span，不采集密码、参数、正文或结果。资源自动发现与 HTTP/进程自动埋点继续关闭。
6. **运行日志。** 保留路由模板、服务端请求 ID、状态和耗时；HTTP 方法也限制为标准枚举。URL、查询参数、请求头、Cookie、请求体、异常正文和工具载荷均不记录。

能力 `trustedInput.errorOutputVersion: 1` 标识本轮错误出口策略，不增加新的私密操作或任意内容审查能力。

## 明确的边界

这里验证的是 Bridge 管理的受信输入、消费者及公开出口。Provider 和持有 Token 的 MCP 是受信接收方，不应把凭证放进正常文本、结构化结果或应用 HTML。成功消息、文件、普通命令输出和 App 内容仍是用户数据，这一模块不是对所有内容进行搜索替换的 DLP 系统。

Codex 的内部模型循环和原生持久化由 Codex 管理。Bridge 可以隐藏公开的失败诊断，无法在 Codex 收到 MCP 结果之前拦截它，也不会重写原生对话文件。本次恶意 MCP 错误测试没有在该错误之后继续调用模型；它验证的是公开结果规范化，不能据此保证恶意 MCP 向 Codex 回传凭证后仍不会进入后续模型上下文。原生 Home 和服务端备份仍按私密数据管理。

同 UID 恶意进程、调试器及宿主管理员不属于 Broker 的强隔离范围。密码/API Key 在受信消费时必然存在于必要的进程或网络缓冲区；可控 Buffer 会清零，不承诺浏览器、JS 字符串或系统缓冲区的物理擦除。普通 MCP/A2UI 输入不能接收私密凭证，任意 Agent 私密请求、任意 sudo 命令和 stdio 凭证注入仍关闭。
