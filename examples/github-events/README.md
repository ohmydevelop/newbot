# GitHub 仓库事件

这个插件让 Newbot 在仓库发生变化时运行自动任务。它主动查询 GitHub，不需要给内网 Newbot 配置公网回调地址。

## 安装和使用

1. 在仓库根目录运行 `npm run build:event-plugins`。
2. 在 Newbot 设置中导入生成的 `.data/event-plugins/github-events` 插件包。
3. 新建或编辑自动任务，在“添加触发器”中选择插件提供的 GitHub 事件来源。
4. 配置账号，选择事件类型，填写 `owner/repository`；工作流完成事件还可按分支筛选。
5. 保存任务。首次读取建立基线，后续匹配事件触发执行，结果追加到该任务的同一个会话。

也可以把插件接到通用出站桥，由独立 HTTPS 中继交付给 Newbot。两种方式选择一种，避免重复创建业务任务。中继部署和配置见 [事件 Bridge 指南](../../docs/event-bridge.md)。

## 支持的事件

| 类型                            | 范围                                                       |
| ------------------------------- | ---------------------------------------------------------- |
| Issue / PR                      | 关闭、重新打开、添加或移除标签、指派或取消指派成员         |
| 工作流完成 `workflow.completed` | 工作流名称、分支、提交、运行链接与结论；可用于 CI 结果分析 |

它不是 GitHub 全量 Webhook 接收器，不包含所有新建、评论或 Push 事件，也不支持 GitHub Enterprise 和自定义 API 地址。

## 凭证和读取范围

公开仓库可以匿名读取，但匿名 API 配额可能不足。私有仓库或需要更高配额时，在私密配置中提供有对应仓库读取权限的令牌：Issue 来源需要 Issues 读取权限，工作流来源需要 Actions 读取权限；所选事件涉及的其他资源也需对应读取权限。

出站桥通过明确列出的 `GITHUB_TOKEN` 环境变量把令牌交给插件。令牌仅用于 `api.github.com`，不要写进任务指令、插件源码或事件正文。

## 轮询与恢复边界

插件约每分钟检查一次。首次读取建立基线，不把已有历史当作新事件执行；应保留持久游标，不能靠删除状态恢复服务。

工作流来源读取最近 100 条已完成运行，以运行 ID 和 attempt 区分重跑，每批最多交付 32 条。窗口完全越过未消费检查点时报告缺口，不静默跳过；已离开该窗口的旧工作流重跑不在覆盖范围内。需要完整审计时，应接入有完整事件保留能力的上游。

这是限定版本的 MCP Events 草案与 Newbot 扩展实现，不是 Codex 自动提供的通用事件能力。真实公网中继与模型验收见 [验证记录](../../.issue/2026-11-17/003-bridge-public-progress.md)。
