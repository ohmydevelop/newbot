# UI15：本地 OAuth 与触摸验收记录

起点：产品46c9672，工作树8d2db4c。用户将Slack测试改为完全本地OAuth，确认暂无真机。以下区分真实客户端、合成上游和设备模拟。

## UI15-O：授权与恢复
- 真实 native Codex（生产同版本）+ 隔离 CODEX_HOME + Newbot server + 127.0.0.1 合成授权服务/受保护 MCP；未使用公开隧道、外部账号或模型请求。
- 浏览器从 Newbot 发起授权，先拒绝、再重试允许；真实 Codex 交换授权码，授权服务校验 S256 PKCE。未伪造完成事件。
- 本地 provider 计数证明：1次拒绝、1次批准、1次PKCE校验、3次工具实际调用（首次/刷新后/重启后）、1次令牌刷新、1次授权码重放被拒绝。
- 原生进程重启后重新发现工具，发现计数增加，再开线程调用 echo 成功。页面刷新可重新加载。
- 证据：evidence-ui15/local-oauth/result.json、local-consent.png、local-connected.png、video/；复现脚本 scripts/test-local-oauth.ts 与 tests/local-oauth-provider.ts。测试结束自动删除隔离配置目录并关闭监听。
- 关联机制回归：connector-contracts.test.ts + mcp-config.test.ts 共19项通过，覆盖attempt匹配、迟到/重复完成、全局事件与安全反馈等。此部分为替身单测，不冒充第三方登录实测。
- 尚未覆盖：Slack真实账号登录/授权、Slack管理员策略与实际读写工具、任意第三方OAuth兼容性。本地授权页是合成身份授权，不能证明真实身份提供方的密码/MFA登录。

## UI15-M：触摸、拖拽、动画
- Chromium手机模拟使用CDP触摸事件，非鼠标滚轮；320/390专家选择内外双向滚动、工作流程默认折叠及两端交接、横向分类不误切换、纵向目录滚动、抽屉关闭后操作恢复、正常与reduce-motion动画、平板拖拽取消及宽度刷新恢复。
- 第一轮3项失败经最小HTML对照证实来自测试中途强制改scrollTop的输入顺序。保留失败证据；改用实际连续触摸，三个路径通过。没有因此改写产品滚动实现。
- 已查看专家/流程截图、抽屉/流程录屏抽帧；未见本轮引入字体、色彩、布局更改（产品文件未变）。该证据不能证明真机帧率或Safari表现。
- WebKit已下载，但Arch主机缺libicu74/libxml2兼容运行库；未用不兼容库软链接冒充修复。无手机可连接，真机与Safari保持未验收。
