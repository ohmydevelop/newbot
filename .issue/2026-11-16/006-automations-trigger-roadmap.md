# AUTO-5 其他触发器接入路线图（规划，未上线）

## 目标与现有边界
沿用Grok实测“添加触发器→搜索选择→单行概要→按需设置”流程。已有时间触发（小时/日/周/月/年）不变；新增事件触发必须有真实事件来源、授权、验证和可追踪运行记录。MCP工具可调用不等于自动具备事件订阅；现有插件OAuth不能直接冒充Gmail/Outlook订阅授权。
2026-11-17查阅官方文档；Grok可观察事件类型见AUTO-2证据，不声称其服务端实现已知。

## 优先级与产品交互
|阶段|交付|用户设置|依赖与发布门槛|
|---|---|---|---|
|1|通用Webhook|添加触发器→Webhook→生成地址/密钥→测试事件；保存后紧凑显示来源和最近收到时间|稳定可达HTTPS入口、签名及事件ID、限流/请求体上限；本地真实HTTP发送与重启测试通过后才开放|
|2|GitHub PR/Issue事件|选择已授权仓库、事件和动作（例如PR打开/更新）；显示连接状态|优先GitHub App安装权限；使用实际webhook，不用轮询冒充；测试仓库验收签名/权限撤回/重投|
|3|Gmail / Outlook新邮件|选择邮箱→发件人/收件人/主题过滤；默认仅必要字段进入任务|各自OAuth、订阅创建/续期和历史补偿；SMTP发送配置只负责发信，不提供收件授权|
|4|Linear、行情等|相同来源/条件/状态组件|逐项验证官方API、授权与数据许可；行情不能仅凭未接数据源的价格输入框宣布完成|

推荐先实现1+2，让邮件和后续来源复用事件接收/去重/恢复机制。此为实现顺序建议，未在本轮添加不可用按钮。

## 共用后端与不变量
- 保留单Server与SQLite，不新建第二Agent或调度引擎。增加事件收件箱，使用`来源实例 + 上游eventId`唯一约束；签名认证在入库前，先可靠保存再响应上游，执行由后台队列接管。
- 事件指向任务/触发器revision与不可变配置快照。任务编辑、暂停、删除后，旧订阅/旧请求不能重新激活任务；密钥轮换显式记录版本。
- 同一来源事件对同一任务只产生一次有效派发。上游重投、进程重启、并发worker、网络重试不得复制运行；结果未知仍采用现有unknown/手动确认，不自动重做外部动作。
- 时间触发当前积压合并策略不能无条件套用于事件：默认逐事件FIFO、不重叠；队列上限与超量状态明确。只有显式选择“合并短时间同类事件”才可合并。
- 事件数据作为不可信输入，不能覆盖系统指令或授予插件/主机权限。正文/附件按用户选择加载；认证头、密钥和OAuth令牌不进入普通事件日志或模型上下文。
- 共用现有submitRun、Chat/Plan/Work、插件/技能/专家绑定、审批、取消、独立会话、邮件outbox；运行记录增加“触发来源/事件时间/接收状态”以解释为什么执行。
- 验签使用上游原始请求字节，常量时间比对；不由模型做鉴权判断。通用Webhook需明确签名格式、时间窗口、稳定事件ID与重投约定，不能仅把秘密放URL。

## 官方约束依据
- GitHub要求校验`X-Hub-Signature-256`；应使用`X-GitHub-Delivery`识别投递，重投保留该ID，因此适合作为幂等键的一部分。[签名校验](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries)、[投递实践](https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks)。
- Gmail推送依赖Cloud Pub/Sub与`watch`；需要续订并用`historyId`读取变化，不能只把收到推送当成完整新邮件。[Gmail Push](https://developers.google.com/workspace/gmail/api/guides/push)。
- Microsoft Graph需完成Webhook验证与订阅管理；通知接收应快速返回，续期和生命周期事件还需恢复/补偿路径。[Webhook接收](https://learn.microsoft.com/en-us/graph/change-notifications-delivery-webhooks)、[订阅生命周期](https://learn.microsoft.com/en-us/graph/change-notifications-lifecycle-events)。
- 当前Cloudflare临时分享地址会变化；第三方Webhook回调和订阅必须绑定稳定地址，或者在入口变化后显式重新登记，不能沿用失效地址假装已连接。

## 阶段1最低验收清单
1. 正确签名接收、错误/过期签名拒绝、体积/速率上限、密钥不入日志。
2. 相同事件串行/并发重投、保存后崩溃重启都只创建一个运行；唯一键覆盖任务/触发器归属。
3. 编辑/暂停/删除与在途事件竞争；运行中事件排队、不重叠；取消只取消目标运行。
4. 服务/模型不可用、权限拒绝、事件负载缺失时记录真实失败且可恢复。
5. 320/390/768/1280、浅深色、弹层/焦点/返回；来源与条件长文本省略，关键状态不被颜色替代。
6. 本地发送器→真实HTTP接收→真实Agent→运行记录→通知；最后测试仓库/真实邮箱分别验收，模拟证据不能替代上游兼容性。
