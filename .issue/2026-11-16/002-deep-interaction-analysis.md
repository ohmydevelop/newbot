# Issue 002：深层交互调查结论

调查日期：2026-11-16。本轮仅分析；没有修改产品代码、保存配置、调用业务工具或发布版本。

## 1. 用户目标与结论

用户要保留旧版的聊天与插件能力，让连接器、技能、专家、模型遵循一套可预测的操作方式，并保持 Grok 的简洁、清晰和连续感。不是把每个按钮换成图标，也不是删除所有标题。应当成立的约定是：

1. 同类目录具有相同的搜索、添加、状态、更多操作和返回模式。
2. 主行中的名称、状态和操作对齐；说明是一行辅助信息，不能改变操作位置。
3. 操作区域不随正文加载、说明/源码切换而跳动。
4. 详情主内容由详情滚动容器承担；真正需要的小选择窗保留内部滚动，到边缘交给外层。
5. 可见名称始终代表同一个对象；机器 ID 只承担引用和执行职责。
6. 表单填入值后仍能识别字段意义。简洁应减少重复说明，而不是删除必要标签。

本轮确认五组问题仍存在：表单可见标签缺失、目录状态/菜单错位、技能详情操作不稳定且目录缺少更多菜单、工具详情受旧卡片高度限制、专家成员显示内部 ID。统一加号是合理的产品调整；模型搜索当前已具备；专家选择窗的桌面上下滚动衔接当前通过，不能继续按未修复问题处理。

## 3. 逐项因果链

### 002-A 专家成员窗口的滚动

**当前桌面未复现；手机待验证。** `.expert-member-picker` 当前是 `max-height:min(34vh,300px)`、`overflow-y:auto`、`overscroll-behavior:auto`（web/styles.css:5038）。父级 `.plugin-center-content` 也是可滚动且允许衔接。

实测滚动：内部可滚动范围 406px，外层 352px。内部从底部滚到顶部时外层保持 352；继续向上，内部保持 0，外层从 352 到 208。反方向：内部到 406 时外层保持 216，继续向下，外层从 216 到 352。见 expert-scroll-top-chain.json、expert-scroll-bottom-chain.json。

这证实桌面滚轮路径符合预期，但不证明所有浏览器会把单次长手势的剩余动量交给父级。原问题发生版本、设备和手势未确定，不能断言原反馈无效。也不能为修复它全局删除 overscroll 隔离：外层弹窗仍应阻止背景聊天滚动。

关联：导入技能 `.import-skills` 使用 `overscroll-behavior:contain`（styles.css:5337），属于相同嵌套滚动风险，有代码证据、尚未实测。聊天工作流程上一轮有独立回归，但不是专家选择器的验收证据。

### 002-B 必要字段标签被当成冗余说明隐藏

**已复现。** ConnectorEditor.tsx:168–219 与 GatewayEditor.tsx:217–249 把名称/地址等标签置为 sr-only。辅助技术可以读到标签，但视觉用户输入内容后只能看到值。线上模型创建表单的标签实际为 1×1px，clip-path 为 inset(50%)，不是颜色太浅造成的错觉。证据 newbot-form-styles.json。

Grok 当前 Add MCP Server 保留 Name、Server URL、Headers 可见标签，与用户 image-1 的意图一致。名称和地址应恢复短标签，placeholder 只给示例；不需要再加重复说明段落。专家表单本来就有名称、简介、提示词标签，应成为一致性参照。

关联：独立 MCP、模型网关同机制；插件配置和私密字段组件需逐字段检查，不应批量把所有 sr-only 都取消。图标按钮的辅助名称、搜索框的隐藏标签不是同一问题。

### 002-C 添加操作的统一

**产品改进建议，现状已确认。** 连接器/技能是文字加下拉箭头；专家与模型是文字直接创建按钮。四者通过 CatalogToolbar 共享位置，却没有共享添加语义组件，因此样式相同不等于操作契约相同。

建议目录工具栏统一加号，accessible name 分别为“添加连接器/技能/专家/模型连接”，焦点与悬停提供简短提示。只有一个创建路径的直接进入；有多个路径的打开相同风格菜单。保留 aria-haspopup/expanded、键盘操作和触屏可点区域。菜单项目仍用文字说明具体动作。

不能简单 lint 禁止 `.catalog-add` 的文字：CatalogNavigation.tsx:131 的“在聊天中使用”和商店条目的“添加”也复用了这个类，但不是目录新建入口。先分离目录添加组件和主操作组件，再约束使用边界。

Grok 本轮 Skills 仍显示文字 New Skill，Connect Apps 中有 Add a custom connector。因此“全部改 +”是 Newbot 的明确设计选择，不能冒充 Grok 所有地方本来都如此。

### 002-D 状态和更多操作不在一条基线上

**已复现且根因确认。** Sentry、Slack、GitHub、cloudwalker 有说明时，菜单中心均比状态中心低 10px；无说明的 newbot_test、hids 差值为 0。证据 row-alignment.json。

CatalogCopy.tsx 将名称和状态放在 `.catalog-title-line`，说明放在下一行；外侧 `.catalog-entry` 却用 `align-items:center` 对整个两行块和更多按钮居中（styles.css:4218）。二者对齐的是不同参照物，因此描述出现后必然偏移。不是某个插件描述文本特殊。

应由共享目录行布局统一主行、描述行与操作槽。名称、状态、更多按钮处于同一主行；描述独占下一行并省略。保留主体点击与更多按钮为独立可访问目标，不能把按钮嵌套进另一个按钮。不要通过固定 translateY(-10px) 掩盖问题。

关联：模型默认状态也复用 CatalogCopy 与外层 catalog-entry，有代码证据；专家不可用状态同理。技能目前缺更多按钮，需补齐行行为后一起验收。不同业务的“已启用”“已连接”“默认”不能强行改成同一个状态词。

### 002-E 技能详情与目录不一致、操作跳动

**已复现。** SkillsSettings.tsx:115 的 SkillReader 后面依次渲染 CatalogUse 和 controls；plugins.css:232–239 将 reader 改成自然高度、正文 overflow:visible。说明与源码高度不同，后继操作自然被推走。

真实技能 ff：说明模式正文高度 156.078px，“在聊天中使用” y=425.078；源码模式正文高度 270.531px，按钮 y=539.531，整体下移 114.453px。停用/卸载也同幅移动。证据 skill-layout-shift.json。用动画平滑这个移动不会恢复操作位置稳定的约定。

建议在技能详情标题区提供“在聊天中使用”主操作和更多菜单；说明/源码采用紧凑、稳定的查看模式切换区。主行不参与正文高度变化；手机不足一行时采用预先定义的第二行，不能根据正文临时换行。停用/卸载进入更多菜单，卸载保留确认。不要为固定按钮又新增一个被困住的正文滚动窗。

技能目录当前只有说明入口和已启用状态，没有更多菜单；SkillsSettings 的 readable=true 分支可直接确认，浏览器也一致。Grok 个人技能行已有更多菜单（Edit/Share/Download/Disable/Delete），支持在目录层处理管理动作。Newbot 应提供自己实际支持的详情、启用/停用、卸载，不为“对齐”虚构分享等能力。

关联：插件技能详情、聊天历史技能引用都复用 SkillReader；它们有不同权限和动作集合，不应因共享头部出现卸载历史引用等错误操作。专家详情 CatalogUse 同样放在可变正文后面，是操作锚点的同类风险；是否调整需在统一详情规则中决定。

### 002-F 工具列表被旧卡片样式困在小框里

**已复现且根因确认。** 线上 hids 有 125 个工具，`.connection-tools` 自身高 4965px、overflow:visible；真正困住内容的是外层 `.provider-row.mcp-row`，clientHeight=224、scrollHeight=5119、overflow-y:auto。证据 tools-layout.json。

McpSettings.tsx:357–387 在 CatalogDetail 内继续使用旧 `.provider-row.mcp-row`。styles.css:4077 的 `.mcp-row:not(:has(details[open]))` 固定高 224px（窄屏244px）；4447 的详情覆写虽然写了 height:auto，却因前者包含 details[open] 的选择器权重更高而失败。详情覆写同时保留 overflow:auto。这是旧卡片与新详情职责混用及 CSS 权重冲突，不能只给工具列表改高度。

建议详情正文停止继承旧卡片高度/滚动语义，工具列表使用详情主滚动容器；工具名与说明按信息层级呈现，长目录可提供局部搜索。不要用 !important 再叠一层补丁，也不应删除所有工具分隔线来冒充修复。

关联：ToolsSettings.tsx:449 的部分插件工具入口也复用 McpSettings，因此会共享风险；PluginComponents 的原生插件连接配置是另一条实现，需要分别核对，不能宣称全都同因。

### 002-G 模型搜索

**当前版本已具备，非本轮待修缺陷。** 公网“模型”目录有“搜索模型”。输入不存在项出现“没有匹配的模型或连接”，清空后恢复百智-MQ、默认状态与25个模型。证据 models-search.txt。

### 002-H 专家选择连接器时显示内部 ID

**已复现且数据流根因确认。** 同一 hids 连接器在目录中可正常显示，但专家创建框显示 connector_b0ed7a772c8e45e58edcde12cdc04a65。服务端 configuration.ts:227 已从 connectorNames 返回显示名称；experts.ts:123–126 再次组装目录时却显式 `name: c.id`，丢弃正确的 name。前端按 m.name 显示，问题不在文本截断。

修复应复用配置公开视图的显示名，ID 保持稳定。专家详情 ExpertMembersView 同样消费 expert/list，会一起受影响；experts.ts:89–93 的停用/移除提示也直接显示 ID，应区分可解析名称与确实丢失的成员。

兼容约束：不能把历史 connectorIds、工具路由、OAuth、证书/凭证关联键改成显示名；显示名可能重复、可修改。已移除对象保留明确不可用状态，需要诊断时再展示 ID，不能给失效对象伪造正常名称。expertContextText 中用于实际工具引用的 ID 不应未经协议核对就替换。

## 4. 本轮 Grok 对照：事实与建议分开

只读观察页面为 https://grok.com/?_s=connectors 与 https://grok.com/?_s=skills，证据 grok-add-mcp.jpg、grok-skill-menu.jpg、grok-edit-skill.jpg、grok-form-styles.json。没有提交表单、改账号、保存技能或发送消息。

已确认的设计：

- 目录到详情保持设置容器、分类导航和面包屑上下文，不叠加新的应用层级。
- MCP 创建保留短字段标签；说明只解释用户需要知道的用途。用户截图中的“标题”对应 Headers，不宜照抄错误翻译，应称请求头。
- 个人技能在目录中有更多菜单；编辑页名称、简介、指令各有清楚标签，主次动作集中。
- 所观察 MCP 字段为14px、字重425；标签14px、525；详情标题17px、525。字体为 X-VF 系列及系统回退，主体字色约为 srgb(0.902,0.898,0.890)，标签为同色约64.7%透明度；输入底色 rgb(25,25,25)、圆角10px，普通边界为约14%白色。聚焦输入边框蓝色。
- 对比 Newbot 同类模型字段：14px/400，Noto与CJK回退，正文 #fcfcfc，底色 #131211，边框 #2d2c2a，圆角10px。差异集中在字体度量/字重、亮度层级与表面关系，不能靠一个“圆角相同”判定视觉对齐。

建议遵循层级、密度和状态的关系，不直接复制专有字体文件，不把拉丁字体425/525机械套到中文。应在实际中文名称、长英文、暗/亮主题下调整语义 token 与字体回退，核对字符边界、行高和阅读清晰度。

本轮没有采集 Grok 的逐帧动效或手机触控惯性，因此没有证明动画时长、缓动、边缘惯性“完全一致”。已测得的114px布局跳动与滚动容器错误应优先消除；之后在同一固定参考状态下比较进入、返回、切换和失败恢复。保留原100/180/300ms基线，未经对照不要凭“更丝滑”另加动画。

## 6. 为什么已有 lint 和验收没挡住

现有检查有价值，但覆盖的是特定约定，不是整套体验证明：

- scripts/check-design-ownership.mjs 主要禁止旧设置布局选择器回流，并锁定内容宽度和三档动效时长；不会分析 `.mcp-row:not(:has(...))` 的权重，也不会发现固定高详情。
- eslint.config 的文件范围列举了 Settings、CatalogToolbar、ProviderSettings、GatewayEditor 等，没有覆盖 SkillsSettings、ExpertsSettings、ToolsSettings、ConnectorEditor。即使扩范围，现有规则也没有规定添加操作槽和可见表单标签。
- settings-contracts.spec.ts 的几何断言针对顶栏；像素基线最终采集空专家目录。它不会证明有说明/状态/更多按钮的行对齐，也不会触及长技能和125工具详情。
- 上一轮 interaction-acceptance 对工作流程滚动与模型/MCP配置表单有覆盖，未覆盖技能正文模式切换后的按钮锚点、专家目录的ID/name转换。

因此不应把问题简单归因于AI没读文档。需要把可执行约束落在正确层次，并用故障注入证明测试确实能挡住旧问题：

|层次|新增检查|故障注入/失败标准|
|---|---|---|
|组件与ESLint|目录添加只能使用共享添加组件，图标按钮有名称；持久字段使用可见标签组件；限制目录详情继承旧卡片类|在任一目录重放旧按钮/隐藏关键label/旧卡片类，应报错；保留搜索、辅助名称和明确语义例外|
