# AUTO-2 登录态 Grok 自动任务对齐

## 用户目标、范围与约定
2026-11-16 用户要求在真实 Grok 可访问后继续实现尽可能对齐。延续 AUTO-1 已发布功能与 Newbot 温黑/中性浅色设计；入口仍为新建聊天下面，不把新的 Grok 导航改版强加给整个聊天系统。
预期：从目录发现任务、在连续面板内配置触发器/指令/通知、保存后查看状态和运行记录；高级选项按需展开，返回保留目录位置和搜索，取消不创建任务。一次保存/执行只生效一次，已有任务不因UI调整失去配置。

## 事实与根因
- 普通 Chrome 已登录，可读取 /automations；Craft 独立浏览器403不代表真实网站不可访问。只操作未保存草稿，不保存Grok任务、不触发执行、不读私人聊天。
- 实测 Grok：设置容器内紧凑目录、搜索、横向类别、按类别双列轻量模板行；32px图标、名称/单行省略说明、右侧添加。详情/编辑在同一容器逐级导航。
- 实测编辑：图标+名称、Triggers、指令框（底部附件/连接器/技能/模式）、通知，固定底部取消/保存；触发器先选择种类，再一行配置，Hours弹层可全天/时间窗口。真实类型比官方宣传更丰富：Hourly、Gmail/Outlook收件、GitHub/Linear事件、Finance、Webhook。
- 当前 Newbot：3个模板仅空列表出现，大标题/重复标题、全宽虚线添加、表单日期时区全部展开，独立二级Modal；根因是基于官方演示的结构推断而非登录界面的证据。需修正组件层级与信息密度，不能靠局部字号补丁。
- 尚未观察：Grok已保存任务概览/运行历史（账号无已存任务，未授权创建）；不把官方说明当实时运行证据。

## 实施顺序
1. 保存不含私人侧栏内容的登录态目录/草稿/手机截图与测量。
2. 增加有约束的任务图标、小时频率/窗口；补边界单元测试，保持老配置兼容。
3. 目录分类/模板、紧凑行、单区域编辑/返回、统一控件与固定操作区；只改自动任务表面，不重置全局字体/导航/设置。
4. 更新回归使其验证新用户路径而非旧DOM；真实浏览器桌面/触摸、运行历史/持久化、关联滚动验证；独立设计审查。
5. 记录验证与差距，提交推送、备份部署；核对公网产物与任务页面。实测有回归则先修再发布。
