# UI15：真实 OAuth 与手机交互补充验收

用户授权继续补齐UI14未验证项，重点为真实OAuth登录和手机滚动、拖拽、动画，并保持已有Grok视觉/心智模型。起点8d2db4c；生产产品46c9672。不覆盖002原始反馈与UI14结论。

## 问题、预期与不变量
- UI15-O：前轮只验收OAuth选项和协议单测，未完成第三方账号授权。一次授权须绑定同一连接器/attempt；成功回跳后能发现授权工具，取消/拒绝可重试，过期回调不得成功，凭证不进入聊天/证据；独立MCP与插件MCP共用完成机制。
- UI15-M：前轮主要是桌面Chromium滚轮和尺寸模拟。触屏纵向滑动不能被横向控制/拖拽吃掉；内滚动到边缘可继续外层；抽屉关闭后背景可操作；触控取消释放捕获；动画不闪跳，reduce motion有效。
- UI15-R：插件技能/历史技能只读入口仅代码核查，需补浏览器实际读取、源码切换与返回，不出现错误管理权限。

## 顺序与范围
1. 核对运行版本、设备与OAuth入口；需要用户账号/设备信息时早问，同时继续独立验证。
2. 对照已有Grok证据及当前可访问页面，执行手机触摸/动画、真实OAuth可达链路；保存脱敏截图、帧时序和结果。
3. 证实缺陷后先追加原因与同机制范围，再改产品代码和回归用例；不凭假设重写界面，不改变权限或TLS策略。
4. 若修复，执行相应检查、构建版本校验并部署原实例；若只补验收则不为制造发布重启生产。保留账号配置，测试新增配置必须明确命名并记录清理。

## 验收证据与完成界限
OAuth须区分元数据发现、打开真实登录页、用户批准、回跳/工具发现、刷新恢复；只有完成实测的一段可标通过。涉及新敏感权限最终授权由账号持有人确认。不索取聊天中明文密码或验证码。
手机至少覆盖390及320宽度、真实touch输入序列、正常/减弱动画、滚动两端与取消；录屏/截图人工检查。真实设备无法接入时保留待验收条目及具体接入条件。
计划/进度在原issue目录，证据evidence-ui15/。当前：调查中，尚无产品改动。

- 首轮三例失败：手势滚动后由测试写 `scrollTop=0`，下一次反向触摸没有带动父容器。事件未被 preventDefault；完整祖先链没有内层 overscroll contain。
- 同一输入顺序在无框架的最小嵌套 HTML 中复现；连续用触摸到达边缘则正常。不能据此认定 Newbot 滚动机制有缺陷，也不能加人工滚动补丁绕开浏览器。
- 修正验收路径：只有初始排列使用程序定位；中途用连续 touchStart/touchMove/touchEnd 到达两端，再检查下一手势改变外层位置。专家320/390、聊天工作流程三例均通过（mobile-natural.txt）。
- 范围改为新增可复现验收工具及 CI 入口，不修改产品 CSS/组件/权限实现，不触发无必要生产重启。
- UI15-R 历史技能：`SkillReferences.tsx` 当前没有调用方，无法当成在线可达入口验收；不凭空添加已被隐藏的消息元数据入口。插件技能读取仍通过真实设置页面补验。
