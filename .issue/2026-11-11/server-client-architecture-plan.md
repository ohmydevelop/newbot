# Server + Runner 实施计划

关联调查：server-client-architecture-analysis.md。日期：2026-11-11。用户已授权连续实施；从隔离P0探针开始，证据通过后进入下一阶段。继续固定已有内核基线，不立即替换当前服务或移动数据。

## 范围

首期一个 Server + 一个 Runner；支持同机与分机，节点丢失后配置/插件重建以及最后确认检查点的会话冷恢复；全局上传大小可设无限制、附件进入会话工作区。既有会话、凭证、插件归属、App、热更新均保持。多节点自动调度、多租户、活进程迁移、任意插件私有数据库自动备份、生产上线验收不在首期。

## P0：契约与可恢复性探针

对应 SC-01/02/03/06/07/08。建立 Server/Runner 配置所有权、身份/修订、逻辑路径、插件版本/记忆scope清单，核对上游远程执行是否已覆盖全部工具；记录单一模式 ADR。隔离内核验证原生会话 flush/export/import、身份保留、路径重绑定、App动态工具恢复。核对实际记忆开关，证明全局策略不会误读个人或跨项目数据。

验收：两个不同用户路径临时运行根中恢复同一原生 threadId、完整工具历史且不重执行；如上游接口不足，仅增加最小原生补丁并生成协议。不得新建线程冒充完成。没有可验证的检查点前不宣称主机可丢弃。

## P1：先抽取本地 Runner 边界

对应 SC-01/08。定义白名单 RunnerTransport（命令ID、会话归属、修订、事件序号和回执）；将目前 Codex 子进程、文件/扩展物化、私密执行放入本地 Runner。Server 保留SQLite权威配置、操作结果及授权。保持原 HTTP/AG-UI 和 UI 兼容，先通过本地 transport 验证，不一次同时改网络、路径和数据格式。

验收：原有热切换、插件引用、审批、错误、附件、App稳定挂载和断线恢复回归；依赖配置不再由两个进程分别判断或保存。

## P2：目录与逻辑资源身份

对应 SC-03/05/07。引入 path service 和 workspaceId/fileId/digest；Server ~/.newbot/server，Runner ~/.newbot/client、codex、runtime-home、resources、state，工作区 ~/Newbot/workspaces。独立技能优先由原生显式root读取，兼容旧 .agents/skills 项目入口。原生全局记忆保持原格式，作用域未验证前不自动扩展启用范围。

迁移：只读清单→版本/空间检查→备份→停止相关写入→复制到stage→hash核对→原生结构化重绑定/导入→原子发布→恢复验证。保留旧目录回退，不合并个人目录、不在运行时批量mv、不替换历史文字。SQLite 从实施时实际 schema（当前v16）增量迁移，不复用其他轮次预定版本号。

验收：旧线程、新线程、旧附件URL/快照、引用技能与插件、不同路径恢复一致；迁移中断可回退，宿主个人Home摘要不变。

## P3：单节点远程连接与允许配置同步

对应 SC-01/02/08。实现注册、节点身份、TLS出站连接、版本协商、能力上报、heartbeat、唯一租约/epoch、幂等命令和持久outbox。Server投影允许配置/资源清单，Runner校验后原子采用；凭证独立短时注入。保留本地transport用于测试，产品仅一套语义。

验收：同机/分机1+1真实连接，断网、重连、迟到确认、丢回执不重复执行；同一会话竞争执行被拒绝；节点撤销后不能领新任务；在途外部结果未知不自动重放。

## P4：扩展全生命周期与新节点重建

对应 SC-02/07。Server保存包而非仅源码URL；节点内容寻址下载，原生激活清单绑定版本。插件内部技能/MCP/钩子统一管理；独立技能配置保持已有语义。升级不覆盖运行资源，卸载和紧急撤销分离；本地依赖检查明确缺什么。回收保护任务/App/检查点引用；插件可变数据不进入包目录。

验收：长任务升级、运行中卸载、移除引用、禁用技能、App旁路、恢复旧版本；删除临时Runner后重新安装，在源仓库离线时仍能恢复已存插件和允许配置。此删除仅在专用测试目录，不删除用户当前Client。

## P5：会话文件与全局上传策略

对应 SC-04/05。Server SQLite maxFileBytes=null 表示无产品上限；独立总量与并发策略、修订和跨会话能力发布。替换Buffer整包上传为分块、续传、增量校验、原子完成；先服务端持久，再工作区就绪。新聊天先建立draft/workspace身份；大文件Agent输入改资源引用/按需读取。历史原件与可写工作副本分离。

验收：小上限拒绝、调大/不限后所有会话生效；受控大文件/低内存测试；断点重试、重复完成、空文件、同名文件、磁盘满、跨会话越权、草稿切换/过期；通过当前公网代理分块上传，附件历史/下载正常。预览和模型不支持不能误报成上传失败；安装包限制仍独立。

## P6：恢复检查点与替换主机演练

对应 SC-01/03/06/07。关联原生恢复包、文件版本、插件版本、允许记忆、App/审批/回执与同步游标。对象先上传，最后事务发布checkpoint。任务完成触发，主动同步可用；Server读取已同步历史而不依赖在线Runner。原生SQLite不普通文件实时复制。

验收：A节点完成任务并同步→销毁测试A→全新B重新注册→恢复同一线程、上传原件、产物、插件配置/版本并续聊。覆盖A死亡在上传中/工具执行中/回执前，区分已确认、未同步、未知副作用。设备OAuth与临时凭证不越权复活；检查点损坏/版本不兼容明确失败并保留原数据。记忆按scope恢复，不跨项目混入。

## P7：交互收敛、文档与兼容回归

首期默认自动用唯一节点；节点详情提供在线、版本、同步、缺失依赖及恢复入口。插件设置不拆散组件，技术字段收进诊断；文件显示上传/同步/可用。更新过时架构和运行隔离文档。

验收：桌面/手机、深浅主题、键盘，慢网/离线/失败不丢草稿；类型检查、构建及相关测试通过。只将有证据的条目标完成；模拟上游与真实1+1网络分别记录，正式部署验收另排。

## 执行约束

阶段依赖P0→P1→P2→P3→P4→P5→P6→P7。每阶段实施→验证→修正→更新进度，授权后不逐阶段反复确认。若原生冷恢复证明无法保持身份/工具契约，P0记录阻塞并调整设计，不先迁走用户数据。每阶段证据位于同目录 evidence-server-client/，不覆盖已有issue原文/截图。

当前状态：P0核心恢复门槛已通过（9项真实内核检查，包含分页历史与工作区迁移）；P1本地进程/文件/资源边界、持久控制基础及P2路径前置项已验证；P3-A独立节点TLS链路已验证。P2完整目录迁移、P3允许资源/配置同步与主Bridge适配、P4–P7仍待实施。详见进度与证据。不能把本地模块抽取称为Server/Runner远程拆分完成，也不能把工作区迁移工具称为整机恢复完成。

### P1/P2 细化（实施调查）

- SC-03：普通及分页历史均已通过原生冷恢复；format 1 明确拒绝需要其他线程的 history_base/fork 依赖，不能只复制叶子文件。当前33条原生历史未发现此类依赖；账号作用域仍由原生验证，不删除账号字段。
- SC-08：同一Server数据库缺少进程级独占，迁移停写不能仅依赖“当前没有任务”。增加Linux进程锁与正常关闭标记；崩溃后可重新启动，但未经正常关闭不能迁移。验证双启动、迁移竞争、失败恢复。
- SC-02/07：`privateFieldBinding` 将插件物理command/args/cwd/env路径纳入凭证接收方摘要（有代码证据），同包换目录会失效。先使经包摘要验证的插件使用逻辑资源路径参与绑定；旧绑定仅在原接收方完全匹配时转封装，目录迁移不能借此修改真实URL/用户参数或包摘要。验证相同包跨目录、改URL/参数/包拒绝、旧密文转换与重启。
- P2标准目录解析已经接入，新安装可采用标准路径；旧实例自动保留旧布局，显式切空白Home拒绝。尚未迁移用户数据。完整迁移仍需资源身份、凭证及工作区关联验证，不将目录解析当成迁移完成。

## 本轮 P1-C / P3-A：持久控制与节点连接

前置核对：现有RunStore只保护Web提交，LocalRunnerTransport只有进程内RPC编号；不能将它当成断线后的命令回执（有代码证据）。原生调用已发出但响应丢失时，必须保留未知结果，而不是用新RPC编号重发。服务端配置修订、节点代次、作用域和消息游标均需进入网络边界。

不变量与关联风险：
- RC-01：同一命令ID只能对应同一内容，重复投递不重复执行；覆盖开始任务、App工具调用、审批回复和参数更新。原生调用与SQLite不能组成分布式事务，因此发出窗口崩溃标记unknown，不宣称外部副作用恰好一次。
- RC-02：只接受当前节点代次和已分配作用域，过期修订不能启动新操作；已经发出的操作结果仍属于原命令，不能回写新配置。覆盖断线、旧节点重连、撤销、并发更新。
- RC-03：回执/事件先持久化再确认。接收序号连续、重复包内容一致；断线后重发相同事件，不丢失或跳过。节点本地崩溃后，dispatching转unknown；未发出的accepted命令可明确识别。
- RC-04：传输缓冲不成为明文凭证库。普通缓冲加密，专用临时命令正文只在内存持有，Server重启后不可执行旧临时授权。节点令牌仅存摘要于Server，不能使用Web Cookie替代节点认证。CLI配置不包含个人Codex环境。
- RC-05：租约过期时拒绝新命令并停止受管运行时，不把进程退出等同于外部副作用回滚。网络断线与浏览器断线分开处理。未知操作不自动在新节点重放。

实施顺序：类型/白名单与持久账本→故障/重启/重复验证→Server节点控制及鉴权路由→Runner出站连接、心跳、回执重传与独立入口→独立进程和真实内核探针。新链路先在隔离实例启用；原Web Bridge继续本地适配器，完成文件/资源/授权通道前不配置为远程生产运行。

接口采用有限的节点connect/exchange，浏览器仅允许登记/查看/撤销节点，不提供任意原生RPC接口。Server SQLite从实际v16增加控制元数据；Runner独立state库不共享Server或Codex的SQLite。参数与响应为短期传输数据，不复制完整会话历史。

验收：重复命令、冲突ID、丢响应、派发窗口崩溃、旧epoch、旧revision、撤销、断网重连、重复/缺号事件、私密正文重启失效、非法Origin/节点令牌/URL、独立网络进程。证据分开记录模拟执行器与真实Codex；两进程同机网络测试不冒充两台物理主机验收。本轮不提前移动现有服务或删除任何用户Client。

### P1-C / P3-A 本轮状态

持久命令/回执、节点独立认证、出站TLS、工作区归属/修订、租约与停止确认、独立Runner入口已实现并验证，证据见 `evidence-runner-control/` 和同目录progress本轮章节。主服务仍保留本地链路，不进行未经资源/恢复验证的接管。

发现的共同风险已同步处理：迟到unknown覆盖完成结果（已复现/测试）、丢命令响应和丢事件确认造成重发（真实TCP测试）、启动未完成时先释放租约（隔离时序测试）、临时配置重启失效（存储测试）、节点令牌被用于Web管理（实际主服务路由测试）、未停机即转交工作区（测试）。分机实测、完整资源同步、未知故障机器的人工恢复及事件库回收仍待后续阶段，不将其计为完成。

补充RC-05（代码证据）：Node宿主SIGKILL时无法执行finally；detached原生进程组可能仍存活。仅等待Server租约超时后允许不同bootId启动，会留下同节点重复执行风险。本阶段先fail-closed：独立Runner使用严格正常停止标记，非正常退出拒绝自动启动；Server不同bootId也要求旧节点确认停止，不能仅依赖lease_until。后续P6提供核验旧执行环境终止后的显式恢复，或以原生父进程死亡/cgroup监督完善自动恢复。此限制不改变现有本地Server的重启行为。
