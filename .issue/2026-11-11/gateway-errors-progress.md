# 网关错误修复进度

已读取两张截图、AGENTS、错误投影/事件/前端与原生切换守卫源码。确认存在三层错误原因丢弃及错误按钮语义混用，详见计划。保留上一轮未提交修改，不覆盖。

## S1 已实施

- 新增共用安全错误分类：余额、额度、限流、认证、权限、上下文、模型、上游服务、请求格式、TLS、连接及未知。只发固定文案、建议、白名单原生类型和 HTTP 状态；不回传上游 URL、header、正文或任意错误码。
- 实时通知（包括自动重试）、最终失败、历史投影与 RPC 失败接入；缺少终态原因时保留前一个已识别诊断。安全摘要按会话/任务保存在既有 SQLite metadata，成功/中断清理，重启补回失败历史。
- 前端就近展示原因与处理方式，任务/会话编号及协议状态按需展开。模型切换拒绝区分当前/目标；目录刷新不再作为切换失败的“重试”。推理面板同步显示设置错误。
- 查阅最近 8 个实例 rollout 文件未找到可提取的原生 error 事件，不能从现有记录独立确认用户当时欠费响应的具体代码。用户确认欠费作为反馈事实，代码丢弃原因作为已证实根因；不虚构历史响应。
- 针对测试已覆盖分类不混淆、无敏感内容、自动重试与完成清理、历史一致性、数据库重开与跨任务隔离、切换守卫文案。进入真实浏览器补验；接收方为隔离替身。

## S2 浏览器与同类入口

- 1440px 桌面与 390px 手机：余额原因与处理建议直接可见；诊断详情含 HTTP 403 和任务编号，原始示例 Bearer/URL 不出现。重新读取、刷新后原因不变；限流自动重试明确显示“正在自动重试”，任务保持运行。截图 `billing-desktop.png`、`billing-mobile.png`。
- 手机运行中选择另一个模型：说明缺的是当前任务模型的能力资料，并提示结束或停止后再选；原模型仍选中。刷新目录不清掉切换失败、不假装已经重新切换；见 `switch-mobile.png`。这一步使用明确的隔离拒绝响应，不称为真实网关跨 Provider 验证。
- 查到网关目录/连接测试也丢失错误正文，已接入有大小限制的 JSON 错误分类；HTML、超大或损坏响应只使用 HTTP 状态，不展示原文。目录层只保留受信的 PublicError，网络异常仍安全处理。
- 停止自动重试时发现前端保留暂态错误，已按确认取消事件清理，并增加对应行为测试；非取消的异常中断仍保持原有恢复语义。

## S3 发布验证

- 56 项相关测试、类型检查和完整构建通过。自动化包括请求分类、历史/事件、SQLite 重开、凭证观测、运行隔离、会话设置和 Provider 诊断；不是外部付费网关的实测兼容性结论。
- 取得空闲维护锁后备份并重启服务；schema 保持 16，32 个线程、96 个请求、5 个附件保持一致。密码、凭证、个人/实例 Codex 配置、网关配置均未改变，3 个近期历史结构核对一致，未创建模型任务。详见 `evidence-gateway-errors/service/local-update.json`。

- 最终将模型请求错误与 MCP/其他原生 RPC 区分，避免把连接器认证误称为模型网关认证；未知的发起失败不提示不存在的“展开诊断”。新增测试后共 57 项通过。最后一次发布结果见 `release-result.txt` 与 `service/local-update.json`，完整构建 `final-build.txt`，公网/本地资产一致证据 `published.json`。
