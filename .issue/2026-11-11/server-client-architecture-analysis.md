# Server + Client 架构深度评估

日期：2026-11-11。状态：只读调查及设计建议，未实施迁移、未改变服务配置。用户要求评估架构简化、全局扩展/记忆、标准目录、可替换 Client、全局可调上传限制；不是本轮直接重构授权。

## 1. 结论与不变量

方案可行。建议将 Client 命名为执行节点 Runner，避免与浏览器 Web Client 混淆。Server 是控制与恢复数据的权威来源；Runner 维护本机可重建的运行副本，运行 Codex App Server、MCP 子进程及工作区工具。首先仅部署一个 Server 和一个 Runner，可同机部署不同进程，未来增加节点不改变逻辑身份。

应成立的不变量：
1. 配置只由 Server 发布，节点只能确认已应用版本或提交变更请求，不能双向覆盖权威配置。
2. 扩展全局安装不等于所有会话可执行；实际有效能力由强制执行的配置/策略交集决定，不靠模型遵守提示词。
3. 一轮绑定资源版本；安装升级不修改进行中的任务所持文件。
4. 一会话同时只有一个有效执行者；断网或节点替换不能自动重复执行有副作用的命令。
5. Client 丢失后，Server 已确认持久化的数据能够恢复；未同步数据和活跃进程不得承诺无损恢复。
6. 上传成功指 Server 已持久化；用于任务前还必须确认目标节点文件就绪。大文件不得整体载入 Bridge/浏览器内存或直接塞入模型上下文。
7. 宿主个人 ~/.codex 与 ~/.agents 不参与读取、修改和同步；路径变化不改变会话/插件/文件的逻辑身份。

## 3. 推荐职责

|职责|Server|Runner / Codex|
|---|---|---|
|登录、节点注册、授权和期望配置|权威保存与校验|验证下发对象、版本及本机约束|
|模型/插件/专家选择|保存用户意图、修订|按原生接口实际应用并确认|
|插件包和独立技能|保存不可变包、来源、摘要、启停及引用|下载验证并本地物化；按任务激活|
|推理、上下文、工具调用|转发控制/展示事件，不实现循环|Codex 唯一 Agent Loop|
|会话、文件、记忆恢复|接收已确认的原生恢复包和文件版本|本地原生格式、单写者、产生检查点|
|文件上传/下载|权限、全局限制、分块接收、持久化|会话空间物化、按需读取|
|凭证|独立加密保存、按接收方和任务发放|受信执行组件临时持有，不进入普通快照|

Server 仍可 Fastify + SQLite + 本地磁盘对象文件，无需 Redis、Postgres、消息队列或独立对象存储服务。SQLite 存元数据，插件包/大文件/原生检查点存磁盘内容寻址对象；不能把几 GB 文件塞进 SQLite 配置行。Server 自身数据及加密主钥必须有备份；Client 可替换不代表 Server 可丢弃。

Runner 主动建立经过认证的出站长连接，Server 不需要访问节点的公网端口。Browser 继续现有 HTTP + AG-UI SSE；Server↔Runner 承载白名单控制、事件序号/回执及心跳，可用一个 WSS 通道；文件通过分块 HTTPS。不是把 Codex 任意 RPC 暴露公网。

备选“Server 运行 Codex + 远程执行工具”会让历史天然集中，但必须可靠远程化 shell、文件、MCP stdio、钩子、资源路径和沙箱。仅远程 shell 不足。与用户希望节点拥有原生 Home 的目标相比，首期推荐 Runner 本地 Codex；不同时建设两套运行模式。正式实施前在 P1 比较已有上游远程能力，若完整覆盖可减少 fork，则记录 ADR 再调整。

## 4. 扩展生命周期与作用域

生命周期：来源扫描 → 校验/预览 → 发布不可变版本 → 节点下载校验 → 任务取得版本引用 → 原生激活 → 任务结束释放活动引用 → 无任务/历史App/检查点引用后回收。

- 安装、启用、当前任务激活是三种不同状态。安装一次，所有获准会话可引用同一只读包；并非所有会话都启动包内 MCP。
- 实际集合 = 全局允许 ∩ 节点兼容/允许 ∩ 会话引用 ∩ 包内启用组件。插件内技能、连接器和钩子继续归属插件，不拆成独立安装项。
- 独立技能保留“全局启用可发现”的现有语义，另支持会话明确收窄；插件默认仍明确引用/专家引用才激活。不默默改变产品语义。
- Codex 注册工具、加载技能、执行钩子必须执行此集合；Host 的 App 工具调用再次校验，避免通过 App 或隐藏的全局自动发现绕过。
- 升级准备新目录，后续任务绑定新摘要，进行中任务使用旧摘要。卸载阻止新引用，现有任务按原资源完成；紧急撤销与普通卸载区分，撤销应禁止后续调用而不是仅等待下一轮。
- 不把 MCP 实例跨会话共享作为默认优化。实例身份至少包含插件版本、连接器配置修订、凭证主体、作用域；stdio/MCP 可能有可变状态。共享只读文件安全性与共享进程不是一回事。
- 文件共用不等于强隔离。同 OS 用户/完全访问可读相邻路径，模型策略不是安全边界。需要对抗不可信插件/多用户时另配 OS sandbox/独立用户/容器；首期明确单信任域。

## 5. Home 与工作目录

建议工作区根名为 **~/Newbot/workspaces**，界面称“工作区”。不把运行文件放在源码仓库；支持安装参数覆盖但逻辑身份不随路径变化。

```text
Server（可与 Runner 同机，数据所有权独立）
~/.newbot/server/
  server.sqlite            # 配置、节点、会话索引、操作回执、授权与引用
  objects/                 # 插件包、文件快照、原生会话检查点
  secrets/                 # 加密主钥/服务器身份，独立备份
  staging/                 # 未完成上传与导入

Runner
~/.newbot/
  client/                  # 节点身份、同步游标、已应用修订和待回传回执
  codex/                   # CODEX_HOME，原生内部布局由固定版本维护
    sessions/              # 示例：原生会话记录
    plugins/               # 原生插件缓存/索引
    memories/              # 原生记忆（启用时）
    ...                    # 原生 SQLite、认证状态等，不自建同名伪格式
  runtime-home/            # 仅子进程 HOME/XDG；隔离个人目录
    .agents/skills/        # 允许的独立全局技能的受控投影
  resources/               # 下载后的不可变包，原生 local_root 指向允许版本
  state/plugins/<id>/...   # 插件可变数据；newbot约定，不宣称官方通用标准

~/Newbot/workspaces/<workspace-id>/
  uploads/<file-id>/<name> # 已确认上传文件，保留安全文件名与稳定身份
  outputs/                # Agent 产物约定位置
  ...                     # 项目文件、Git 仓库等
```

CODEX_HOME=~/.newbot/codex，子进程 HOME=~/.newbot/runtime-home；不改启动者 HOME。选择嵌套 codex/ 是为了让官方运行时文件与 newbot 控制元数据不混用，不要求上游为新目录名修改内部格式。用户要求“全局放在 ~/.newbot”因此满足；不把整个 ~/.newbot 当成可同步黑盒。

Server 保存 workspaceId、fileId、resourceDigest 和相对路径，Runner 负责本机根路径解析。官方 threadId 同样保留，但加 runner/environment 身份与恢复映射；应用 sessionId 与原生 threadId 显式映射，不能通过创建新原生线程冒充原线程恢复。跨机路径重定位只更新结构化引用，不全文替换历史中的路径文字。

## 6. 配置同步与主机替换

下发的是有版本的“此节点允许的配置视图”，不是拷贝 config.toml。Server 按字段和作用域白名单投影；普通配置进入节点缓存SQLite，Codex 线程/任务参数读取内存快照。磁盘文件只用于原生确需的资源、索引、认证或最小受管启动配置，仍不将它作为用户配置事实来源。

节点上报 desiredRevision / appliedRevision / 实际任务采用修订、资源摘要和原生能力；不能把下载成功当成生效。节点本地路径和可执行程序存在性属于节点事实，不回写成全局绝对路径。下发 URL/stdio 命令要受注册节点的允许策略约束，不能让任意 Server 字段变成 shell 命令。

新主机恢复：安装 Runner → 管理员批准注册 → 新节点身份绑定允许工作负载 → 取配置/包清单 → 校验下载 → 检测系统依赖 → 请求目标会话独占执行权 → 恢复已同步文件与原生检查点 → 验证历史/资源/凭证 → 允许续聊。

只保存配置和插件：能创建新会话，但不能恢复旧工作区或完整历史。为满足“继续使用”的较强预期，建议首期同时交付冷恢复检查点：原生会话格式、插件版本清单、工作区文件版本、产品侧 App/附件/操作回执一起关联同一个 checkpointId。先上传对象，最后事务发布清单；失败不能把半份备份标为可恢复。检查点之外的新本地数据明确标为未同步。

不得对运行中的 Codex SQLite 和 WAL 做普通文件复制同步；使用原生 flush/export 或协调一致的 SQLite backup/rollout 边界。固定源码 thread/resume 支持 threadId/path/history，但 history 是实验路径且可能忽略原 threadId，不能据此承诺完整移机恢复。需原生 export/import 与 workspace rebind 探针，再决定最小补丁。

两个层级的恢复承诺：
- 配置/插件/已确认上传：Server 已落盘即可重建，源仓库失联也能从已存包恢复。
- 对话/产物/记忆：恢复至最后已确认检查点。首期建议每个任务结束做检查点，运行中增量回传但不承诺活进程迁移；界面区分“完成”和“已同步”。不能恢复内存进程、终端交互、未回传写入或外部服务副作用。

断网策略：不接新任务或启动新的外部副作用；已发出的调用可能完成，结果先持久本地 outbox。租约/epoch 只能防止新调度，不能撤回已经在上游执行的请求。新节点接管前隔离旧节点，对未知结果先核对，不自动重放；exactly-once 无法仅凭本地账本保证外部 API。设备身份重建，不复制旧设备私钥；OAuth/主机绑定登录按供应商要求重新授权。临时凭证遵守原作用域，不随备份复活。

## 7. 记忆的边界

应区分：原生会话历史、用户/项目长期记忆、插件包中的技能指引、插件业务状态。不是把所有东西归为“插件记忆”并全局共享。

全局只是物理存储根：逻辑 scope 至少有 owner/project/session/plugin+receiver。用户偏好可跨会话；项目资料仅同项目；插件业务缓存按插件、业务账号/接收方与会话约束。插件指令在只读包，状态不能写回包路径。全局原生 memories 的读取/整合不应把受限插件/项目内容隐式注入其它会话。

首期建议保留原生格式，验证现有记忆开关；未完成作用域隔离前不自动启用全局跨项目记忆。可变插件数据只有声明为可恢复的数据目录才备份，未声明的任意宿主路径不承诺恢复。单节点单写者；未来多节点记忆采用分域单写者或显式合并，不直接 rsync 互相覆盖。插件业务数据库需要自身一致快照/停写协议，不将文件复制等同数据库备份。

## 8. 全局可调上传策略

Server SQLite 保存一份带 revision 的全局策略：maxFileBytes: null 表示不设产品单文件上限；可单独配置总存储、会话存储和同时上传数量。UI 允许“不限制”，不能用 JS Infinity 写 JSON。默认迁移沿用旧限制，管理员明确选择不限制后对所有新发起上传生效；现有文件仍可读，进行中上传固定开始时策略版本。

大文件路径：浏览器分块/断点续传 → Server 暂存、增量hash、配额预留 → 验证完整后原子提交 → 会话逻辑绑定 → Runner 拉取并原子落盘 uploads/ → 任务可使用。新聊天首次上传即分配稳定 workspaceId/draftId，可晚于此创建原生线程；草稿超时清理不得删除其它会话引用。切换会话、刷新、重试和幂等完成均检查归属。

“上传容量”“预览/解析预算”“模型输入预算”“插件安装包限制”分别管理。大文本只传文件引用并按需读取，图片受模型实际能力约束；原文件可以已上传，但预览或模型处理不支持时明确说明，不伪造失败上传。每次分块可固定较小上限；磁盘余量、并发、速率、压缩/解码膨胀预算继续存在。总量也可配置 null，但不能宣称物理无限。Cloudflare/反向代理请求大小和超时不能通过关闭应用上限消除，需分块通过现有入口实测。

共享历史快照采用不可变 fileVersionId；会话工作副本可以被工具修改，不能拿修改后的文件替代历史上传原件。读取接口绑定会话/拥有者，路径遍历、链接逃逸、上传未完成、部分删除和磁盘满均需验证。

## 9. 原生二次开发的取舍

保留已实现的资源 root pinning、原子 modelRoute 与能力确认。优先补“运行时能力、状态与资源契约”，不将 Web 登录、UI 文案、Server SQLite 或插件商店写进 Rust 核心。

优先验证/补齐：
1. 统一 typed RuntimeProfile + revision，封装配置/资源输入，原生只负责其拥有的配置生效，Bridge 负责授权和对外契约。先包装已有接口，不重复造第二套配置系统。
2. 显式资源根/组件允许集合，包含技能、MCP、钩子；尽量取消每轮全量复制独立技能与通过目录扫描猜测归属，继续保持原生 SKILL.md/插件格式。
3. 原生 checkpoint/export/import、一致 flush、保留身份与结构化路径重绑定。把线程恢复所需内部格式知识封装在内核，而不是 JS 直接改上游 SQLite。
4. 受限 memory scope 与插件数据目录，仅在现有官方配置不足且有验证需求时扩展。

保持补丁小而有契约测试；固定 upstream commit、可重现构建、生成协议类型、版本协商。更深 fork 增加上游合并和恢复格式迁移成本，不能把“都能改源码”当成无限扩展依据。

## 10. 交互简化

首期仅一个节点时自动使用，不给每条消息增加主机选择。设置分为模型、扩展、存储、执行节点；插件详情统一配置组件。普通聊天只显示必要的离线/同步失败/恢复确认；具体修订号、路径和协议原因放诊断详情。插件安装成功与节点可用分开显示，已有版本在更新下载时仍可用。

模型列表继续遵循最新用户决定：全部合法目录条目显示，不恢复用途过滤。运行能力检查不等于列表筛选。既有热切换、审批、App 稳定挂载、错误细节、私密输入路径均作为回归约束。

## 12. 来源和验证边界

- [官方环境变量](https://learn.chatgpt.com/docs/config-file/environment-variables)：CODEX_HOME 与 CODEX_SQLITE_HOME 可指定位置；不等于只改 CODEX_HOME 就隔离所有用户技能。
- [官方技能发现](https://learn.chatgpt.com/docs/build-skills)：HOME/.agents/skills 与工作区/管理员/系统来源需显式处理。

- 本地固定源码 app-server-protocol/src/protocol/v2/thread.rs：resume.history 标记实验、path/history 优先级；memories/read、memories/write：全局记忆根和整合行为。

本轮结论是源码调查和架构判断，不是完成远程恢复/无限制上传的实测证明。未进行破坏性主机删除、目录搬迁、真实付费模型调用或新部署。
