# Issue 001 追加：以 GitHub URL 决定导入来源

2026-11-11 用户要求直接按已访问的 URL 导入，不再重复选择分支或标签。本轮替代原计划 S4 中的分支/标签选择、搜索和分页 UI；保留其历史记录。

## 问题与不变量

|编号|触发、实际与预期|证据与根因|
|---|---|---|
|URL-01|粘贴分支/标签链接后仍出现分支类型、搜索、下拉、刷新和分页；预期仅链接及扫描操作|有代码证据：GithubImportSource 每次输入主动调用 refs/resolve 并可生成独立 ref，重复表达用户已确定的来源|
|URL-02|URL 与单独 ref/path 可以指向不同内容；预期新增导入的唯一来源为 URL|有代码证据：imports.create 接受 ref/path；resolver 支持覆盖。隐藏控件不足以恢复一致性，需关闭新请求的覆盖路径|
|URL-03|扫描复用另一个同步解析器，它把 URL 第一个片段当作 ref；预期已有固定快照不重新解析或切换来源|有代码证据：githubSource 与 githubCatalog.resolve 两套逻辑，固定版本扫描再次调用前者；统一已解析快照校验|
|URL-04|访问 tag 可使用 tree/tag 或 releases/tag/tag 链接；预期按原标签而非同名分支导入|有代码证据：只允许 tree，release 链接被拒绝；新增标准 release tag 地址解析并验证实际 tag 对象|

不变量：粘贴 URL 决定仓库/ref/目录；明确引用失败不能回退；扫描和安装使用同一提交快照；粘贴尚未提交的输入不发起远程发现；失败不丢草稿；仅固定公开 HTTPS GitHub 服务，无凭证转发。

## 关联风险与范围

- 技能、插件安装、插件升级共用 SkillImport：有代码证据，全部纳入同一修改和浏览器检查。
- 分支/标签带 `/`、子目录、SHA 地址：已有最长真实引用解析，保留并扩充行为测试；tag 的名称不应被同名分支覆盖。
- 预览后远程分支移动、重复扫描、重启：有代码证据，提交已保存；复用已固定提交与目录，不发起重新解析。自动测试验证下载目标与持久数据。
- 最近导入旧记录：保留可见记录及已固定快照；未固定提交的旧暂存不能猜测新来源，明确要求重新扫描。
- URL 解析失败/额度限制：沿用扫描操作错误，保留输入，可原位重试；不再维护分支发现错误区。
- 本地目录、ZIP、插件运行隔离、审批和模型切换：无共同改动，不重构；相关导入回归覆盖。
- 不新增私有仓库授权、任意 URL 代理或公网部署。当前用户服务仍为旧产物，验证使用新候选的隔离实例。

### 补充：重复扫描与来源变动

有代码证据：旧 resolver 对 metadata 和 commit 结果统一缓存 60 秒，同一分支刚更新后重新扫描会取得旧提交。URL 简化后不再预加载目录，单次解析请求数较少；移除此全局缓存。每次新扫描读取 URL 当下指向，已有导入仍使用自己的固定提交，新增测试覆盖分支移动后新旧扫描分离。
