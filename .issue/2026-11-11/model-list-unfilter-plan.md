# 模型列表撤销用途过滤

用户要求撤销上一轮用途筛选，全部展示。此前过滤符合旧要求，本轮按新的产品约定调整：目录中合法模型 ID 不因用途被隐藏；展示不等于运行兼容性认证。

## 调查与范围
- U1（有代码证据）：providers.ts 按 chatCandidate 裁减目录，导致嵌入/重排不显示。
- U2（有代码证据）：session-runtime.ts 对目录、历史、手填与默认合并后再次过滤，并拒绝按用途保存默认；需要一并撤销。
- U3（有代码证据）：RuntimeSelector 以用途判断已选模型无效；需要撤销，缺失目录项仍正常提示。
- 热切换能力、上下文及工具验证为独立执行约束，本轮保留。不修改原生内核、凭证、已存默认或个人 Codex 配置。
- 保留 ID 格式、敏感信息与响应资源限额等安全校验，不将“全部展示”解释为开放任意不合法目录数据。

## 顺序与验收
1. 撤销目录和默认用途限制及前端用途判定；保留用途元数据，兼容已有 SQLite 记录。
2. 更新目录行为测试：嵌入、重排、未知、聊天及历史/手填/默认均可发现、选择；能力验证测试继续通过。
3. 类型检查、构建；开发实例空闲维护下更新，浏览器核对模型选择器。记录验证及任何阻塞。
