## 已确认原因及实施细化（00:14）

`live-summary.json` 确认已安装 0.5.2，但报错线程和新线程都保存了 `enabled=false` 的连接器快照；当时插件详情 `configured=false`。原生 rollout 显示 00:09、00:10 调用原稳定名称后收到 `unsupported call`，并非连接器 ID 发生变化。00:12 用户再次保存后 `configuration-state.json` 已显示 `configured=true`、必填密钥已保存。真实操作的历史私密输入不读取，无法还原每次输入值。

代码证实两条共同缺口：保存使用新配置计算凭证绑定，绑定变化后得到空凭证集合，却可提交“成功”覆盖旧值；同时显式插件/专家引用仅检查插件安装/启停，不检查其启用的连接器是否配置完整。后续让模型使用插件技能但不给工具，造成按历史名称反复调用。既有热更新流程先保留，使用真实原生回归检查其实际行为。

S1/S2 收敛为：

1. 保存的原子校验：启用连接器缺必填密钥时拒绝；已有密钥因普通配置变化不再匹配时，明确要求重新输入，保存前配置/密文/修订保持不变。显式清除、主动停用仍有可表达路径；不把密钥自动授权给新地址/新代码，不增加业务字段猜测。
2. 详情显示实际缺失字段；保存回执区分可用、停用和待配置，避免清除必填项后仍称“下次任务使用”。
3. 明确选择插件或包含插件的专家时，在任务登记/模型派发前核对其启用连接器；由冻结快照约束，恢复后再校验原生就绪状态。无关未配置插件和用户主动停用的可选连接器不阻塞普通聊天。
4. 保留通用开发者能力说明：只能调用当前发布的工具；历史名称不证明当前能力，禁用/缺配置不应被解释为需要重启，也不能通过 Shell 绕过连接器。
5. 隔离模拟 Provider/MCP 验证：缺项不产生模型请求；补齐后同一原线程请求带当前工具且实际执行一次；普通参数、重装/升级、启停和重启恢复采用同一校验。真实用户正在修改的配置保留。

不新增 SQLite 迁移。新校验读取已有描述、私密绑定和扩展快照；已有不完整设置可读取和修正。保留所有原配置/历史、插件和私密输入隔离。前轮浏览器控制禁用；仅通过现有表单错误和状态文案反馈，不扩展新的设置页面。
