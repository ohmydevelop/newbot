# 004：面向使用者整理 README

## 目标与问题

用户要求更新 README，提供人类易读的说明。首次阅读应能理解产品用途、安装前提、配置顺序和当前边界；不能把历史计划当成当前行为。

实际：README 混合阶段代号、历史测试数量、安装指南和协议细节；缺少事件 Bridge。使用指南仍称每次自动运行新建会话，GitHub 示例仍称不支持 CI。README 的 npm 快速启动未说明当前生成协议需要定制原生内核。

预期：从用途、启动、日常使用到部署和开发逐层展开，术语有解释，命令与当前代码一致。

## 证据与原因

- `package.json`、`generated/version.ts`、`server/codex.ts`、`native/codex/manifest.json`：npm Codex 版本和当前协议基线不同；启动检查版本，不能承诺只安装 npm 包就具备当前内核能力。
- `server/automations.ts`、`docs/event-bridge.md`：任务复用专属会话，事件由插件接入。
- `examples/github-events/server.ts`：已声明 `workflow.completed`。
- 原因：功能变化后没有同步整理用户入口文档，历史记录与当前指南混用。以上为代码证据；本轮不重新执行模型或部署验收。

## 范围与步骤

1. 先保存本计划；重写 README，保留开发版本定位与重要数据/部署限制。
2. 修正直接关联指南中的上述冲突；不重写历史 issue，不修改产品代码、凭证或数据库。
3. 校验 Markdown 本地链接、npm 命令、格式和差异，记录结果。
4. 沿用本会话推送授权，提交并推送 `codex/newbot-systematize`。

无数据迁移。依赖仅为当前源码与已有验收记录；无需外部账号。
