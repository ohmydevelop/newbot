# AUTO-7F：HTTPS 中继与真实生态安装验收

用户目标：插件事件通过内网机器主动出站连接进入自动任务，并复用任务会话；OpenClaw/Hermes 必须经过真实安装、发现与运行流程。

## 证据与约定

前轮记录及 tests/event-bridge-ecosystems.test.ts 证明的是独立 hook 函数向 HTTP relay 发布；webhook 测试还将 HTTPS 地址映射到 HTTP。它们不证明真实生态安装或 HTTPS 端到端。生产为 d10faea，工作树 HEAD 36f0277，本轮在 newbot-systematize 隔离验收，不改生产会话。

不变量：安装包可被实际产品发现并运行；TLS 验证始终启用；事件经持久中继、MCP 插件和自动任务执行；同任务复用同会话；确认/重试不能丢失已接受事件；平台不增加提供方分支。

## 实施顺序与范围

1. 固定上游版本，隔离目录安装官方 OpenClaw 与 Hermes，记录来源与发现命令。
2. 本地 CA + HTTPS 反向代理 + 独立真实 relay；可信和不可信客户端验证。
3. 导入 relay 插件并建立隔离 Newbot 自动任务，执行事件至会话的完整链路。
4. 通过两个实际产品加载安装包、产生生命周期事件；验证两个事件关联同一任务会话。
5. 修复发现的共同缺口，加入可重复验收脚本、记录边界；产品有改动才走构建/发布门禁上线。

不处理：公网 relay、第三方 SaaS 账号、真机测试、上游产品功能改造。模型若使用本地确定性服务，仅声明真实 Agent runtime，不声明外部模型兼容。依赖网络下载、上游安装条件；测试凭证、证书私钥和数据库仅存 gitignored .data/bridge-acceptance。无需生产数据变更；如有协议改动保持旧包兼容。
