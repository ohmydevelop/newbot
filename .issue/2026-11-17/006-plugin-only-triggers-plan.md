# 006：事件来源仅由插件提供

## 用户目标与复现

用户在添加触发器中仍看到 GitHub、OpenClaw 等固定业务选项，要求通过插件集成，平台不硬编码具体业务。

预期不变量：新增外部事件触发器必须来自当前可用的已安装插件；前端和 API 不能绕过该约定。未安装来源插件不能创建对应任务。时间触发仍为平台能力。旧任务、凭证、会话与历史不能因收紧新增入口而丢失。

## 已知证据与根因

- `AutomationScheduleFields.AddSchedule` 把 `eventSourceLabels` 固定列表与插件 providers 拼接，`AutomationEditor.onEvent` 仍创建旧 source。
- `server/automations.save` 接受包含旧枚举的通用读取 schema，未区分新增与历史兼容。
- `server/automation-events.ts` 仍包含旧业务验签与数据适配；`shared/automations.ts` 同时保存旧标签和通用任务类型；旧前端字段内也有业务分支。
- `check-event-boundaries.mjs` 仅覆盖订阅目录及两个 UI 文件，遗漏触发器选择器、保存路径及旧事件接收实现。
- 早前移除了 OpenClaw/Hermes 示例，但未关闭旧创建入口。历史完成记录不能覆盖本次发现。
- 当前开发分支 codex/newbot-systematize；实际服务位于 newbot 的 dist，验证后需发布相同构建才能消除在线菜单。

## 范围、顺序与兼容

1. 保存调查和计划，采集线上旧菜单证据。
2. 隔离旧 schema/标签、旧接收协议和旧编辑字段；平台新增路径只依赖插件目录与通用接口。
3. 在事务内按既有任务检查旧触发器身份，防止 UI 隐藏但 API 仍可创建；保留修改旧条件与移除旧触发器。
4. 更新契约、API、边界检查和浏览器测试；证明不改平台注册表也可用新插件。
5. 对构建和界面做本地验收，提交；备份线上产物、取得空闲维护锁后发布同一构建，公网复验。

不实现 OpenClaw/Hermes 生态插件，不把旧 webhook 自动转换为新订阅，不修改用户任务配置或加密凭证，不重做视觉。不需要 schema 升级；旧内容继续可解析。若发布不兼容则回滚产物，保留数据库。

## 验收

- 无插件来源时菜单只有时间选项；有插件后按声明显示，不追加固定 GitHub/Hermes/OpenClaw/Webhook。
- 新增旧来源、复制旧来源至新任务、替换旧 source 均被 API 拒绝，数据库和入口无副作用。
- 既有旧任务可读取、编辑、轮换凭证、接收事件、删除触发器；定时任务与通用插件任务保持正常。
- 通用插件账号/schema 配置、事件到同一会话链路通过；手机/桌面就近浮层不溢出，Escape 焦点恢复。
- 生产源码/构建/运行入口一致；公网菜单与本地验收一致。模拟上游与真实业务结果分别标注。
