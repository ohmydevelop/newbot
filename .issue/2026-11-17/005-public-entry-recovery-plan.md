# 005：公网入口失效恢复

## 用户目标与现象

用户访问刚提供的 trycloudflare 地址失败。预期：公布的地址可打开并登录；进程存活不能当作公网可达证据。实际：主站本机登录 200，公网 TLS 连接失败；主站、应用域和中继 cloudflared 日志均持续报告 `Unauthorized: Tunnel not found`，但 systemd 仍显示 active。

## 根因与证据

临时隧道的远端注册已失效，cloudflared 在原进程内反复重连，未退出，因此 Restart=on-failure 未触发重建。远端为何删除注册尚未确定。证据来自生产实例 `.data/cloudflare-web.log`、`.data/cloudflare-apps.log`、`.data/event-bridge-live/tunnel.log`，以及本机 /api/login 200。

运行源站为 `/home/a/Documents/ChatGPT/newbot` 的现有 dist，由 newbot-test.service 提供 3100；本轮不替换构建产物。调查与记录在开发分支。

## 关联风险

| 入口                 | 共同机制             | 状态与处理                                        |
| -------------------- | -------------------- | ------------------------------------------------- |
| 主站                 | 临时 Cloudflare 隧道 | 已复现，重建并验证公网登录                        |
| MCP Apps 应用域      | 相同隧道模式         | 有日志证据，重建，保持不同 origin 与隔离          |
| OAuth 回调           | 依赖主站 origin      | 有配置证据，同步回调；不冒充真实账号 OAuth 验收   |
| 事件中继             | 相同隧道模式         | 有日志证据，重建并核对生产者/消费者与持久游标迁移 |
| 登录密码、模型及会话 | 源站仍可用           | 不更改；重启前检查活跃任务与审批                  |
| 邮件链接、分享元数据 | 可能引用旧域名       | 待验证，仅更新确定属于本实例的地址                |

## 实施顺序与范围

1. 保存本计划，备份会改变的本机配置；不在记录中写凭证。
2. 重建失效隧道，读取新注册地址并确认连接。同步主站、应用域、回调及分享元数据。
3. 源站进入空闲维护后重启以应用 origin；保留数据和密码。
4. 中继优先保留原数据库、route、密钥、事件及游标；地址变化的绑定迁移必须有备份和队列证据，不能清空状态强行启动。
5. 公网验证首页、登录、会话接口、应用域隔离与浏览器实际打开；检查关联事件通道。

不购置域名，不配置未授权 Cloudflare 账号，不修改 UI 或模型执行逻辑。固定域名缺失仍是临时分享限制。

## 验收与状态

公开新地址前确认真实 HTTPS 登录与页面可用，密码不变；应用域不暴露主站登录/API。事件通道恢复需区分网络、队列与模型业务验证。浏览器或外网探测受限时明确报告。结果记录于 `005-public-entry-recovery-progress.md`。

状态：恢复与验收完成；长期临时域名限制见进度记录。
