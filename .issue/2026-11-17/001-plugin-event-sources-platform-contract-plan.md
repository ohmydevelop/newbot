# AUTO-7E 平台通用事件扩展约定：架构纠偏评估

## 用户目标与问题
用户指出平台应提供通用接口，由插件实现，而非平台硬编码各家服务。触发：安装非 GitHub 事件插件。实际：manifest 仅允许 github-issue-events-v1，宿主直接构造 GitHub adapter，字段仍固定仓库与 token。预期：实现版本化事件扩展约定的插件安装后贡献来源、账号连接方式、资源字段、事件和订阅能力，增加提供方无需改平台服务与 UI。

不变量：提供方特有 API、事件、字段、认证转换属于插件；平台拥有授权、执行边界、调度、持久化、派发及统一 UI。不是所有现成插件自动具备事件能力，只对实现该扩展的插件承诺兼容；纯工具插件不推断出事件。

## 代码证据及因果解释
- 有代码证据：shared/event-subscriptions.ts 使用 adapter literal 与 githubEventLabels；service.ts 导入/实例化 githubIssueEvents，并给所有来源绑定该事件列表。
- 有代码证据：shared/automations.ts 订阅必须填 owner/repo；AutomationSubscriptionFields.tsx 固定仓库、token 和每分钟文案。
- 有代码证据：server/event-subscriptions/contracts.ts 已有通用 PullAdapter，engine 的游标、租约、去重、目标派发可保留。问题在扩展边界只开放了声明，未开放插件实现能力；不是底层 engine 全部需要重写。
- 已核实范围：当前源码。前轮构建/本地验收是 GitHub 特例的证据，不能证明第三方零改核心接入；本轮没有运行新插件复现，不宣称浏览器已验证通用性。

## 同类风险
|优先级|入口/机制|状态|范围与理由|
|---|---|---|---|
|高|manifest→注册→执行|有代码证据|宿主白名单仅含特定厂商 adapter；改为版本化扩展执行协议与插件身份授权，不能把任意脚本直接载入主进程|
|高|账号和认证|有代码证据|固定 token 无法表示 OAuth/多字段凭证；平台管理秘密引用与授权流程，插件声明需求，防止令牌进入通用事件|
|高|任务配置/校验/UI|有代码证据|固定 repository 阻断邮箱等资源；受限配置 schema 和标准控件渲染，服务器同样校验|
|高|升级/卸载/恢复|待验证|沿用包摘要与账号绑定、CAS、代际隔离；新运行器仍须通过旧生命周期用例|
|中|poll/长轮询/订阅续期|待验证|平台管理持久检查点、取消、超时和退避，插件适配上游；确认回执可选，不假设所有上游支持 ack|
|中|旧 webhook 与任务数据|有代码证据|新增 generic config 时需迁移旧 repository；已有 source 名称/链接不得被重解释|
|中|订阅状态文案|有代码证据|固定每分钟不适用于长轮询；平台按能力与策略显示，不由插件注入任意 HTML|
|排除|整站视觉重构|不适用|使用既有 Grok 风格表单控件，修正配置来源即可|

## 调整方案与顺序
1. 冻结第一版可选事件扩展协议：来源发现/元信息、事件类型、资源与筛选 schema、认证能力、连接验证、增量读取及可选确认、取消/关闭；统一错误与版本协商。新平台约定不得冒称 Codex 或 MCP 标准。
2. 平台实现单一扩展运行桥，优先检查现有 connector/插件运行通道能否复用。传输选型在核对现有能力后确定，不为每个提供方增加宿主注册分支。插件业务实现通过受管理执行边界运行；网络/凭证权限显式绑定插件，不直接 import 不受信任的插件代码进入服务器。
3. 从 shared/server/UI 移出 GitHub 特例到独立示例插件；平台接收受限字段 schema 并用现有控件渲染。凭证仍由平台 vault 与授权流程管理，只向获准执行提供必要访问。
4. 迁移现有 GitHub 任务到通用 config，保留任务/会话/目标身份和游标；不可兼容的插件升级明确暂停，不悄悄重放。
5. 增加一个与仓库字段完全不同的本地测试插件（例如信箱资源、不同认证字段），证明只安装插件即可发现/配置/运行，无平台代码修改；替身不冒充真实 Gmail。
6. 复跑重复事件、断线、崩溃、凭证变更、插件卸载、迟到响应、恢复与多任务共享，检查深浅色/窄屏与动态字段焦点。增加架构检查：平台模块不得导入提供方实现或厂商字段列表。

## 验收与不处理范围
关键验收：第二个独立插件在不修改 Newbot 核心/前端的条件下安装、自动出现来源、生成不同字段配置并触发同一任务会话；错误协议版本有明确状态；撤销授权立即阻止后续事件；旧任务无数据丢失。用插件合规测试验证兼容，而非只把字符串改为任意值。

2026-11-17 用户已授权实施以下正式计划。真实 Gmail OAuth、现有任意 MCP 插件自动转事件、OpenClaw/Hermes 全量兼容不作为无证据承诺；后续转换器须实现同一扩展协议。原生 Codex 版本配套问题仍为独立上线阻塞。

## 已批准实施基线（AUTO-7E）
- 目标：第二个插件只通过安装、配置即完成来源发现、动态字段和执行；宿主不增加厂商分支。
- 使用 MCP SDK 和锁定 ext-events 草案 47d95c979faa73427e1f6e0ac0c1347559d8ea37 的事件方法；内部 CloudEvents 1.0，通用 engine 继续拥有持久化/去重/租约/派发。
- 插件通过版本化声明引用包内 MCP 连接；事件元信息来自 events/list。stdio 与 Streamable HTTP 独立于 Codex Agent Loop；凭证、认证、TLS 复用平台机制，不把进程隔离当沙箱。
- 交付顺序：协议/运行桥与夹具→动态注册与配置→GitHub 外移和信箱第二插件→自托管 Fastify/SQLite 中继→OpenClaw/Hermes 发布转换→迁移/浏览器/原生验收→备份候选发布。
- 中继提供发布/领取/确认；只有出站即可消费，租约重投，待处理不清除，完成正文7天/去重30天，十万待处理上限；不创建收费云资源。
- 参数来自受限 schema，前后端同校验，原 Grok 字体/布局/菜单保持。匿名、私密字段、OAuth 和自签名证书的入口保持统一。
- GitHub现有事件语义保留；OpenClaw导出消息接收/发送/会话重置，Hermes导出agent开始/结束/会话重置。源端持久发件箱，事件不是任务指令。
- 旧任务/会话/触发器/密钥/去重键保留；迁移日志恢复跨库操作，Worker 迁移完成前不启动。不兼容来源升级暂停而不重放。
- 架构自动检查禁止平台依赖厂商适配器；合规/故障注入/原生导入/实际出站/窄屏深浅色浏览器验证形成证据；外部账号不足不得冒充完成。
- 完整验收覆盖授权中的计划五节：协议能力、共享来源、断线恢复、重复及迟到、OAuth拒绝/刷新、私有证书、插件生命周期、固定会话、旧入口回归、中继部署包、开发模板。

## 续轮：迁移、中继、插件接入与浏览器验收
- E1 已复现：push 回归两个失败；直接调用 adapter 未确认重复领取属预期，账号改名重建 adapter 属生命周期缺陷假设（需针对性复测）。约定：持久确认前允许重投；仅名称变化不得改变游标/活动流。
- E2 有代码证据：v1 GitHub 来源仍经 legacy 入口；迁移须保留既有 source_events/deliveries 主键，不允许重新 baseline 吞事件；迁移恢复先于 worker。
- E3 有代码证据：中继已有持久 fanout/ack；缺少签名 webhook、部署包与消费者回收入口。相关边界包括失效回执、私有令牌、正文保留期限、重启恢复。禁止把 Bearer CloudEvents 入口称为 MCP webhook 标准实现。
- E4 待验证：动态插件浏览器流程、深浅色窄屏、滚动/焦点/菜单。通过实际安装第二种插件证明无需核心改动，模拟信箱不称真实 Gmail。
- 顺序：修复生命周期与断线→兼容迁移/故障测试→补齐中继通道/部署/生态包→通用 UI 浏览器→发布门禁。旧 webhook/会话/账号保留，不替用户创建外部云资源。
- 发布条件：当前代码构建、架构检查、针对性回归、浏览器与固定内核 smoke 均通过；任何必要能力未验证则保持当前线上版本并列出具体差距。

迁移实现决策：不重新划分旧订阅，不改独立 inbox/游标库；主库事务内补 arguments 和 migration 完成记录。因此取消不必要的跨库重键迁移，避免新增双写恢复风险。既有 v1 源继续经隔离兼容层执行，升级到不同包摘要仍要求重新确认；新 v2 插件不增加兼容层分支。验收包括迁移中断回滚、重复启动、固定会话/账号密文/旧 webhook 保留和既有订阅重启用例。
