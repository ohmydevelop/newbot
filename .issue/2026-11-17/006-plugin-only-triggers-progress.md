# 006 事件来源插件化与旧格式删除：实施与验收

## 当前决定

以 `006-plugin-only-triggers-strict-plan.md` 为准。第一轮保留旧格式的方案已被用户明确否决，没有发布。当前实现不再隔离/兼容旧入口，而是删除。

## 问题 → 原因 → 修复

- 固定来源菜单：新增入口仍合并旧枚举。现只从已安装插件目录构造来源，时间触发保持平台实现。
- 旧 API 绕过菜单：删除旧 webhook 路由、认证例外、旧密钥设置接口及对应发送脚本。统一任务 schema 必须有当前来源、账号、事件名和参数。
- 旧事件包继续运行：删除 v1 适配器和平台 GitHub 业务引用；账号只解析当前配置对象，不再读取原始 token 格式。
- 自动补旧字段：删除 repository→arguments 转换；v24 清理无效任务及队列/历史/引用，并移除旧路由表。
- 自动补会话绑定：删除读取时猜测历史会话的逻辑；缺少显式绑定的旧运行任务被清理，聊天正文不删。
- 关联机制：凭证库初始化还依赖旧路由表，测试复现新实例凭证锁定后同步删除依赖；独立订阅库按任务与触发器清理无效目标，保留有效游标和去重记录。
- 回归约束：扩展 `check-event-boundaries.mjs`，阻止固定业务进入平台和旧端点/兼容模块重新出现。旧协议测试被当前协议拒绝/清理测试替代；移除旧实验桥，保留独立插件与引擎测试。
