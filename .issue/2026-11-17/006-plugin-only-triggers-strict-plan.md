# 006 第二轮：插件事件接口唯一化，不保留旧格式兼容

用户最新要求：代码不保留旧格式兼容；缺少当前格式必要信息的数据直接删除。本计划取代 006 原计划中的旧触发器隔离和身份保留方案，原记录保留为调查历史。

## 目标与不变量

所有外部触发器只能由已安装的当前事件插件提供。平台不注册具体业务来源，不接受旧 source、旧插件事件声明或缺少必要字段的事件任务；不会补猜字段或继续执行旧数据。合法任务的身份、去重游标、会话和运行结果保持不变。

触发条件：新增/编辑/重启/接口直调。实际：旧业务菜单、旧 webhook 接收器、v1 账号解密及 repository 转 arguments 仍维持旧路径。预期：唯一当前协议，旧格式数据清理一次，后续写入严格校验。

## 证据与范围

源码证据见上一轮计划。2026-11-17 只读盘点实际生产数据库 v23：12 条任务，其中 4 条含旧 source（2 条已软删除、2 条可见），8 条旧 webhook 路由，1 条当前 subscription 任务、1 个事件账号。现有真实业务任务已具备 providerId、connectionId、events、arguments；无需业务字段转换。

|风险|状态|处理及依据|
|---|---|---|
|固定菜单与新增/编辑 API|已复现/有代码证据|目录只读插件；当前字段必填，拒绝旧来源|
|旧接收器、认证例外、凭证轮换、UI 字段|有代码证据|删除整个旧入口和业务解析实现|
|v1 manifest、原始 token 账号、repository 字段补全|有代码证据|删除兼容模块；不再转换，删除不符合当前配置的记录|
|任务关联表、未执行队列、独立订阅游标|待验证|清理无效任务及其队列/历史/引用，保留聊天本体；仅清理失效订阅，不重置有效游标|
|插件暂时离线/停用与账号过期|有代码证据|与格式无效区分：网络或授权失败不能当作旧格式删除理由|
|时间任务和当前插件任务|待验证|保持身份、会话、账号与运行历史；重启和真实任务复验|
|桌面/手机触发器浮层|待验证|已有样式不改；验证目录、搜索、焦点、布局和动画|

## 实施顺序

1. 删除旧 UI、协议枚举、接收端点、兼容适配器与旧发送脚本；当前 schema 要求事件参数、账号、来源和事件名。
2. 用一次性破坏性清理替换字段转换迁移，数据库升至 v24。无效任务连同依赖记录删除，原会话内容保留。清理旧路由表。账号仅按实际解密后的当前字段校验，不因外部不可达删除。独立订阅库移除无效配置和失效任务投递。
3. 将检查覆盖整个事件实现和触发器 UI，禁止重新引入旧适配及平台业务来源；测试旧格式拒绝、删除事务与幂等性、有效数据保留以及插件端到端。
4. 构建、浏览器验收后，以生产备份副本先执行 v24 清理，核对删除清单。发布使用维护锁、数据库/产物备份和准确版本验证；公网复验。

不处理：其他无关模块的历史迁移、引入 OpenClaw/Hermes 兼容、改变现有视觉设计。历史调查记录不是运行时兼容代码。业务插件中的 GitHub 事件实现仍属插件，不应删除。

## 验收

- 无插件不出现业务来源；安装任意符合接口的插件即出现，无平台注册表改动。
- 旧来源和缺失当前必填字段的保存被拒绝，不会补字段；旧端点不再注册。
- 重启后无效旧任务与关联记录真正删除、无孤儿引用；有效任务与会话、账号和游标不变；清理可重复且失败事务回滚。
- 模拟插件端到端注明为测试上游；线上实际插件和同一会话结果独立验证。
