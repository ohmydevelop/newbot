# AUTO-7C 出站订阅开发实验

## 授权、目标与范围

用户在 AUTO-7B 评估后授权“规划开发实验”。本轮在当前 codex/newbot-systematize 工作树开发可重复运行的隔离实验，不将实验组件接入生产进程或改动现有 UI/线上配置。

目标路径：导入声明式实验插件 → 注册受控 Pull 适配器 → 两个任务共享一个来源订阅 → 仅主动 HTTP 请求拉取 → 事务保存来源事件和各任务分发记录 → 复用真实 Newbot automation 队列，在各任务固定会话执行。

实际缺口和因果证据继承 001-plugin-event-sources-intranet-plan.md：来源枚举与入站协议绑定；receiveEvent 只有单任务事务；没有跨任务来源 inbox/checkpoint/ack。因此先验证可靠交付的共同机制，再接实际 SaaS。

## 本轮约定与风险

|编号|不变量/共同机制|调查状态与证据|验收|
|---|---|---|---|
|E1|来源订阅只由服务端主动出站，不要求回调地址|有代码证据：生产仅支持入站；实验新增 Pull|本地 HTTP 上游监听，订阅消费者不调用 listen；真实 Newbot app 仅 inject，不监听公网|
|E2|inbox、目标快照、游标一起落盘，落盘后 ack|待验证；当前缺跨任务事务|ack 前崩溃/ack 失败、重新开数据库、重投；不丢目标、不重复 run|
|E3|同一订阅只有有效租约持有者提交，迟到响应不能越权|待验证；Runner 可借鉴但不共用凭证|并发实例、租约过期、禁用期间响应、重新启用 fencing|
|E4|一个目标失败不阻塞其他目标；成功回执丢失允许幂等补发|待验证；任务 receiveEvent 提供幂等底座|两个任务共享拉取，故障注入与恢复，同会话独立 turns|
|E5|插件仅声明已注册适配器，未知代码不能执行|待验证|未知 adapter、非法 manifest、卸载/重新安装与在途响应|
|E6|初始化不回放历史；撤权/游标缺口/容量满可观察|待验证|基线游标、401/429/410、重试时间、队列上限；不把错误消息原文持久化|
|E7|账号/资源身份与事件命名空间不混用|待验证|相同上游事件 ID 不同连接隔离；同 ID 不同内容拒绝且游标不前移|
|E8|任务暂停/修改/删除不接受旧版本事件|有代码证据：receiveEvent revision/enabled 守卫|任务端最终检查，过期目标终止而非无限重试|

## 实施顺序

1. 实验放 examples/event-subscriptions；定义严格版本化清单、受控适配器注册表、业务事件和绑定目标。manifest 不携带 URL/密钥或可执行代码；主机注入连接适配器。
2. 使用独立实验 SQLite（不迁移生产 DB）实现订阅唯一键、修订/租约、inbox、目标分发、checkpoint 与待确认 receipt。同步事务边界不得跨 await；同一实例并发 tick 合并。
3. 实现有超时/大小限制/禁止重定向的受控 HTTP Pull 实验适配器；仅固定本地地址用于可重复测试，不作为可配置任意 URL 的生产连接器。真实 Gmail/GitHub 适配器留下一阶段。
4. 故障测试覆盖 E1–E8，再用本地真实 HTTP 上游 + 实际 Newbot automations + FakeCodex 跑集成实验；模型/账号为替身，结果须明确标注。事件通过实验桥映射到现有 webhook 类型，仅复用内部队列，不创建或暴露 webhook 地址；此桥不冒充正式动态插件注册完成。
5. 提供一条可重复实验命令、报告文件；运行类型检查、原自动任务事件/会话回归；更新计划与证据。实验不改 UI，因此不伪造 Grok 浏览器验收。

## 后续阶段与兼容

- 根据实验结论把可靠机制迁入服务端正式 schema/插件生命周期与凭证系统，再接 Gmail history/PubSub 和明确支持语义的 GitHub 资源轮询。
- 正式接入前补真实账号 scopes、代理/私有证书、游标过期重建策略、存储清理/事件重放政策、UI 连接与状态、进程监督。
- 保留旧时间/Webhook ID、签名密钥、任务会话与生产数据库；本实验不变更既有生产协议、不发布至公网。
