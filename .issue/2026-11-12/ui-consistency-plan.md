# 交互一致性：侧边栏状态位、相对时间与操作文案

日期：2026-11-12。来源：用户提交的 `.issue/2026-11-12/002.md` 与截图 `image-12/13/1/2.png`、`image.png`。

## 用户目标

1. 统一图标/动作的心智：菜单里的“查看详情”统一为“详情”。
2. 侧边栏对话行：鼠标悬停显示“更多（⋯）”，否则显示状态；状态与“⋯”共用右侧同一位置（现在状态占固定 76px 且在“⋯”左侧）。
3. 在某个位置显示“最近工作时间”（相对时长，参考 `14h ago`）。
4. MCP 卡片菜单：“查看详情”→“查看”，“重新连接”→“重连”。
5. MCP 工具详情里“停用”是文字按钮，其余是图标按钮 → 统一为图标。
6. 排查同类 UI/UX 不一致并一并处理。

## 现状与证据

- 侧边栏行：`.history-link` 内渲染 `ThreadStatus`（`flex: 0 0 76px`），行尾另有 `.history-more` 按钮（hover 才显示），两者并排。证据 `web/App.tsx:1049-1080`、`web/styles.css:340-371`、`5345-5400`。
- 对话摘要 DTO 已带 `updated`（毫秒），但界面没有展示：`shared/types.ts:41-48`、`server/db.ts:166-173`。
- 菜单文案不一致：`McpSettings.tsx:270/286`、`ToolsSettings.tsx:222`、`ExpertsSettings.tsx:189` 使用“查看详情”“重新连接”。
- MCP 工具详情动作区混用：铅笔、删除、刷新是 `.icon-button`，“停用/启用”是 `.secondary` 文字按钮（`McpSettings.tsx:415-440`），截图 `image-2.png` 已标红。
- 同类问题排查：其余设置行（Provider、Skills、Plugins、Experts）动作区已全部为图标按钮；仅 MCP 详情一处混用。头像 `.avatar` 使用硬编码浅色 `#e5e3df`，在深色侧栏里是唯一非主题色块（`web/styles.css:392`）。

## 方案

- 侧边栏行结构改为 `[标题][相对时间][动作位]`；动作位固定 30px，状态与“⋯”绝对定位重叠，hover / 键盘聚焦 / 菜单展开时状态淡出、按钮显示。状态改为图标式（等待态显示图标+数字徽标，完整文案留在 `title`/`aria-label`），避免 76px 空列和文字挤压。
- 悬停能力弱的环境（`@media (hover: none)`）改为状态与“⋯”并排常显，避免触屏用户失去入口。
- 新增 `web/time.ts`：`relativeTime()`（刚刚 / N 分钟前 / N 小时前 / N 天前 / N 周前 / 月日）与 `absoluteTime()`（`title` 用，精确到分钟）。时间常显、次要色、等宽数字。
- 菜单文案统一：MCP 菜单“查看”“重连”；Tools/Experts 的“查看详情”→“详情”。整句按钮（配置反馈、凭证重连等）保留“重新连接”，因为它们是解释性按钮而非菜单项，不与图标菜单混排。
- MCP 工具详情的启停按钮改为 `.icon-button` + `Power/PowerOff`，保留 `aria-label`、`title` 与禁用逻辑。
- 头像改用主题变量（`--hover` / `--text`），深色下不再出现浅色硬编码块。

## 不做

- 不增加“置顶”功能（用户截图里的图钉来自其它产品，本产品没有该状态）。
- 不改状态判定逻辑（完成/失败/等待的语义与颜色保持）。
- 不改菜单结构、不改动作权限与禁用规则。

## 验收

- 单测：`relativeTime` 边界（<1 分钟、分钟、小时、天、周、月日、未来时间、空值）。
- 构建与全量测试通过。
- 浏览器实测（隔离 fixture 服务，不写真实数据）：普通/悬停两态截图（浅色+深色）、动作位无布局跳动、相对时间正确、等待态徽标、MCP 菜单文案与详情图标按钮、触屏（`hasTouch`）下两者并排。
- 真实服务复查：首页与登录正常，无控制台错误。
