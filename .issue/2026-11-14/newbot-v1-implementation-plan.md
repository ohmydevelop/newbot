## 1. 目标、范围和决策优先级

用户目标：以一个Agent前端框架、一套默认设计系统和标准协议承接Newbot，减少通用基础能力的自研；保持轻量、私有化、Codex后端、MCP Apps、多Provider，支持明确边界下的多Bot和多主机。

现状：生产是React/Vite/Fastify + Codex + AG-UI，已有自研聊天界面、官方A2UI0.9与MCP Apps SDK、配置/授权/回执/本地Runner。不是从零建设。主要迁移风险是重复执行/状态所有权、包兼容、既有权限边界和历史恢复失守，不能仅以新界面出现作为验收。

决策优先级：用户本次v1.0架构与本计划 > ARCH-01修订 > STACK-02历史计划。具体变更：
- CopilotKit唯一Agent前端框架；删除旧计划的assistant-ui备选，不自动换框架。
- Apps SDK UI为默认组件/主题来源，ChatGPT风格替代此前Grok逐像素视觉目标。即时发送、思考默认折叠、紧凑步骤、滚动衔接、附件分块、侧栏管理、无硬编码追问等行为约定继续保留。
- Radix只补Apps SDK UI未覆盖的行为；不以shadcn或Cult再建立默认组件体系。
- A2UI协议1.0固定；具体兼容renderer与包版本经阶段G1验证后形成可执行版本锁。优先官方React实现，不自行开发协议处理器；无法兼容则记录阻塞与ADR，不强制安装掩盖问题。
- 原issue/截图和历史计划不覆盖。PRODUCT.md、DESIGN.md、surface brief在实现新设计系统的阶段更新为实际行为，避免文档提前宣称线上已迁移。

本计划覆盖完整v1.0交付。性能/版本验证、基本安全和数据归属从第一阶段实施；多Bot和多主机完整交付是后续阶段，不把未实现能力提前暴露。排除：第二Agent Loop、第二AG-UI客户端、RAG平台、多Agent编排、付费云服务依赖、Claude/Grok插件转换器、自动接管未知副作用、对任意用户内容的全能DLP。

## 2. 冻结的技术与部署边界

| 职责 | 采用方案 | 执行边界 |
|---|---|---|
| 推理/工具循环/原生历史 | Codex App Server | 唯一Agent执行核心；保留必要补丁直到上游验证覆盖 |
| Agent前端与标准状态交互 | CopilotKit React + TS Runtime | Runtime嵌入同一Server；不用BuiltInAgent再跑模型 |
| 通信 | 官方AG-UI SDK | native事件到标准事件薄适配，产品扩展明确命名；不重写协议客户端 |
| 通用界面 | Apps SDK UI + Newbot tokens | React19/TS/Vite/Tailwind4；Radix补缺；独立运行不伪造window.openai |
| 动态UI | A2UI1.0 + Catalog | 官方core与兼容renderer；Catalog不依赖CopilotKit私有状态类型 |
| 第三方应用 | 官方MCP Apps AppBridge | 独立origin/iframe与服务端授权；不要求经过CopilotKit渲染组件 |
| 代码/数学/图表 | 现有成熟Markdown/高亮/公式库 + ECharts | 只保留一条产品Markdown渲染实现，不因Apps SDK依赖而出现两套 |
| 编辑与Diff | Monaco | 在受控工作区编辑入口按需加载；代码消息仍用轻量高亮 |
| 动效 | Motion + 原生CSS | 复杂布局与进退场用Motion；简单hover不用JS；尊重reduced-motion |
| 本地应用状态 | Zustand | shell/设置/非Agent普通草稿；不复制权威消息、执行和审批状态 |
| 数据校验 | Zod | 应用保持自身版本；第三方SDK版本边界隔离，不全局强制跨主版本 |
| 主机执行 | 现有Runner演进为Host Connector | 同一节点身份/回执/租约体系，不创建第二套连接协议 |
| Provider/MCP适配 | 现有Server配置/路由/授权 | 不另造模型循环和重复工具执行器 |

首次迁移保持单Server + WebUI + 本地Host Connector；独立Apps origin属于安全隔离而非新微服务。远程Connector阶段才启用分机产品路径。保留现有SQLite/对象存储，不强制增加Redis、Postgres或Kubernetes。

### 2026-11-15 · 用户反馈后的交付约束

用户明确拒绝只有文本聊天的在线实验页：原插件等能力缺失。G1技术探针不再作为日常使用入口交付；当前日常入口保持原完整产品。用户可验收版本必须同时具备原应用外壳、历史导航、连接器、技能、独立专家、商店、模型服务/设置、附件/工作台和完整执行呈现，逐项验收记录见 [功能保留矩阵](newbot-v1-feature-parity.md)。不能靠隐藏未迁移功能、复制按钮或链接到不相容的独立数据实例满足此门槛。

调整迁移顺序：在G1协议验证并行推进时，提前梳理G2/G4完整业务接入；优先复用原插件/配置领域接口和业务组件，再逐层替换基础控件与聊天状态集成。未通过的模块保留原可用路径，不删除原实现。每个聊天入口仍只能有一个执行管线；不得同时运行旧store和CopilotKit管理同一轮次。此调整不解除G1的Actions/A2UI/Apps完整闭环要求，也不把恢复原入口等同于新架构迁移完成。

候选版本来自2026-11-14官方快照：CopilotKit1.88.0、AG-UI1.0.4、Apps SDK UI0.2.2、A2UI web_core0.15.0、MCP ext-apps2.0.4、ECharts6.1.0、Motion14.14.0、Monaco0.57.0；Codex候选0.169.0。以上不是已验证组合。实施开始重新确认发行信息，选稳定渠道精确锁定，版本调整记ADR，不自动追latest。

已知版本问题：@a2ui/react0.15.0依赖web_core^0.15.0，而其markdown-it0.2.2依赖要求web_core^0.14.0；React包没有显式/v1_0导出。G1需验证根入口/官方修正版或CopilotKit发布的兼容A2UI renderer，不能根据文档支持表直接认定可用。后者只是renderer适配，不是引入第二Agent框架；若采用，Catalog定义保持中立。

## 3. 身份、状态与安全契约

### 身份

Bot定义为独立的执行与资源归属单元，不等于一个聊天、一个模型、一个专家或一个Skill。专家继续是提示词/插件/技能的组合配置。身份链为：用户主体→botId→sessionId→nativeThreadId→turnId/requestId；工具调用/前端动作各有callId/actionId；节点执行带nodeId/epoch；配置有revision。不能用绝对路径或URL充当逻辑身份。

旧实例显式映射到default Bot，保留现有native Home/历史路径；没有兼容验证前不移动旧数据。新增Bot从独立Home、工作区和授权配置创建；原始认证密钥不得随检查点复制。

### 状态所有权

| 对象 | 权威所有者 | 其他层职责 |
|---|---|---|
| 执行、模型轮次、原生历史 | Codex | Adapter读取/投影，不重新构造第二执行循环 |
| 会话归属、执行回执、配置、审批、检查点索引 | Newbot Server | SQLite持久化；Runner按revision执行；UI只展示 |
| Agent消息与活动状态 | 后端事件/历史的客户端投影 | CopilotKit管理前端交互；不同时让Zustand双向写同一状态 |
| 普通界面状态与草稿 | 前端非Agent store | 不包含系统凭证；旧会话草稿按会话隔离 |
| A2UI持久状态 | Newbot快照/动作账本 | 官方renderer生成可重建视图，保存协议版本 |
| App临时实例 | Host生命周期 | 能力随会话/授权/过期失效，不因iframe存活永久有效 |

AgentRunner：run沿用稳定请求ID及回执，connect只接续事件/历史，stop绑定当前轮次，isRunning由后端活动状态决定。正常重复提交只能产生一次有效派发；崩溃后结果未知不得自动重放副作用。浏览器断线不等于取消执行；进程恢复不承诺继续已中断的任意外部命令。

### 权限与动作

- 前端Actions需注册到Codex动态工具契约：Schema→授权范围→native call→对应浏览器动作→结果校验→同callId回传。多标签不能同时消费同一有副作用动作；过期结果不能改变新轮次。
- 纯界面动作可在浏览器完成；主机/外部服务副作用必须走Server→Connector执行边界。审批绑定服务端规范化的真实操作、接收方、参数和有效期，拒绝/超时均不能执行。
- A2UI普通确认不等于宿主授权。security-ui使用受信Server意图，模型Catalog不能选择伪造的系统授权组件。
- 系统管理的凭证、密钥与私密字段原值不进入模型、普通事件、日志或遥测；接收方限定注入。业务敏感内容按数据出站策略处理，不承诺自动识别所有用户粘贴内容或第三方结果里的秘密。
- Bot逻辑过滤与执行隔离分开验证。同UID不同目录不是强隔离；隔离机制在G0定案并于G5落实。无法证明隔离时不开放“不可信Bot代码”能力。
- 角色/范围、节点权限和工具参数均由服务端再次检查；Connector落实文件/进程/网络边界。高权限Docker管理工具不能通过挂载宿主socket冒充普通沙箱隔离。
- Provider在请求接受时冻结model/provider/revision；当前轮不被热切换修改，下一轮使用新配置。必要的native有序重建不重启Web Server。

## 5. 工作阶段与退出条件

各阶段执行“实现→针对验证→修正→记录”，通过后进入下一阶段；若遇具体阻塞，记录可复现条件，继续无依赖任务，不伪造兼容或切换已排除框架。一次只切换一个权威执行管线。提交前更新本目录进度；代码提交按阶段拆分，不把版本升级、目录移动和界面重构混成一个提交。

### G0 基线、身份与所有权契约

工作：核对当前源码/dist/native/服务/公网入口，建立一致性备份；记录当前依赖、接口、事件与数据格式；设计default Bot映射、身份/权限作用域和Connector隔离；把原用户反馈变成用例。
交付：baseline.json、contracts.md、migration-map.md、原问题→现有测试→新增验收矩阵、重复实现待删除清单。实施分支使用codex/newbot-v1；目录移动暂缓。
退出条件：所有权无冲突；旧数据不搬移也能纳入default Bot；所有P0操作具有服务端归属校验；性能基线有真实数值。身份/权限设计必须先于功能接线。

### G1 版本锁与最小完整闭环

工作：隔离小工程精确安装CopilotKit/Apps SDK UI/A2UI，检查exports/peer/许可证/遥测，不使用force或legacy-peer-deps；TS Runtime适配Fastify的会话cookie、Origin、流式连接和取消；使用官方AgentRunner/AG-UI扩展点。
在同一页面贯通：真实Codex普通对话、一个前端Action、一个A2UI1.0表单、一个官方SDK MCP App、一次受控审批。Apps SDK UI同时应用到普通表单和A2UI Catalog；不等待全面换皮后再发现兼容问题。
交付：精确lock、兼容ADR、最小样例、依赖树/网络与bundle记录、mock失败用例与真实模型证据分别保存。
退出条件：干净npm ci/build通过；独立Vite无ChatGPT全局依赖；A2UI1.0增量/绑定/action有效；MCP App请求经原有授权路径；重连不产生新turn；无必需云服务/第二Agent Loop。
阻塞分支：官方React包冲突未解时核对官方兼容发布或有来源的renderer适配；缺少稳定可用组合则阻塞正式A2UI切换，保留旧渲染器用于旧数据读取，不伪称1.0完成。

### G2 CopilotKit聊天与Apps SDK UI迁移

工作：替换消息列表、composer、状态/工具/思考呈现和消息操作；聊天由单一CopilotKit适配投影管理；Zustand只留非Agent状态。统一tokens、图标/槽位、按钮与字段，更新PRODUCT/DESIGN/surface brief为新的默认设计系统。
保留行为：点击发送立即出现本地消息和运行按钮；正文与图片/附件连续分块；选择的专家/插件/技能发送后只在侧栏管理；专家独立分类；思考默认折叠；步骤有标题和实际状态；流程滚动到边缘能查看其他消息；上下文追问不设固定兜底；精简无用说明，错误/权限信息不隐藏。
Actions完成注册/调用/匹配/过期/恢复生命周期，前端拒绝或关闭不伪造成功。
退出条件：短聊/长聊/纯附件、切换/断线/重复发送/取消/双标签用例全部通过；手机与桌面键盘焦点和滚动可用；旧聊天可读；被替换的聊天通用实现已删除或逐项说明短期兼容原因。

### G3 A2UI与MCP Apps、编辑和图表

工作：用中立Catalog封装Apps SDK UI、ECharts等组件；新写A2UI1.0、旧0.9按版本读取；保留资源限额与提交防重；宿主使用标准AppBridge和现有独立origin。App需要的网络、下载、显示模式逐项声明/授权，不全量开放。
Monaco仅工作区编辑/Diff入口懒加载；保存必须校验文件归属及版本，冲突不覆盖，普通聊天代码继续轻量高亮；不将不可信代码直接在主页面执行。Motion用于需要的进退场/布局变化。
交付：a2ui-form、github-review及docker-mcp-app示例中的最小功能；Docker示例默认只读模拟数据验UI/协议，真实宿主能力单独限定与验证，不把模拟当真实运维成功。
退出条件：A2UI create/update/delete/动作/旧快照/刷新重启通过；App加载/关闭/过期/拒绝/工具返回通过；编辑冲突与下载/资源边界通过；第三方App只能按主题协商一致，不突破iframe隔离。

### G4 插件、Provider、凭证与授权中心

工作：连接器/技能/专家/商店/设置共用新控件；沿用原生Codex插件目录与安装，不复制市场安装器；保留URL自动推断、损坏包修复、OAuth完成/失败/重试、私有CA选择与origin绑定。Provider管理只配置现有执行路由。
security-ui展示服务端真实授权意图；私密输入接可信消费者，不进入普通Actions/A2UI数据模型。字段未保存时不能检查旧值冒充新配置成功；安装/启用/配置/连接/授权状态分别表达。
退出条件：官方Slack安装与配置/同类GitHub包恢复/商店导入/专家提示词均回归；受控OAuth/TLS失败和恢复通过；真实Slack账号链路如未完成仍标待验。Provider切换下一轮生效，当前轮不变，Web Server不重启；配置重启恢复、拒绝/过期审批不执行。

### G5 多Bot与Host Connector

工作：沿现有Runner实现节点身份、资源分发、回执/epoch、检查点上传和恢复；Bot范围贯穿配置、存储、凭证、事件及执行；落实G0选定的进程/OS权限或容器隔离，不借目录名宣称隔离。
旧默认Bot在显式迁移前保持旧路径；新Bot独立创建。多主机启动采用明确节点选择，无自动调度/未知副作用接管。Server确认全部检查点对象后才报告备份成功，不能将正在上传的内容视为可恢复。
退出条件：两个Bot同名工具使用各自凭证，跨Bot/API/文件/环境/审批访问均拒绝；两个独立节点完成受控执行、掉线、重复回执、撤销、恢复；“双物理主机”能力必须有对应真实环境证据。旧节点未确认停止不得自动接管；检查点恢复范围与数据损失窗口明确。

### G6 目录整理、内核兼容、生产验收与部署

工作：按独立纯移动提交迁移apps/web、packages/ui/chat/a2ui/mcp-app-host/contracts/security-ui、services/server、connector；不同时修改业务逻辑。contracts/ui不能导入server凭证或native运行代码，packages暂为workspace内部模块，不增加发布服务。
Codex新版本及3份补丁单独评估：上游已覆盖则删除，否则最小重放并验证；不能只更新npm版本就声称线上内核升级。完成类型/全量测试/构建/native必要检查、真实浏览器与真实模型验证；文档、版本锁、删除清单、遗留项同时更新。
部署：空闲维护→一致性备份→完整构建/native发布→公网资源与运行路径核对→配置/历史/附件/专家数据保留核对→真实模型验收→解除维护。保留现有登录与入口；临时Cloudflare域名不承诺永久稳定。
退出条件：下表全部必要验收有证据，原用户路径无功能倒退，回滚演练完成；只有此时标记v1.0已交付。

## 6. 统一验收与性能预算

| 编号 | 行为约定 | 可观察通过条件 |
|---|---|---|
| V01 | 一次操作一次有效派发 | 重复发送/重连/重复事件不新建重复native turn；未知结果显示核对，不自动重放 |
| V02 | 状态归属 | 切换、迟到回复/Actions/OAuth、旧节点epoch不能改当前会话/授权 |
| V03 | 恢复 | 刷新接续，Server/Connector重启后从已确认状态恢复；断线不自动取消，丢失窗口有说明 |
| V04 | 动态UI | A2UI1.0表单/图表/action和旧0.9历史并存；App标准握手、工具执行、拒绝/过期可恢复 |
| V05 | 权限 | 篡改botId/sessionId/参数/审批ID、跨App或跨服务调用均拒绝；Server/Connector执行边界均检查 |
| V06 | 凭证 | 合成测试秘密不出现在模型请求、普通AG-UI/state、日志/遥测；只到被授权接收方 |
| V07 | 配置 | 保存后读回及重启恢复；Provider当前轮冻结、下一轮生效；CA限origin；OAuth失败能重试 |
| V08 | 视觉/交互 | 320/390/768/1280宽、浅深色、键盘焦点、长消息/嵌套滚动、折叠状态、附件分块全部检查 |
| V09 | 多Bot/主机 | 实际跨Bot执行读取被拒绝；节点撤销/掉线/旧epoch不越权；恢复证据标明模拟/双进程/真实主机 |
| V10 | 部署/回滚 | 源码/构建/native/入口一致，旧数据保留；回滚不覆盖新增用户聊天 |

性能采用G0同机同浏览器同数据集基线（500条消息、20个步骤、包含附件），至少5轮记录。拟定门槛：本地发送至消息可见p95≤100ms；首屏gzip JS相对基线增长≤15%；主要交互p95与稳定内存增长≤20%；Monaco/图表/深层设置不进普通聊天首屏。以上为目标，不是已测成绩。超预算先分析依赖和状态重复，优化后复测；不能因换库就接受显著退步，也不通过少量UI截屏替代性能证据。

## 7. 数据兼容、灰度与回滚

- 数据迁移新增可回退字段/表，原始native历史、A2UI快照、凭证、插件版本保持；默认Bot映射留显式版本。
- 灰度在隔离入口/副本进行，不能让新旧前端同时替同一会话提交。若保留临时开关，开关只选一条完整管线，有退出条件和删除阶段。
- 发布备份包括DB一致性快照、对象/附件、配置、旧dist/native与版本清单；凭证仍按现有安全存储处理，不进入issue/git。
- 回滚优先恢复代码/native并保持向后兼容数据；涉及DB恢复先核对新增数据，不直接用老备份覆盖新聊天。无法安全回滚时转维护并给出具体恢复方案，不偷偷删除数据。
- 主框架不可行时记录最小复现、已尝试方案和影响，修订该阶段ADR；不自动引入assistant-ui/AI SDK或绕过权限/peer约束。
