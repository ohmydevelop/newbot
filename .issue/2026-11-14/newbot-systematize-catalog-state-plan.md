# NB-SYS-03 · 目录请求生命周期

2026-11-15，承接 NB-SYS-01/02。用户要求继续在旧版体验上体系化；本轮保持样式、导航、图标、接口与数据格式。

## 问题、证据与约定

1. 连接器刷新从 loadSettings → loadDiscovery → plugin/list，但 ToolsSettings 仅最后 read 设置 busy；前两阶段可以重复触发刷新。有代码证据，慢网络浏览器复现待验证。
2. 商店初始读取有 live 检查，手动 load 无生命周期检查且没有 busy；操作完成后的目录可能被更早读取覆盖。专家读取/保存/删除也独立释放同一个 busy。共同根因：异步操作没有统一所有者，最后返回的请求被误当作当前操作。代码证据，不宣称已在生产复现。
3. 专家保存成功后 list 失败仍保留新建表单并提示“保存失败”，再次提交可能新建第二条。保存结果与读回结果混为一次成功/失败。代码证据，需注入故障验证。
4. 插件子组件 onUpdate={setDetail} 不检查当前详情，迟到回调可重开已经关闭的详情。代码证据；用当前对象身份约束回写。

不变量：一次操作最多一个有效提交；较早读取不能覆盖较新结果/写入；旧操作不得解除当前 busy；卸载页面后的结果不得回写；写入已被确认成功后不能诱导再次创建。停止等待写入并不等于撤销服务端写入，不用 AbortSignal 假装取消提交。

## 实施与兼容

1. 提取页面级操作 scope：相同读取去重、不同读取取最新、写入独占并使旧读失效、卸载使结果失效。只中止读，不中止写。提供 React 适配，busy 从同一所有者派生。
2. 接入三个目录；每个 await 后检查所有权，catch/finally 同样受约束。保留操作顺序、已有错误语言及服务端并发/幂等协议。
3. 专家保存一经成功关闭已提交草稿；读回失败显示目录恢复提示。商店/插件也明确已完成与目录失败的区别。
4. 进行可控乱序、重复请求、失败、卸载与重新挂载测试；构建及相关业务回归；真实浏览器检查原布局及深层表单。替身故障注入单独标记。
5. 完成后提交推送，备份并仅发布新前端到原公网入口；核实公开资源哈希、原入口/数据未换成实验版。

不处理：视觉改版、依赖升级、全局请求客户端替换、服务端幂等重写、生产配置变更及数据迁移。无新存储格式。原插件、技能、专家、商店功能保留。

## 验收与证据

- 受控延迟期间刷新立刻 busy，重复动作不重复执行；旧成功/失败不覆盖新结果、不释放新 busy。
- 写入期间读/写不能插入；写后读取失败不重提已成功写入，允许刷新恢复。
- 页面离开后读被取消，迟到写不更新旧页面；重新挂载可正常读取（含 React StrictMode 生命周期）。
- 浏览器检查连接器目录、商店深层操作、专家保存/删除及手机布局，保留现有交互。
- 证据保存在 evidence-systematize/catalog-state/，进度保存 newbot-systematize-catalog-state-progress.md。初始状态：调查完成，实施/验证待完成。
