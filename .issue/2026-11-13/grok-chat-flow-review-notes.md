# 本轮独立源码调查提示

2026-11-13。审查角色只读产品源码，无浏览器交互，不修改产品。与 finish review 的截图证据门分开记录，以下不是已修复验收。

## 已有证据及修复优先级

1. **能力属于会话配置，不应重复占据每个消息。已复现（用户原图）+有代码证据。** `App.tsx` 的 expert、plugin、skill 为三个独立 `.skill-draft-list`，`Message.tsx` 又展示用户消息引用；组合使一条很短的问题占据多层。初次选择可单行显示，溢出通过有名称的展开控件访问；开始提交后输入与消息只保留内容和附件，侧栏统一管理专家、插件、技能。不能靠清空实际选择实现隐藏，否则下一轮能力丢失。
2. **名称必须跨提交和重启完整。已复现（用户原图）+有代码证据。** `server/session-inputs.ts:remember` 仅保存技能 id/sha256，而展示端依赖 displayName/name。除修正新写入，还需用同会话同技能摘要的历史记录恢复旧数据；保留摘要验证，不能把已失效版本静默替换为最新版本。无可恢复信息时显示明确可移除的不可用项，不能留空标签或只显示计数。
3. **提交接受之前已有清楚反馈，接受之后不能重影。用户反馈+有代码证据。** `App.send` 先等 `submitRun` 再载入历史；添加乐观消息必须覆盖普通 ack、状态查询恢复、私密字段等待、明确拒绝、unknown、放弃和导航切换。`inspectSubmission` 也会确认并清理 pending；仅在 send 成功分支移除乐观气泡会留下幽灵。unknown 不得自动重试；提交阶段不要给出虚假的可停止承诺，实际有 turn 后才调用停止。
4. **侧栏成为唯一配置入口必须拥有完整动作。有代码证据。** 当前 `WorkbenchRail` 仅插件/技能移除，无专家、无添加；直接隐藏 composer chips 会减少现有能力。纳入专家详情/更换/移除，插件和技能添加/移除，长名称溢出与不可用态，并检查手机 Dialog 内打开 picker 的焦点和返回。
5. **过程层级应服务任务状态。有代码证据，Grok 对应运行态待验证。** 目前总过程 disclosure 内 reasoning 又是 disclosure，工具标题默认“调用工具 · 原始名称”；需要用可理解的活动标题和一致图标表达，但保留命令/原始结果供按需查看。正在等待审批、失败、停止、最终输出不能被无条件合并进折叠日志。`presentationBlocks` 特意让 A2UI/结果拆分过程组，这是功能边界，应保留。
6. **硬编码推荐不应回来。有代码证据。** 当前 `FollowUps` 由 inline 模型元数据或补充生成接口取得，失败显示重试，不含固定问题 fallback。本轮不要把状态说明也误判成推荐问题；实际生成失败、过期请求与新一轮期间仍应不显示旧问题。此结论仅是本地源码，部署一致性仍由主线程核验。

## 候选验收最小集合

- 320/390/桌面：一个能力、三个能力、多个长名称；一行内横向排列，超出一行折叠，键盘可展开且隐藏项不占 tab 顺序。
- 首次发送后气泡没有能力徽章、输入区没有三组配置；侧栏仍能查看并操作相同配置，刷新/重启后名称不空。
- 慢接口点击后立即显示当前草稿；反复点击只产生一次执行；确认后不重复；确定失败保留草稿；unknown 明确显示待确认；切换会话/新草稿不被迟到响应覆盖。
- 思考与工具流式、完成、失败、停止、审批等待；必要交互输出可操作。无实测 Grok 参考的部分标为 newbot 适配。
- 手机侧栏关闭后焦点返回触发按钮；侧栏打开 picker 后选择与退出不被外层 Dialog 焦点锁困住。

## 保留

现有温黑/中性浅色、统一 2px 描边、完整权限状态、会话草稿隔离和单次执行保护；避免为外观抹除这些真实行为。
