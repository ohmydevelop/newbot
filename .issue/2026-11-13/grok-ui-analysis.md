# Grok → newbot 界面拆解

来源为当前已打开的 Grok 页面可见 DOM、计算样式和截图；不等同于访问 Grok 私有源码。原始数据在 evidence-grok-ui。以下区分观察与实现决策。

|维度|已观察的参考事实|newbot 的实施|
|---|---|---|
|信息层级|标题与 composer 成组，桌面 1440×900 中标题 y≈206、输入 y≈271，主要区域有大量留白|is-home 布局将输入从固定底部提到标题下；有消息时回到底部|
|响应式|390×844 标题 y=256，输入内容 y=723，320窄屏同样输入靠底|480以下切换为底部输入；中等屏保留成组布局；导航使用抽屉|
|配色|画布 #131211、输入 #201f1d、主文 #fcfcfc、辅助 #9e9e9e；边线为白6%|语义token覆盖主界面、菜单、设置、预览；浅色使用同层级白/灰色，不声称来自未观察的Grok浅色|
|字体|universalSans、Inter等回退；标题24/550，输入16/28|不复制字体文件，沿用现有可用无衬线与中文回退；中文标题25–28，正文15.5/1.85，去掉原正文0.07em字距|
|输入组件|752宽上限、24圆角、102高左右；40px按钮|保持752/24，按newbot模型+审批能力略加高度；附件、模型、审批和发送可用|
|图标|主体16–22px，部分描边1.75；按钮多为圆形|统一现有Lucide到1.75，保留newbot标识，不复制Grok商标|
|动效|可见按钮计算样式：100ms颜色过渡；静态输入容器无动画|100ms反馈、180ms导航/工作区定向出现；减少动态效果禁用；这是设计适配，非Grok菜单动效的实测复刻|
|交互|页面主任务集中在输入；扩展入口次级|建议先填草稿，移动端重复的技能/插件图标收入已有“+”菜单；独立授权不进入普通输入|
|状态|Grok本轮只观察首页和可见控件|newbot还覆盖运行/完成、重连禁用、草稿恢复、长标题、模态焦点等本产品状态|

## 边界

Craft Anything 已建立 brief/plan，但独立网页打开在用户明确授权后仍被其内部 consent_required 拒绝，未修改全局 ask_before_running。所有参考尺寸都来自现有页面的正常只读浏览器观察。未录得的 Grok 菜单、设置、付费功能、发送动画不得宣称逐项复刻。本次不复制远程品牌资产，也不虚构 newbot 的语音或自动化能力。
