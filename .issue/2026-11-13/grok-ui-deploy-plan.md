# UI-20261113-DEPLOY：实际实例部署与真实模型验收

## 目标、触发与现状

用户明确要求把新版部署到实际 newbot，并接真实模型验证；确认使用原 Cloudflare 分享地址。当前仓库 .env/.data/public-share.json 指向原 Quick Tunnel，但3100无监听、原PID不存在，两条原隧道均不在运行。3147为上一轮模拟预览，不能当真实实例。当前数据库 schema17，9会话、31请求、2附件；默认网关百智-MQ、模型 deepseek-flash。历史分享清单计数已过时，以当前数据库为准。

## 不变量、证据与判断

- 保留原SQLite、密码、加密主密钥、实例Codex历史及现有Provider定义；不把模拟数据混入实际实例。
- 发布的静态资源来自当前工作树；保留上一代资源以兼容打开的旧页面。
- 单次UI发送只创建一个有效Turn，真实上游回复可恢复；分享入口保持密码认证与独立App origin。
- 已证实：端口/进程检查显示服务已停止，未发现需中断的活动服务；当前.env指向已存在原生Codex二进制。停止原因未调查，本轮不据此声称修复原因。
- Quick Tunnel原域名不能指定恢复，需要建立新临时域名；延续原分享范围与认证，不开放新的免认证入口。

## 步骤、兼容与回退

1. 将原数据库、凭证主密钥、环境、dist与Codex home备份到.data/restart-backups下私有目录，保存摘要及schema/计数。
2. 构建当前产品dist；保留原原生Codex版本。不迁移用户数据或新增依赖。
3. 恢复两条本项目Cloudflare临时隧道，更新精确origin；用用户systemd临时单元运行实际3100服务，保持回环监听和原认证。
4. 验证本地readiness、配置恢复、静态资源、原数据与凭证不变；验证公网认证及App域隔离。
5. 公网浏览器登录，以现有默认模型发一条不使用工具的合成消息，检查真实回复、单次Turn与刷新恢复；空闲后重启一次核实恢复。
6. 更新分享记录、证据和进度，交付新地址。失败时保留备份并恢复旧dist/env；不盲目恢复数据库覆盖新用户数据。

不处理：新正式域名、Named Tunnel、全套生产验收、全部模型/MCP矩阵、无关系统服务。现有分享恢复授权不扩展为改动其他应用隧道。
