## 目标、问题和不变量

|编号|触发、实际与预期|证据及判断|
|---|---|---|
|PL-01|外部插件无配置描述时，宿主按产品名、版本及包摘要合成字段；应只依据通用包契约|有代码证据：`plugin-descriptor.ts` 的 CloudWalker 分支、`plugin-connections.ts` 的专属 URL 校验。撤销这些规则，保留通用 MCPB 描述适配和私密通道|
|PL-02|已安装插件无升级入口；导入替换没有明确目标/版本，升级会重置插件启停、普通配置及部分技能选择|有代码证据：`ToolsSettings.tsx` 仅安装/卸载；`imports.ts` 同名替换；`setSkills` 强制启用父插件；配置 state 按包摘要丢弃旧值。升级必须保持身份、明确版本/内容差异，失败恢复原包，不能冒充卸载重装|
|PL-03|打开独立连接器列表时短暂显示 `plugin_…` 后消失|用户截图已复现；前端初始独立目录合并全量运行状态，异步插件详情返回后用 tools 名称排除。服务端归属来自延迟生成 map 或持久化 mcp 名称，旧导入记录可能为空；具体竞态待定向复现。归属必须在第一份响应中确定，不依赖插件详情请求顺序|
|PL-04|插件详情及卸载说明仍使用“工具连接”|有代码证据：`ToolsSettings.tsx` 两处。用户术语统一为连接器，工具仅指连接器提供的实际工具|

关键约定：插件组件始终归属插件；同名独立连接器不被误隐藏。升级维持插件 ID、已关闭技能、父插件状态和可兼容普通值；新增权限/改变接收方的秘密必须重新确认。包变更在空闲互斥中完成，历史线程与个人 Codex 配置不改写。
