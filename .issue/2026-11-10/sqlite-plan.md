# Provider SQLite 持久化与热更新

用户已确认将 Provider 定义、全局默认、网关默认和推理参数保存到 SQLite。替代先前“Bridge 重启清空 Provider”的产品行为；线程参数热更新、活动任务快照及个人 Codex 隔离保留。密钥仍通过独立凭证库保存，不放入普通配置 JSON。

| 阶段 | 实施与验收                                                                                 | 状态 |
| ---- | ------------------------------------------------------------------------------------------ | ---- |
| S1   | 数据库 v6→v7 增量迁移；版本化配置单行；白名单验证；先提交后发布；失败不改内存，冲突不覆盖  | 完成 |
| S2   | 所有修改入口接入 SQLite；启动自动恢复；外部下发/重载同样持久化；加密凭证引用与会话配置恢复 | 完成 |
| S3   | Web 状态、能力查询、说明文档及测试脚本更新；桌面/移动端验证                                | 完成 |

SQLite 只存当前允许的非敏感 Provider 运行参数与凭证引用。既有会话设置和偏好仍使用其现有表，MCP/插件/Skills 的原生管理不迁到任意配置表。继续不写 Provider config.toml/Profile，不编辑个人 ~/.codex。正式部署与上线验证后置。

每阶段实现、针对性验证、修复并记录后直接进入下一阶段。仅有验证证据才标记完成；进度记录追加到 progress.md。
