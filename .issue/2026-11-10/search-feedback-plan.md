日期：2026-11-10。当前状态：F1–F5 已实施并验证，测试服务已更新。原调查保留，新增 issue 项的分析见 `issue-02-analysis.md`。

## 反馈与目标

用户在搜索聊天截图中标出了“搜索已保存的对话名称”，要求检查。原图原样保存于 `evidence-search-feedback/user-search.png`。关联原 issue：`2026-11-10-02.md` 中的非必要提示和提示导致布局跳动；该文档及其图片保持不变。

用户目标是快速找到并打开聊天。正常界面应直接提供搜索入口和结果；文字只在它能帮助确定范围、做出选择或恢复失败时占用注意力。请求进行中仍须有可访问的反馈，但后台刷新不应把已有内容推开。

## 不变量、证据与根因

1. **搜索范围准确，表达一次即可。** `web/App.tsx` 的搜索过滤只使用 `t.title`，并进行 NFKC、大小写和首尾空格处理。当前不支持对话正文检索，不能把精简文案描述成全文搜索能力。约 1479 行的 `<p className="muted">` 无条件输出标记文字；不是浏览器残留或后端错误。
2. **已有内容不因背景刷新而移位。** 打开搜索的 effect 调用 `loadThreads()`，`web/store.ts` 使用单一 `threadsLoading`，`App.tsx` 的搜索与侧栏均条件插入段落。`web/styles.css` 的通用弹窗以自身高度居中，新行改变高度后还会移动整窗。不能只删静态说明就宣称解决了布局跳动。
3. **减少文字不能抹掉必要反馈。** 搜索范围、失败重试、权限限制、不可逆操作及凭证保存方式影响用户判断，应在对应控件或操作处表达；不能全局隐藏 `.muted` 或 `role="status"`。

已核对源码 HEAD `2ccb031`、磁盘构建、本地服务和当前公网入口：均使用 `/assets/index-Buh0x2VX.js`，包含该说明；本地及公网资源与磁盘 SHA-256 一致。公网诊断使用真实列表响应，在浏览器内临时延迟其交付以观察请求中状态，不修改服务端响应或数据。

1440×1100 浏览器中，加载结束时搜索输入框 Y 改变 +17px，第一项结果 -17px，侧栏首项 -21px；两个位置同时呈现读取提示。原截图证实 S1，浏览器和源码补足 S2 因果链。证据：`evidence-search-feedback/inspection.json`、`public-search.png`（聊天名称已遮罩）。

UI/UX Pro Max 的两次定向检索未获得适用文案条目。本计划依据现有产品信息层级、渐进披露原则与实际代码/浏览器证据，不把无关检索结果当作设计依据。

## 实施顺序

1. **S1：精简搜索表达。** 删除独立说明；将真实范围合并到占位文案，保留输入框无障碍名称。梳理搜索列表间距，不留用于旧说明的空白。
2. **S2：稳定刷新反馈。** 区分初次无数据读取与有缓存结果的后台刷新；后者不另插占位段落，使用稳定位置的进度图标及辅助技术状态。搜索弹窗和侧栏共享数据状态，但各自维持布局。根据定向复现再调整搜索专用容器，不随意固定所有 Modal 的高度。
3. **S3：按机制清理关联入口。** 处理推理保存状态、网关正常态技术说明及 MCP 重复信息。区分正常说明、忙碌状态、失败和权限原因，按语义处理，而不是引入“隐藏所有提示”的全局样式。
4. **验证与记录。** 每项实施后完成针对性验证，再更新本计划和 `search-feedback-progress.md`。存在未验证能力或独立问题时单独记录，不能标记整份 `2026-11-10-02.md` 完成。

范围限于上述反馈与布局机制。不增加全文索引、不更改网关持久化、不修改个人 Codex 配置、不调整后端协议、不接入新部署方式。无需 SQLite 迁移；保留现有搜索匹配、失败恢复和最新请求保护。

## 验收

- 默认搜索界面只有标题、输入及结果，没有重复解释搜索用途的常驻段落；文案不声称可搜索正文。
- 结果不变的刷新前、中、后，搜索输入框、首条结果和侧栏已有条目的位置保持一致（最多 1 CSS px 测量容差）；已有结果仍可操作。首次读取、慢请求和失败各有清晰状态。
- 空查询、无匹配、全角/大小写/首尾空格、刷新失败后重试、重复打开、Escape 和键盘焦点行为保持正确；错误状态不能变成“无结果”。
- 推理设置保存成功/失败有反馈，控件不因额外行移动，失败后保持实际有效值；不隐藏错误来达成视觉验收。
- 网关常态列表不再展示 SQLite 实现说明；配置来源异常和临时凭证等必要提示仍可找到。MCP 名称、来源和只读原因不重复堆叠，工具列表便于直接浏览。
- 实施后在桌面与手机、深浅主题检查受影响入口。运行类型检查、构建及相关交互/恢复测试；只因新增状态风险补足有意义的测试，不为单句文案另建测试套件。

### F5 回归新增 R1：默认模型与推理参数必须成组有效

已复现：旧 issue 综合测试将网关默认改为仅从上游目录发现的 `secondary-model`（没有已知推理档位），随后新会话报“模型不支持该推理强度”。首次综合回归在“自定义网关默认值应用到新对话”的发送步骤失败；修复后证据位于 `evidence-search-feedback/issue/ui-result.json` 及 `tests/model-defaults.test.ts`。源码显示 `session-runtime.capture` 隐式继承全局 effort，Bridge 创建时也再次回填该值；默认模型写入未重新校准 effort。这不是目录 UI 文案问题。

共同机制包括 SQLite 运行快照和旧原生配置兼容路径、切换全局默认、非默认网关开始新会话。范围限定为隐式默认值的兼容校验，不改变已存在会话和显式参数拒绝规则。实施：用同一个兼容默认解析函数，保存默认模型时同步合法 effort；捕获新请求和创建线程时不重新注入不兼容的隐式值。验收：两种配置路径中的无推理模型可开始新会话，合法档位保持，显式不支持的档位仍被拒绝；执行原综合浏览器回归及契约测试。无需数据迁移，读取旧快照时兼容修正。
