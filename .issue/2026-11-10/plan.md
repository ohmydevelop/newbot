# Provider 内存配置与参数热更新

> 本文件记录先前纯内存阶段。用户后续已确认 SQLite 持久化，当前实现及验收以 [SQLite 计划](sqlite-plan.md) 为准：重启自动恢复配置，继续保留参数热更新。

依据：用户要求完全接入“Provider 运行配置只驻留服务端内存，会话选择持久化，通过原生参数热更新”的模式。继续隔离个人 Codex，保留会话、文件、MCP Apps、Skills、插件及私密凭证能力。正式上线验收后置。

| 阶段 | 工作与验收                                                                                           | 状态 |
| ---- | ---------------------------------------------------------------------------------------------------- | ---- |
| H1   | 核对固定版原生覆盖语义；实现不可变内存 Provider 快照与版本校验；不向原生配置写 Provider 参数         | 完成 |
| H2   | 接入目录、网关编辑、默认选择、线程创建/恢复/切换及每轮配置绑定；空闲应用、执行中保留快照、失败可恢复 | 完成 |
| H3   | 接入凭证绑定与启动恢复；明确配置重启丢失、上游重新下发、凭证重连边界；避免旧文件成为隐式配置来源     | 完成 |
| H4   | 提供受鉴权的配置下发接口与页面状态；持久化会话选择；已有实例安全切换和备份                           | 完成 |
| H5   | 原生双网关实际路由、同地址更新、历史/PID、不写配置、重启后恢复/缺失状态；既有自动与浏览器回归        | 完成 |

仅有证据的项目标记完成。每阶段实现、验证、修复、记录后直接推进。内存配置不包含凭证明文；凭证延续独立 Broker。模型参数热更新不终止已执行任务。插件/技能/MCP 的原生安装及认证状态仍按现有能力管理，Provider 全局配置不写文件。

未接入外部配置来源时，Bridge 重启后 Provider 定义清空，旧会话可读，续聊等待重新下发；不静默改用其他 Provider。旧文件先保留备份，不自动覆盖个人配置，不将旧配置反复导入冒充纯内存。

验收证据：337 项自动测试、12 组真实原生内存配置测试、原生加密凭证重启恢复、50 组浏览器回归及现有测试服务切换。详情见 [进度与证据](progress.md)。模型推理均使用本地合成响应，未调用付费模型；正式部署与上线验收仍后置。
